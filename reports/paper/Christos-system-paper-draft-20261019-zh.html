摘要

研究动机。 计算反应预测已越来越多地用于天然产物和中医药（TCM）研究，但现有工作流常常把预测与出处分离，难以判断某个候选为何被生成，也没有清楚区分探索性输出和实验室建议。这个问题在中医药数据中尤其突出：药材名、植物物种、炮制品、方剂版本和来源档位都可能指向不同的化学起点。

结果。 本文介绍 Christos，一个本地优先的反应预测系统，集成异构化学数据的只读访问、模板式正向枚举与逆合成、条件证据、出处标注和可复现报告。Christos 可按药材、拉丁物种、COCONUT 物种、方剂或用户提供的小分子解析输入；它不会静默合并同名方剂的不同版本，也不会写入底层数据库。系统提供命令行和本地浏览器界面，每次运行都输出 CSV/TSV 台账和单文件 HTML 报告。

在泄漏受控的 USPTO-50k 基准上，所选正向配置在 50,016 条反应上达到 82.32% 的单步召回（命中 41,173 条；Wilson 95% CI 81.98–82.65%），基线配置为 55.43%。逆向模板搜索在 5,002 个目标上达到 94.74% 的 any-hit 覆盖率；多步规划器在 300 个目标上，深度 ≤2/≤3 的成功率分别为 47.67%/72.33%。中医药数据层索引 31,646 个药材成分、269,105 个 COCONUT 成分、12,071 条方剂记录和 1,526 条药典方剂条目。出处链中的 3,228 条生产模板全部映射到 ORD 反应标识。500 条模板条件审计中，493 条至少有一次产物匹配，491 条至少有一类条件记录。

可用性。 Christos 使用 Python 3.12、RDKit、rdchiral、SmartReact、DuckDB 和 SQLite 实现。公开发行版刻意分为只读研究应用和预计算演示包；公开 Demo 关闭任意目标逆合成和自由试剂输入。代码、数据卡、协议和参考文献核验快照将随稿件准备发布。

关键词：反应预测；逆合成；天然产物；中医药；出处；可复现性；反应模板

引言

当实验数据或量子化学数据不足时，模板式反应预测是探索化学转化的一条实用路径。RDKit 提供广泛使用的化学信息学工具（RDKit, 2024），RDChiral 在保留立体化学的同时抽取和应用反应模板（Coley et al., 2019），AiZynthFinder 和 Retro* 等系统则把模板库与搜索、排序结合（Genheden et al., 2020; Chen et al., 2020）。USPTO-50k（Schneider et al., 2016）和 PaRoutes（Genheden & Bjerrum, 2022）等基准资源让不同方法可以比较，Open Reaction Database（ORD）则提供带实验背景的反应记录（Kearnes et al., 2021）。

这些工具通常作为预测引擎来评价。另一个工程问题是：预测系统能否保存结果的历史——使用了哪条输入记录、哪个模板被触发、哪个来源数据库提供了化合物、观察到了哪些条件，以及结果是实验先例、规则外推，还是未经验证的假设。当同一套软件同时用于分子化学、天然产物化学和中医药研究时，这种区分非常重要。

中医药会带来特殊的数据解析问题。一个中文药名可能对应药典条目、炮制品、地区别名或植物物种；一个方剂可能有多个组成不同的历史版本，方名不能当作某个固定组成列表的同义词；一个化合物可能来自药材专库，也可能来自 COCONUT 这样的物种级天然产物集合（Sorokina et al., 2021）。把这些标识符当成可互换对象，可能从模糊输入得到一个看似精确、实际来源错误的化学结果。

Christos 因此围绕四项要求设计：

  1. 显式解析输入。 药材、炮制品、拉丁物种、COCONUT 物种、方剂和用户小分子走不同解析路径；系统报告实际使用了哪条路径，以及哪些记录未匹配。
  2. 保持数据只读。 SQLite 数据库和方剂文件通过只读连接打开；运行可以写报告和台账，但不能修改源数据。
  3. 为每个候选附加出处。 每条产物路径记录来源化合物、反应模板、规则名、条件证据、轮次和不确定标记；系统做标注，不静默删除候选。
  4. 明确公开边界。 公开演示层有意窄于研究引擎：任意目标逆合成和自由试剂输入关闭，Demo 不分发数据库。

本文介绍系统的数据模型、反应层、条件层和评价结果。它不是临床有效性声明，也不是合成操作方案，更不能替代实验室验证。所有结果只作为软件和基准证据报告，并明确模板预测与中医药来源数据的边界。

材料与方法

系统概览

Christos 由一组可组合的层次组成，而不是单一模型：

层次 功能 主要实现
输入解析 中文药材、拉丁物种、COCONUT 物种、方剂或 SMILES sources/herb.py、sources/coconut.py、sources/formula.py
反应枚举 正向模板应用与级联扩展 core/smartreact_engine.py、SmartReact
逆合成 模板反转与受限路线搜索 tools/retro_search.py
条件层 反应类 profile 与逐模板条件窗口 conditions/、data/mined_top_template_conditions*.json
出处与报告 台账、索引、HTML 报告、来源标签 core/query_base.py、tools/make_report.py
接口 CLI 与本地浏览器界面 integration/tcmai_bridge/

化学引擎与数据源适配器相互分离。这样，同一套反应引擎可以用于药材记录、物种记录或用户给定分子，同时把输入来源保留在输出中。

数据来源与只读策略

当前本地部署使用以下资源：

资源 作用 规模 处理方式
药材库 tcm.db 药材名、成分、别名、依据 31,646 个成分 只读 SQLite
COCONUT 快照 物种级天然产物 269,105 个有效分子 只读 SQLite
方剂记录 复方组成与版本 12,071 条记录 只读 JSON
药典 overlay 2025 方剂条目与官方来源 1,526 条 内部 overlay，不分发
USPTO-50k 泄漏受控基准 50,016 条反应 公开基准
ORD 衍生模板 模板来源与出处 3,228 条生产模板 衍生数据，注明来源

公开版本不重新分发上游原始数据库。ORD 衍生模板按 CC BY-SA 4.0 处理；USPTO-50k 为 CC0（figshare 5104873）；COCONUT curated dataset 为 CC0，基础设施代码为 MIT；SmartReact 模板包为 Apache-2.0。本地药材和方剂资源仍归库主控制，不进入公开演示包。

所有 SQLite 连接使用 mode=ro。当 WAL 数据库因为缺少共享内存文件而无法只读打开时，适配器回退到 immutable=1，以快照方式读取，不创建或修改边车文件。引入这条策略的原因，是观察到普通的读写 sqlite3.connect() 即使只打算读取，也可能生成 -wal 和 -shm 文件。

公开 Demo 只包含固定的小型摘录，而不是数据库：100 味常见中药、每味一个选定拉丁物种、50 个方剂和 150 个预计算示例。方剂限制为 4–6 味，并在打包前做安全过滤；Demo 不开放任意 SMILES 或路线搜索。

输入解析

输入按以下顺序解析：

  1. 药材库中的精确药材名或炮制品名；
  2. 已收录别名，并报告解析后的正名；
  3. COCONUT 物种字典中的双名法学名；
  4. 精确方剂名，保留全部版本；
  5. 研究接口允许时的用户 SMILES。

解析器同时返回选中的记录和未解析 token。对于方剂，系统保留版本列表，并按有记录的来源档位选择默认版本；它不会把同名版本合并成一个“合成方剂”，因为这种合并会产生不对应任何历史或药典记录的组成。

正向反应枚举

正向引擎对底物集合应用反应模板。模板按反应名和反应物类别组织。一次运行可由每味成分数、反应轮数、最大底物对数和每对候选上限约束。

当前选定配置使用 support 过滤后的模板池、每对 cap 32 和底物兼容性预筛。截断参数很重要：过小的 cap 可能在模板存在时仍隐藏正确候选。因此系统在运行元数据中记录对子覆盖和截断状态，而不是把截断结果当成完整枚举。

逆合成

逆合成模块反转正向模板，并递归应用到目标分子。搜索返回切断、前体集合和路线级标注。前体与可用终止集合比对，并标注为可用或不可用。系统不会把“不可用前体”直接判定为不可能，只记录当前可用性匹配缺失。

公开构建默认关闭任意目标逆合成；研究 CLI 必须显式设置研究模式环境变量。这是产品边界，不是说底层搜索在任何场景都无害。

条件证据

条件证据分两层：

  • 命名反应的反应类 profile：包含溶剂、pH、温度、催化剂和气氛窗口；
  • 从 ORD 记录挖出的逐模板窗口：先把模板匹配到真实反应记录，再收集其条件。

逐模板层从 top-N 模板出发，在 ORD 等距样本上运行；只有当模板生成的产物与记录产物匹配时，该记录才贡献条件。当前 500 条模板审计中，493 条至少有一次产物匹配，491 条至少有一类条件记录。得到的窗口只是标注，不模拟动力学、收率或选择性。

出处与报告

台账中的每条候选路径都包含产物结构、来源化合物、来源药材或物种、反应规则、轮次、条件激活标记、方向标记和证据字符串。报告生成器把台账转换为单文件 HTML，并在需要时绘制结构。

系统刻意不做静默评分。方向标记或条件标记只是展示，不删除候选；没有条件证据时显示“无证据”，不能解释为“不可能发生”。

评价设计

评价分三部分。

正向预测。 对 USPTO-50k 记录的反应物运行一轮引擎；只要记录产物出现在候选集合中即记为命中，不使用排序。同时报告基线配置和选定生产配置，并对头条结果使用泄漏受控模板库。

逆合成覆盖。 只要某个切断在去除原子映射后得到与记录反应物集合完全相同的前体集合，即记为命中。覆盖率使用泄漏受控模板库；多步成功率在 300 个目标上用受限 beam 搜索评价。

中医药解析与出处。 通过同一界面测试药材、物种、方剂和 SMILES 输入，记录解析来源、版本、未解析 token 和输出链接。Demo 示例由同一引擎生成，但以固定预计算样本打包，因此不分发数据库。

结果

已实现的数据规模

当前本地部署覆盖：

  • 31,646 个药材成分；
  • 269,105 个 COCONUT 成分；
  • 12,071 条方剂记录；
  • 1,526 条药典方剂条目；
  • 3,228 条带 ORD 反应标识的生产模板；
  • 公开演示目录中的 100 味药材和 50 个方剂。

这些数字描述的是已实现的数据层，不是完整化学覆盖。某个成分或方剂缺失，只说明当前来源没有收录，不说明它在现实世界中不存在。

正向预测

在泄漏受控的 USPTO-50k 基准上，基线配置的单步召回为 55.43%；选定配置使用更大的 support 过滤候选池、每对 cap 32 和兼容性预筛，达到 82.32%（41,173/50,016），Wilson 95% CI 为 81.98–82.65%。

这项提升应被理解为系统配置的结果，而不是模板库在所有情况下都正确的证据。候选截断、模板 support 和模板质量都会影响结果；运行元数据记录这些设置，便于复现和比较。

逆合成与多步规划

泄漏受控逆向搜索在 5,002 个目标上达到 94.74% 的 any-hit 覆盖率。采用 beam width 4 和选定模板库时，端到端成功率在 300 个固定目标上为：深度 ≤2 47.67%（143/300），深度 ≤3 72.33%（217/300）。300 个目标中有 207 个至少有一条被标为可用的路线。

系统报告每个前体的路线级来源和可用性。它不会把“可用”标注转换成“请进行合成”的操作指令。

条件与出处覆盖

3,228 条生产模板全部关联到 ORD 反应标识；当前出处表中的反应级反查覆盖 9,177/9,177 条记录。500 条模板条件审计产生 493 条至少一次产物匹配的模板，以及 491 条至少有一类条件的模板。审计结果作为数据产物保存，本身不会改变默认运行时模板库。

中医药案例

系统既可以按中文药材名、拉丁双名、方名和版本解析，也可以接受用户 SMILES。以甘草为例，当前引擎对 12 个成分运行后产生 552 个候选产物和 552 条出处路径；每条路径均记录来源化合物、反应规则、轮次和条件证据。该案例用于说明报告模型，不构成药理学结论。

方剂解析保留所有同名版本，并报告选中的来源档位与未解析 token。对多版本方剂，输出会列出当前版本和备选版本，而不是折叠成一个组成。

公开演示与安全边界

公开 Demo 包含 100 味常见药材（每味一个拉丁物种）、50 个方剂和 150 个预计算条目。页面没有任意 SMILES 输入框、路线搜索、自由试剂输入、可购砌块或供应商链接。应用对源数据库只读，只写自己的报告和运行时目录。

这一边界对一个能够枚举反应产物的系统很重要。研究接口仍可用于受控实验，但公开接口有意只展示较窄的能力集合。

讨论

Christos 的目标是让反应预测可检查，而不是把不确定性藏在单一分数后面。三项设计选择由此而来。

第一，输入解析是显式的。在中医药数据中，药材名、炮制品、拉丁双名和方剂版本不是可互换标识；系统记录解析路径和未解析 token，使用户能够判断结果是否真的来自预期来源。

第二，出处附加在每个候选上。模板标识、反应记录引用、来源化合物和条件标记让运行结束后仍可审计结果。当底层数据异构时，这比一个裸排序列表更有用。

第三，公开接口窄于研究引擎。能搜索任意目标或展示可购砌块的系统，与只展示固定演示目录的系统具有不同风险画像。Christos 因此把公开可用性看成需要明确功能闸门的产品决策。

基准结果表明，选定配置在冻结的 USPTO-50k 协议上明显强于基线；但它们不证明化学可操作性、生物活性或临床效用。模板引擎仍依赖模板库和输入数据；条件层只标注证据，不模拟反应结果。

局限

  1. 依赖模板。 正向和逆向结果受模板库和候选截断限制。缺少模板可能隐藏正确路径。
  2. 本研究没有实验室验证。 条件 profile 来自反应记录和文献，不能替代实验验证。
  3. 中医药来源异构。 药材名、炮制品、物种归属、方剂版本和来源档位都可能存在歧义；系统报告未解析 token，而不是强行匹配。
  4. 条件证据不完整。 许多模板没有可用条件记录。缺少条件标记表示“当前条件数据中未找到”，不表示“不可能发生”。
  5. 不存在通用安全保证。 公开构建关闭高风险接口，但任何软件过滤都不能替代法律审查、机构控制或负责任使用。
  6. 数据与许可边界。 部分本地资源由库主维护，不能重新分发；公开 Demo 只使用小型脱敏摘录。

结论

Christos 为天然产物和中医药研究提供了一个可溯源、只读的反应预测工作流，将显式输入解析、模板式枚举与逆合成、条件证据和可审计报告连接起来。在泄漏受控的 USPTO-50k 基准上，选定配置达到 82.32% 的单步召回；逆向搜索在 5,002 个目标上达到 94.74% 覆盖率；多步规划在深度 ≤2/≤3 时分别达到 47.67%/72.33%。本系统的主要贡献不是一个新的黑箱预测器，而是一条可检查的流水线：每个候选的来源、规则、条件和不确定性始终可见。

数据与代码可用性

仓库包含协议、结果表、图件源文件和可运行脚本。上游原始数据不再分发。公开演示包是固定预计算样本，不包含生产数据库。投稿前将补充仓库 URL 和归档 DOI。
