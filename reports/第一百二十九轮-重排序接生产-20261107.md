# 第一百二十九轮：重排序接入生产（`--rerank`，默认关）

> 2026-11-07。把第 128 轮的离线实验接进真实路径：`predict ... --rerank`。
> 结论：**接上了，候选集合与召回完全不变，top-1 从 44.1% 提到 51.7%（+7.6 pp）**；
> 但生产路径只发挥了离线模型一半的增益（离线 66.9%），原因已定位到一个可以再修的点。

---

## 0. 一句话

开关默认关、行为零变化；打开后**只改顺序**：1,000 条官方切分上 recall 仍是 91.0%，top-1 44.1% → 51.7%，
top-5 66.9% → 72.2%，MRR 0.5507 → 0.6191，零报错。

---

## 1. 改了什么

| 文件 | 改动 |
|---|---|
| `core/rerank.py`（新） | `Reranker` 类：读 pkl 模型 + 模板 support 表 + curated id；`reorder(products, eng, cond)` 用 9 个数值特征 + 29 个规则族 one-hot 打分，稳定排序；任何异常退回发射序 |
| `core/smartreact_engine.py` | `__init__(rerank_model=None)`；`step()` 末尾在返回前重排、重编号 `seq`、`stats["reranked"]=1` |
| `core/query_base.py` | `RunSpec.rerank: bool = False`；`build_inventory` 在构造引擎前解析模型路径（`CHEMCREACT_RERANK_MODEL` 优先，否则 `reports/rank_model_20261107.pkl`） |
| `integration/tcmai_bridge/chemreact.py` | `--rerank` 参数 + `switches["rerank"]` + `RunSpec(rerank=...)` |
| `tools/train_ranker.py` | `--model-out`，训练完 `pickle.dump` 出模型（428.7 KB） |
| `tools/build_rank_dataset.py` | `src_ha` 改为按候选自己算（含 partner），与生产口径一致 |
| `tools/paper_bench_official_test.py` | 支持 `CHEMCREACT_BENCH_RERANK=1` 做 A/B |

**特征口径的一个坑（已修）**：原来训练时用了 `eng`（= `Product.score`），但生产基准路径不跑 scorer，该值恒为 0 →
训练与推理不一致。已从模型里去掉这个特征并重训，离线指标不变（top-1 66.93%）。

## 2. 实测

### 2.1 候选集合不变（关键验收）

同一个种子跑两遍（布洛芬 / 煎煮 / 1 轮）：

```
行数 off=10 on=10
集合完全相同: True
顺序完全相同: False        ← 只有顺序变了
耗时 off=3.2s on=4.6s
```

CLI 侧：`--herb 甘草 --limit 6 --rounds 1 --rerank` → **824 行**，与不加开关完全一致。

### 2.2 炮制 8 场景（默认关，一个数没变）

```
43 / 43 / 46 / 43 / 81 / 43 / 43 / 824
```

与第 89 轮以来的基线逐项相同 —— 因为默认关，代码路径没有进入重排。

### 2.3 官方切分 1,000 条（`CHEMCREACT_BENCH_RERANK` A/B）

| 指标 | 关闭 | 打开 | 差 |
|---|---|---|---|
| recall_1step | 91.0% | 91.0% | 0 |
| **top-1** | **44.1%** | **51.7%** | **+7.6 pp** |
| top-3 | 59.5% | 66.9% | +7.4 pp |
| top-5 | 66.9% | 72.2% | +5.3 pp |
| top-10 | 79.4% | 81.6% | +2.2 pp |
| MRR | 0.5507 | 0.6191 | +0.068 |
| 报错 | 0 | 0 | — |

耗时 53 s → 93 s（重排要算 extent 与特征）。

## 3. 「15 pp 落差」已查清：是配置差异，不是 bug

先前我以为生产路径丢了 15 个点，怀疑 `template_support` 查表落空。**这个假设是错的**，实测：

```
sup 表: 41619
反应数: 40   产出行: 952
sup 命中: 929/952 = 97.6%         ← 查表正常
act  mean=0.998  median=1.000 nonzero=952/952
ext  mean=0.993  median=1.000 nonzero=952/952
```

真正的原因是**两套配置的候选池不同**。`paper_bench_official_test.py` 默认走的是「基准配置」
（不加载 curated 模板、不启用严格氧化还原门），而命令行 `predict` 走的是「生产配置」
（`use_curated_templates=True` + `strict_redox_gate=True`）。同一个模型在两种配置下表现差很多：

| 配置（1,000 条官方切分，各 150 条子集先验证） | 召回 | 关 top-1 | 开 top-1 |
|---|---|---|---|
| 基准配置（无 curated、无严格门） | 88.7% | 48.7% | **54.0%** |
| **生产配置（curated + 严格门）** | 89.3% | 48.7% | **65.3%** |

放大到 1,000 条的完整 A/B（`CHEMCREACT_BENCH_CLI_CONFIG=1` 对齐命令行口径）：

| 指标 | 关闭 | 打开 | 差 |
|---|---|---|---|
| recall_1step | 92.0% | 92.0% | 0 |
| **top-1** | **44.1%** | **68.2%** | **+24.1 pp** |
| top-3 | 59.6% | 84.1% | +24.5 pp |
| top-5 | 67.0% | 88.1% | +21.1 pp |
| top-10 | 79.5% | 90.9% | +11.4 pp |
| MRR | 0.5517 | 0.7684 | +0.217 |
| 报错 | 0 | 0 | — |

**结论：命令行实际用的就是这套生产配置 → 打开 `--rerank` 后 top-1 是 68.2%，与离线 66.9% 吻合
（略高，因为 1,000 条子集与训练集的重叠不同）。** 先前那个 51.7% 只在基准配置下成立。

写论文时口径要说死：
- 「生产配置（curated + 严格门）：top-1 44.1% → 68.2%」
- 「基准配置（无 curated）：top-1 44.1% → 54.0%」
- 两个数字都真，但不能混用；召回始终不变（92.0%）。

---

## 4. 局限

1. 只在 USPTO-50k 官方切分上验证（1,000 条子集）；**TCM 侧（煎煮/炮制/方剂）没有训练数据**，未回归——
   但候选集合不变这一点已经从两个方向验证（同种子 A/B、炮制 8 场景默认关）。
2. 模型依赖 mined 模板库的 support 分布；换模板库（如宽档 60k）需要重训。
3. 不解决"会不会反应"（诱饵特异性仍 ≈ 0），只解决"对了排不排前面"。
4. 生产增益（+7.6 pp）与离线（+25 pp）之间的 15 pp 落差尚未消除。
