## 1. 做了什么

新增 `api/predict.py`，把前面 12 轮的所有模块串成一条链：

```
输入（方剂原文 / 药材名 / 直接 SMILES）  +  处理条件
    ↓
① 方剂解析  →  药材名 + 剂量 + 炮制     ★复用你项目里的 src/parse_peifang.py★
    ↓
② 成分采集  →  从 tcm.db 读（只读）      sources/herb.py
    ↓
③ 条件激活  →  哪些反应在这种工艺下会发生   conditions/
    ↓
④ 级联收敛  →  7 轮停下，高分产物一个不丢   core/cascade.py
    ↓
⑤ 评分排序 + 来源追溯                    core/scorer.py
    ↓
产物清单（每个产物都带"来自哪味药 / 哪个成分 / 哪条规则 / 第几轮 / 置信度"）
```

## 2. 三种输入方式都通

### A) 方剂原文

```powershell
python predict.py --formula "甘草2两（炙），干姜1两半，附子1枚（生用，去皮，破8片）。"
```

实测输出：

```
解析出药材: ['甘草', '干姜', '附子']
解析器: src/parse_peifang.py（复用你项目里的）      ← ★确实是你那个★
剂量: {'甘草': '2两', '干姜': '1两半', '附子': '1枚'}

甘草             25 个成分
干姜             25 个成分
附子             25 个成分
```

**古方剂量（2两/1两半/1枚）和炮制（炙/生用，去皮，破8片）都正确识别了**——
因为用的是你自己写好的解析器，不是我重写一遍。

### B) 药材名

```powershell
python predict.py --herbs 附子 干姜 甘草 --condition 煎煮
```

### C) 直接给分子

```powershell
python predict.py --smiles "COC(=O)c1ccccc1" --condition 醇提
```

## 4. ★ 顺手解决一个可用性问题：异构体泛滥 ★

第一版跑出来 Top 20 里**同一个分子式反复出现**——它们其实是**不同位点氧化的异构体**。
化学上确实是不同分子，但铺在清单里太吵，而且会淹没其他反应类型的产物。

**新增去重视图 `diverse_products()`**：同一个分子式只保留最高分代表，
并标出"这一组有几个异构体"。

效果：**2087 个主体产物 → 622 个**。信息一点没丢（异构体数量照旧显示），可读性大幅提升。

同时也暴露了一个**规则质量问题**（记下来待处理）：

> `羟基氧化` 一个化合物能产出 **28 个同分异构体**（分子上每个仲醇都被氧化一次）。
> 虽然 `max_products_per_molecule=2` 限了每个分子最多出 2 个，
> 但化合物多了总量还是大。**这条规则需要加位置选择性约束。**
