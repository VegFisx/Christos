## 1. 修：双底物反应的原子守恒率算错了分母

**问题**：第 90 轮引入的 `atom_conservation()` 分母只有「主底物」。
双底物反应（缩合、酯化、Michael 加成）的产物里含第二个底物的原子，
分母却不含它 → 守恒率被系统性放大，反过来又让 `< 0.7` 的判定失真。

第 90 轮报告里那条 `condensation_aldol_001`（`C48H72O19 → C28H34O14`）就是这类噪声。

**改法**（`core/reaction_paths.py`）：

```python
def atom_conservation(source_smiles, product_smiles, co_products="", partner_smiles=""):
    s = heavy_atoms(source_smiles)
    if partner_smiles.strip():
        s += heavy_atoms(partner_smiles)   # ← 分母加上第二个底物
    ...
```

调用方同步（都从台账行取 `partner_smiles`）：
`tools/make_report.py:524`、`tools/check_atom_loss.py:84`。

**实测影响**（甘草 `--limit 6`、煎煮、1 轮、824 行）：

| 项 | 数值 |
|---|---|
| 台账里 `partner_smiles` 非空的行 | **616 / 824** |
| 这些行守恒率的变化（新 − 旧） | 均值 **−2.88**、中位 **−3.14**、最小 −5.83、最大 −0.03 |
| 因为改分母而跨过 0.7 档位的行 | **0** |
| 仍被标「低守恒」的行 | 1（`condensation_aldol_001`，`C48H72O19 → C28H34O14`，0.60） |

读法：改完以后**双底物行的守恒率回到 1 附近**（旧值虚高到 3~7），
不再出现「3.7 都算正常」这种失真；剩下那 1 条是真的「产物只剩片段」，保留标记、不动产物。

## 2. 加：GUI 里的「强制纳入成分」

**为什么**：第 109 轮整味药验证的结论是「取样层决定成败」——
生产默认取样是「marker 优先 → 分子量降序 → 去重」，人参皂苷 Rb1 在成分表里排第 **298**，
默认 12 个种子里根本没有它，于是「人参整味药跑不出 Rg3」不是化学错，是取样漏。
CLI 早就有 `--include`，但 GUI 没入口。

**改法**：
- `integration/tcmai_bridge/ui_page.html`：主表单加 `#include`、方剂表单加 `#f_include`
  （提示文案写明「留空 = 不强制；例：Ginsenoside rb1, Ginsenoside rb2」），两处 POST body 各加 `include:` 字段。
- `integration/tcmai_bridge/ui.py`：`_start_run()` 里若 `include` 非空则 `argv += ["--include", _inc]`（注释写明第 109 轮的来龙去脉）。

**验证**：
- `tools/check_ui_js.py` → **2/2 block(s) passed**（752 / 76,547 字符）。
- 假 `Popen` + 伪造表单（`herb=人参, limit=12, include="Ginsenoside rb1, Ginsenoside rb2"`）
  → argv 中出现 `--include`，值为 `Ginsenoside rb1, Ginsenoside rb2`。
- `ui.py` AST 通过。
