## 2 接入方式

新增只读适配器 `sources/drug.py`：

- 按 **ChEMBL ID → 首选名 → 同义词**解析；
- 名称命中多个条目时，按「母体 → 非撤市 → 已批准 → ID」排序，
  并在运行记录中写明候选数；仍无法唯一确定时报
  `AmbiguousDrugError`，请用户改用 ChEMBL ID；
- 每条种子保留 `chembl_id`、`preferred name`、`formula`、`inchi_key`、
  `max_phase`、`parent_chembl_id`、盐型/撤市标记等来源字段；
- `to_compound()` 把来源标签写成 `药物:ChEMBL:<ID>`，台账
  `source_herb` 列逐条可追溯。

命令行入口在原有 `predict` 上新增：

```powershell
# 单个 / 多个药物
python integration\tcmai_bridge\chemreact.py predict --drug ASPIRIN --cond 煎煮
python integration\tcmai_bridge\chemreact.py predict --drug "ASPIRIN,IBUPROFEN" --cond 煎煮

# 文件：每行一个药名或 ChEMBL ID
python integration\tcmai_bridge\chemreact.py predict --drug-file drugs.txt --cond 煎煮

# 指定快照（默认 data/drugs/chembl_*_drugs.jsonl，也可用 CHEMREACT_DRUG_DB）
python integration\tcmai_bridge\chemreact.py predict --drug ASPIRIN \
  --drug-snapshot data\drugs\chembl_37_drugs.jsonl
```

药物输入与 `--herb/--smiles/--mol` 可以同时使用；引擎把它们当作同一批
底物做两两/单底物枚举。**多药输入是“混合物枚举”，不是复方剂量模型。**

完整 InChIKey 的 5 条差异不是搬运损坏：ChEMBL 的 `standard_inchi_key`
带了 `canonical_smiles` 未编码的立体层（如 `CHEMBL500576` TEMOPORFIN、
`CHEMBL474579` CEFOTETAN、`CHEMBL1201098` CEFOTETAN DISODIUM 等），
骨架与分子式一致。本轮如实报告，不手改结构；反应输入使用 ChEMBL 的
`canonical_smiles`。

## 5 规则与回归

- 规则总数不变：**82**（active 76 / disabled 6）；证据表 18 条不变。
- 未改任何 SMARTS、byproducts、co_reagents、状态或支持度。
- 新增的是输入源与适配器；引擎枚举路径不变。
- 需要观察的边界：药物库快照会随 ChEMBL 版本更新；旧快照保留不覆盖。

## 6 已知限制

1. **只做化学枚举**：不建模给药途径、剂量、吸收/代谢、蛋白结合、
   临床疗效或毒性；输出是候选化学产物，**不是医疗建议**。
2. `max_phase=4` 只是 ChEMBL 的批准口径，不等于当前仍在销售；
   `withdrawn` 字段保留但不会自动剔除。
3. 盐型与母体并存。按名称解析会优先母体；需要特定盐型时请给
   ChEMBL ID。
4. 多药输入 = 同一反应体系里的混合物枚举，不是复方配伍/剂量模型。
5. 5 条立体层 InChIKey 差异见 §3；不手改。
6. 快照只含小分子；生物制品不在本轮范围。
