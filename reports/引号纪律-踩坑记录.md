# 引号纪律 —— 一次任务连踩 5 次的记录（2026-10-11）

> **用户原话**：「把引号问题列入报告里，不要再犯引号的病了」
>
> 这 5 次全部是**我自己的工具用法错误**，不是化学/算法问题。
> 但每一次都要花 1~2 轮定位，而且报错指向的是**生成的代码**、不是**生成代码的那段代码**，很容易看错方向。

## 一、5 个实例（都在同一轮任务里）

| # | 我写的 | 报的错 | 根因 |
|---|---|---|---|
| 1 | `String.raw` 里写含 `\n` 的 Python print | Python `SyntaxError: unterminated string literal` | **`String.raw` 不做转义**：`\n` 变成字面的「反斜杠+n」两个字符，把 Python 字符串截断 |
| 2 | 单引号 JS 串里出现未转义的反引号 | JS `Expected a semicolon` | 反引号提前结束了模板串 |
| 3 | 把 Python 的 f-string 塞进单引号 JS 串 | Python `SyntaxError: unterminated f-string` | JS 串用双引号包 Python 的双引号，配对错乱 |
| 4 | Python 里写 `a = x && y` | Python `SyntaxError: invalid syntax` | 脑子里在写 JS，把 Python 的 `and` 写成 `&&` |
| 5 | 中文引号与 ASCII 引号混用 | Python `unterminated string` | 配对不上 |

**影响**：其中 #1 和 #3 各让一个脚本白跑一轮；#2 和 #4 各触发一次返工；#5 出现过两次。

## 二、硬性纪律（已写入 `AGENTS.md` 第八节）

1. **不用 `String.raw` 写 Python 代码**。
   `String.raw` 只适合正则表达式和 Windows 路径。
   要写换行符 / 制表符 / 转义引号，必须用**普通模板串**，让引擎真转义。
2. **要多行内容，就做成 `string[]` 再 `join(换行符)`**。
   每行独立、绝不在行内换行 —— 这是本工作区验证过最稳的写法
   （本轮的 `_update_handover*.py`、本报告都是这么生成的）。
3. **要嵌入会含引号的文本，一律 `JSON.stringify(s)`**，不要手写引号。
   例：不要写 `L.push("print(\"x\")")`，改成 `L.push("print(" + JSON.stringify("x") + ")")`。
4. **不要在模板串里混中英文引号**。中文引号统一用 `「」`，ASCII 引号只留给代码。
5. **写 Python 时想清楚不是 JS**：`and / or / not`，不是 `&& / || / !`；`True / False / None`。
6. **写完立刻语法检查，别等运行**：

```powershell
python -c "import ast; ast.parse(open(r'路径',encoding='utf-8').read()); print('OK')"
```

## 三、和已有一条纪律的关系

`AGENTS.md` 第六条（省 token）里有一条「**先打印原始数据再写解析逻辑**」，
引号问题是它同一类毛病的**工具侧版本**：

- 数据侧：别先假设分隔符是 `>>`，先把原字符串打出来看；
- 代码侧：别先假设引号能这样拼，**先用 `ast.parse` 验一遍**再往下走。

两者都是「**用 30 秒的检查，换掉一整轮的返工**」。

## 四、本轮实际用到的稳定写法（可直接抄）

```javascript
// 生成 Python 脚本内容：每行一个元素，绝不换行，需要引号就 JSON.stringify
const q = (s) => `L.push(${JSON.stringify(s)});`;
const lines = [
  "# -*- coding: utf-8 -*-",
  "import sys",
  "from pathlib import Path",
  q("## 标题"),
  q("正文里可以随便有 \"引号\" 和 `反引号`"),
];
await tools.write({ file_path: "xxx.py", content: lines.join("\n") });
```

写完立刻：`python -c "import ast; ast.parse(open(...).read())"` 过一遍。
