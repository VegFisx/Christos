# 第一百一十七轮：外部基线核对（能不能和文献数字比）

日期：2026-11-06
范围：`tools/paper_bench_official_test.py`（加 `CHEMCREACT_BENCH_STRICT_SINGLE`）、本报告
数据：`reports/paper/results/official_strict_single_20261106/forward_official_test__strict_single.json`

## 0. 一句话

**USPTO-50K 上不存在可比的已发表正向 top-1 基线**：所有 90 %+ 的数字都跑在 **USPTO-MIT 480K**
（test 40,000），而 50K 上唯一的正向数字是一篇 preprint 的自定义切分 33 %。
所以我们现在的 43.28 % **既不能和 90 % 比，也不能和 33 % 比**——不是数字大小的问题，是分母不同。

## 1. 我们自己的口径（先把尺子钉死）

| 项 | 值 |
|---|---|
| 数据 | `reports/paper/data/uspto50k_official/raw_test.csv`（RetroComposer 镜像的 Lowe 官方 test 切分，5,001 行） |
| 可评 | **4,993**（剔除 8 行「3 个反应物」——我们只支持 1~2 底物） |
| 产物数 | **每行恰好 1 个产物**（实测 `products per row {1: 5001}`）→ 不存在「只比主产物」的宽松 |
| 指标 | RDKit canonical 后 **exact match**，按发射序排名 |
| 召回 | **91.71 %**（4,579/4,993），0 报错，354 s（2 worker） |
| top-1 | **43.28 %** |
| top-5 / top-10 | 67.75 % / 78.85 % |
| MRR | 0.5496 |
| 平均候选 | 21.8 |

补充：加 `CHEMCREACT_BENCH_STRICT_SINGLE=1` 只保留单产物行再跑一遍，**4,993 条一条没少、四个指标完全相同**——
证明我们的 top-1 没有靠「挑主产物」占便宜。

## 3. 为什么不能直接比（六个断点）

1. **数据集规模/切分**：90 %+ 全在 480K（test 40,000）；50K 的 test 只有 5,001/5,007，且 Lowe 底稿存在
   40,008/5,001/5,007 与 40,004/5,000/5,006 等多个 atom-mapping 版本。
2. **指标细节**：是否先 canonical 化、是否整串 exact match、beam/多假设、是否做测试时增广
   （MT 的 90.4 是 20 次增广的平均，本身能抬分）。
3. **输入定义**：separated vs mixed。且 **USPTO-50K 原始数据缺溶剂/催化剂/试剂**
   （SynFormer 2025 原句 "lacks ... solvents, catalysts, reagents"），所以「reactants+reagents→products」
   这个口径在 50K 上根本不成立——我们实际上也是「底物 → 产物」。
4. **atom mapping**：部分模型推理时直接吃 mapping，RxnNano 报有/无 AAM 差 5.3 点（虽是逆合成）。
5. **方向混淆**：50K 上 52~65 % 的已发表条目是**逆合成**（Graph2SMILES 52.9、EditRetro 60.8、RetroDFM-R 65.0），
   聚合榜（SOTA2）把逆合成的 RxnNano 75.1 挂到正向条目，直接照抄会错。
6. **切分方式**：随机切分 vs 按模板/时间切分，差很多；唯一真「50K 正向」的那篇用的就是自定义切分。

## 4. 结论（对论文的含义）

- 现在能写的诚实句子只有：**「在 5,001 条官方 test 切分上，我们的候选集召回 91.71 %，top-1 43.28 %，
  平均候选 21.8；该切分上没有可比的已发表正向 top-1 基线。」**
- **不能写**「优于/接近 Molecular Transformer 的 90.4 %」——那是 480K、40,000 条、不同任务规模。
- 也**不能写**「优于 32.99 % 的 50K Transformer」——那是自定义切分、5-beam、且是 preprint。

## 5. 要真正可比，只有一条路

在 **USPTO-MIT 480K 的官方 test（40,000 条）** 上用**同一协议**跑我们的引擎，再和 90.4 / 92.5 并列。
成本估算：我们 2 worker 跑 4,993 条用 354 s ≈ **7 次/秒**，40,000 条约 **1.5 小时**（不含内存问题）。
前置条件：① 下载 480K 切分；② **先在同一语料上查泄漏**（我们的模板来自 ORD，也是专利来源，
   与 USPTO-MIT 可能重叠）；③ 声明我们的输入不含试剂（480K 有 separated 试剂，我们不用）。
