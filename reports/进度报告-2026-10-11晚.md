这句话里有两个信息，第二个是好消息，第一个是问题：

  **100 个真实反应里 26 个能给出化学上站得住的路线**，全自动、单分子 0.02~2 秒。

  系统仍然不知道反应需要什么条件；仍然测不出假阳性率。

## 三、今天实际解决的问题

白天之后我们做了四件事，每件都有「改前 → 改后」的实测数字。

> **⚠ 口径提醒**：下面几节的数字是在**不同模板库 / 不同搜索深度**下测的，
> **不能跨行直接比较**。每个数字都标了当时的口径（旧模板/新模板、单步/深度几）。
> 想看同一口径下的完整阶梯，看第 3 小节的那张表。

### 1. 逆合成的「终点」错了

原来系统判断「这个分子买得到」，靠的是天然产物库（COCONUT + 中药库）。
这是错的——**天然产物是「别人合成出来的东西」，不是「你能买的原料」**。
之前那个演示能跑通，纯粹因为乙酸、酪胺、水杨酸恰好也在天然产物库里。

改成：从 177 万条真实反应里，挑出**「只当原料用、从来不是产物」**的分子
——化学家买来的砌块。得到 **297,885 个**（核心砌块 32,146 个）。

效果：100 个真实产物里，能给出完整路线的从 **1.2% 涨到 5.0%**。

### 2. 逆合成的「模板」质量差

原来的模板是把**正向反应反过来用**。问题很直观：
它会告诉你「要造这个分子，你需要一个带硼的怪异中间体」——因为正向反应里硼是试剂。

改成：从 177 万条真实反应里**按逆方向重新抽模板**，再按反应中心聚类。
留下 **3,025 条**（比原来的 9,770 条还少，但更准）。

实测：让模板「复现」真实反应，旧模板成功 **10~12.5%**，新模板 **83~97%**。

### 3. 搜索器只会走一步

原来的搜索是「套一遍模板，找不到就放弃」。改成多步回溯：
拆一步 → 前体还买不到 → 继续拆那个前体 → 直到全是能买的。

端到端成功率的变化（100 个真实产物）：

| 配置 | 成功率 |
|---|---|
| 旧模板 + 单步（起点） | 4.0% |
| 新模板 + 单步 | 15.0% |
| 新模板 + 深度 2 | 30.0% |
| 新模板 + 深度 3（现在默认） | 45.0% |
| 新模板 + 深度 4 | 52.0%（但慢 2.9 倍） |

### 4. ★ 那个 45% 有水分 —— 今天最重要的发现

我一开始报的是 45%。后来我做了个检查：**这些路线在化学上真的成立吗？**

结果发现里面有大量这种货色：

```
目标：COc1cc(CC=C(C)C)cc(OC)c1O（一种异戊烯基取代的酚）
给出的「路线」：
   COc1cc(CC=C(C)C)cc(OC)c1N + O=S(=O)(O)O  →  …  →  目标
   └─ 这个前体就是「把目标的一个基团换成氨基」
```

**这不是合成路线，这是「先把目标变个样子，再变回来」。**

所以我加了一套化学合理性判据（残基路线 / 前体比目标还大 / 惰性小分子），
重新量了一遍：

| 口径 | 数字 |
|---|---|
| **形式成功率**（拼出一条完整路线） | **45.0%** |
| **化学可用率**（路线真站得住） | **26.0%** |
| 你看到的第一条路线就可用的比例 | **26.0%**（改动前只有 21%） |

**以后这两个数必须一起报。只报 45% 是在骗人。**

## 五、今天新发现的问题（三个，都比想象中严重）

### 问题 1：逆合成里 19 个点全是假的

就是第三节第 4 条。45% 减 26% = **19 个百分点是「形式上完整、化学上不成立」**。
现在只是把这类路线**排到后面**，没有阻止搜索生成它们。

### 问题 2：判定「好路线」的尺子，我第一版就做错了

我第一版判据说：「如果所有前体的原子数加起来比目标还多，这步就没把分子拆小」。
**结果 6 条已知合法的路线全被判成垃圾**——因为酰胺偶联本来就会脱一个水分子，
两个前体的原子数之和当然大于目标。

改了三版才对（用「前体是不是基本等于目标本身」来判断）。

**这件事的意义**：如果我当时没拿「已知正确的例子」去验那把尺子，
我会向你报告「可用率 0%」——一个完全错误的结论。
**量东西之前，先用已知答案验尺子。**

### 问题 3：有些「买得到」的分子其实买不到

系统判断「可购买」靠的是 InChIKey 骨架匹配（差一点也算）。
实测它会把**碘代胸苷**当成**胸苷**（因为骨架相同）——碘代胸苷显然不是随便能买的。
已经加了护栏（重原子数必须对得上、电荷必须一致），但这类误差没法完全消除。

## 六、和你最初想法的偏差，到底有多大

用一句话说：**方向没跑偏，但重心偏了，而且偏得很厉害。**

你一开始明确说「逆合成是之后要加的」，主线是**通用化学反应预测**（正向）。
今天（和上一轮）的精力几乎全在**逆合成**上。为什么？

因为正向那条路**卡住了**，而且是卡在数据上而不是努力上：

```
正向要解决「反应能不能发生」
  → 需要反例（明确不发生的反应）
  → 反例不存在（ORD 243 万条全是成功反应）
  → 只能靠条件门控（温度/溶剂/试剂）硬推
  → 但条件信息在模板里是缺的
```

**逆合成那条路没有这个死结**——它可以用「买不买得到」当客观判据，
所以它今天能从 4% 一路推到 26%。

**这就是偏差的来源，而且是理性的偏差，不是我走神。**
但代价必须说清楚：**你最关心的那个指标，今天没有动。**

| 你的三条诉求 | 今天的进展 |
|---|---|
| 反应全不全面 | 已达标（28.6%，且不随分子变大而掉） |
| 反应能不能发生 | **0 进展** |
| 逆合成（后加的） | 0 → 26% 可用 |

## 七、我们现在到底站在哪

可以这么说：**我们造出了一台能用的「路线生成器」，但它还没有「化学判断力」。**

它能做的：
- 给一个分子，2 秒内给几条合成路线
- 每条路线标出每一步用什么反应类型、终点原料是什么
- 标出哪条路线化学上更靠谱

它做不到的：
- 说这步反应在实验室里需要什么条件（温度、溶剂、催化剂）
- 说这条路线会不会因为副反应而失败
- 判断一个反应到底会不会发生（**你最想要的**）

## 八、接下来有几条路，请你挑

### 路线 A：回头补正向的「条件门控」（回到你的初心）

把已经建好的**条件表**（从 ORD 提取的 37 类反应的真实温度/溶剂/催化剂分布）
接进正向引擎，让「无条件就触发的反应」被降权或拦掉。

- 好处：直接打你最初说的「反应能不能发生」
- 风险：这只能**减少**假阳性，仍然**测不出**准确率（没有反例数据）
- 成本：中等，条件表已经在了，缺的是接进去

### 路线 B：继续收拾逆合成（把它做到能见人）

把「换基团」那类假路线从搜索阶段就掐死（现在只是排到后面），
目标是把可用率从 26% 推到 35~40%。

- 好处：接进 TCMAI 就是一个能拿出手的功能
- 风险：这是**优化我们已经擅长的东西**，不是补短板
- 成本：中等

### 路线 C：接进 TCMAI（先让东西跑起来）

现在 26% 可用率 + 每条路线带可用性标注，作为「实验性」功能是诚实可用的。
你说的「彻底完备了再接」——**现在肯定不算完备**，但你可以决定「够不够用」。

- 好处：你能真的上手用，反馈比我的基准测试值钱
- 风险：功能会显得不可靠（四条路线里有三条可能站不住）

### 我的建议

**A → C → B**。

理由：A 是回到你的初心，而且成本不高（条件表已经躺在那里）；
C 让你尽快上手，你的真实反馈能告诉我们 B 值不值得做。
B 听起来最诱人（数字涨得最快），但它是在我们已经最擅长的方向上继续投入。
