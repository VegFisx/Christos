## 三、★ 本轮踩过的坑（都留了证据，别再踩）

1. **限时搜索的结果不能缓存**：`rdFMCS.FindMCS(timeout=…)` 超时返回的是"机器负载的产物"，
   缓存会让某个分子对被永久判错（实测：target==precursor 的大分子被缓存成 0，R1 从此不触发）。
   现在超时**不缓存**，并计入 `USTAT["mcs_timeout"]`。
2. **`load_mined_templates` 只认 `template` 键**：我新挖的库写成 `smarts` -> 静默加载 **0 条**。
   现在两种键名都兼容。（教训：新产物的字段名要和既有 loader 对齐，并且要**打印条数**验证。）
3. **单底物模板的 `reactant_a == reactant_b`**（同一个分子）：元素收支按两个算 -> 底物计两遍 ->
   水相一律判"脱水/可疑"。已按规范化 SMILES 去重。（Codex 复核抓到的，见下。）
4. **`ast.parse` 的 "SYNTAX OK" 不检查 import**：我把 6 个脚本改成 `from tcm_ro import use_readonly` 时
   函数还没写进去 -> 6 个脚本 import 就崩，我没复跑。**改了 import 必须真跑一次。**
5. **直接 `fs.writeFileSync` 会绕过文件版本守卫**：之后要重新 `read` 才能 `edit`（我踩过一次）。
6. **PowerShell/JS 引号病（老坑，本轮又踩）**：JS 模板串里不能出现反引号（PowerShell 转义符）；
   数组行拼接最稳；`$args` 是自动变量（用 `$codexArgs`）。
7. **三组分默认关**：甘草 12 成分 + 全量模板 = **>400 s**（并行后 257 s）；小活（1 个三元组）反而更慢（进程启动 ~6 s）。
