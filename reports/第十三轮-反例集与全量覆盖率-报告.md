## 一、反例集：从 853 条候选到 17 条干净反例

### 1.1 流水线

```
全量 1,771,032 条 ORD
  ├─ A 路（notes 严格否定短语）      449 条
  └─ B 路（真实 PERCENTYIELD == 0）  404 条        A ∩ B = 0
        ↓ 规则筛选 screen_negative_candidates.py
     A: strict 147 / weak 145 / false 157
     B: b_zero 229 / false 175
        ↓ 6 块 × 63 条 交子代理逐条复核（读 ORD 原文全文，不只看 400 字摘要）
     376 条全部标注，0 遗漏 / 0 重复
        ↓ 合并 merge_review_labels.py
     strict 17（A 15 + B 2）/ weak 84 / false 275
```

### 1.2 规则筛选的精度：远没有想象的高（实测混淆矩阵）

| 规则给的标签 | 逐条复核后 | 数量 |
|---|---|---|
| A:strict（147） | 仍是 strict | **15（10%）** |
| A:strict | 其实只是 weak | 84（57%） |
| A:strict | 其实是 false | 48（33%） |
| B:b_zero（229） | 仍是 strict | **2（1%）** |
| B:b_zero | false | 227（99%） |

即：**正则命中"没反应"的字面，绝大部分并不是"反应没发生"**。
典型假阳性三类（子代理逐条读原文得出，多个块互相印证）：
1. **否定说的是后一步/另一条件/别人文献**（本步其实有 87~96% 收率）；
2. **补加试剂或升温后就推进了**（→ weak：「该条件不充分」而不是「不反应」）；
3. **否定说的是后处理/析晶/溶解/选择性**（"failed to produce a precipitate" 实收 62.4%）。

### 1.3 B 路（0% 收率）几乎是解析伪影 —— 三路独立证据

子代理在各自分块里**独立**回查 ORD 原始 parquet 后发现同一个机制（0/1/2/3/4/5 块结论一致）：

- 挂着 `PERCENTYIELD = 0.0` 的那个 product 实体，标识符是**层析洗脱剂名**
  （`EtOAc—hexanes` / `ethyl acetate petrol` / `MeOH NH3` / `Solvent B` / `eluent`），
  真正的 `title compound` 那条 product **没有任何收率测量**；
- 0% 的文本来源是**梯度写法**：`column chromatography (0% to 60% EtOAc-hexanes)`；
- 原文往往明写产物已拿到：`1.80 g (92%)`、`355.0 mg (90%)`、`200.0 mg (99%)`、`furnished … quantitatively`。

**量化验证**（`tools/extract_negative_examples.py` 新增 B-v2 口径，全量重扫 236 秒）：

| B 路口径 | 条数 |
|---|---|
| 真实 PERCENTYIELD==0（旧口径） | 404 |
| ├ 0% 挂在**无结构标识符**的"产物"上（**伪影**） | **379** |
| └ **B-v2**：0% 挂在有结构标识符的产物上 | **25** |
| CALCULATEDPERCENTYIELD==0（早先已排除的假反例） | 405 |

B-v2 的 25 条里有 8 条已在上一批复核过（其中 2 条 strict），**剩下 17 条本轮补审 → 0 条 strict**。
补审还发现 `has_struct_id` 这一道过滤**不够**：17 条里 9 条的 0% 挂在 **NH₃ / 2M NH₃ in MeOH**
（名字被解析成了 SMILES，所以躲过了"无结构标识符"过滤），2 条挂在 `EtOAc/isohexane` 梯度，
1 条 0% 来自 `total sulfur content 0%`，1 条来自 `0% to 100%` 梯度，1 条专利原文写
`169 mg (yield of 0%)` 但同句说晶体已收集且 CALCULATED=34.7%；
只有 2 条（Pd/Re 催化马来酸酐氢化，`GBL 10.5% / 1,4-丁二醇 0%`）是**真实 0% 测量值**，
但底物已反应 → 按保守原则判 weak。
→ **B 路彻底出局**：404 条 → 379 条伪影 → 25 条"有结构标识符" → 复核后 **0 条 strict**。

### 1.4 最终反例集（复核 393 条，0 遗漏 / 0 重复）

| 文件 | 内容 | 条数 |
|---|---|---|
| `reports/negative_clean.jsonl` | **干净反例集（strict）** | **17**（A 15 + B 2） |
| `reports/negative_weak.jsonl` | 弱反例（该条件不充分/部分转化/加料后推进） | 86 |
| `reports/neg_screened_false.jsonl` | 逐条复核判定为假阳性 | 290（+ 规则阶段另 332 条） |

置信度极低的反例比例：**17 / 1,771,032 = 0.001%**。

Top 级别的严格反例长这样（子代理复核理由）：
- `ord-819003f3…`：`31P-NMR showed 0% yield … produces no N-(2-hydroxyethyl)aminomethylphosphonic acid`（真·无产物）；
- `ord-15f580d0…`：FTIR 证明 dextromethorphan-HBr 与单宁酸未反应，产物只是混合物；
- `ord-ef6abbf1…`：`failed to react with ethanethiol … all regained starting material`（多条件只回收原料）。

## 二、② agents 段口径：实测后决定【不改】

`tools/probe_agents_value.py`，20 万条，逐段跑角色 SMARTS：

| 角色 | reactants 段 | agents 段 | **只在 agents** |
|---|---|---|---|
| carbonate | 16,718 | 280 | 267 |
| borohydride | 6,154 | 36 | 34 |
| benzotriazole | 3,734 | 6 | 4 |
| phosphine | 3,664 | 1,636 | **1,609** |
| carbodiimide | 3,518 | 6 | 6 |
| uronium_activator | 2,067 | 1 | 1 |
| azodicarboxylate | 1,029 | 1 | 1 |

**决定不改**，两条理由：
1. 除 phosphine 外，agents 段新增量都在 1% 量级 —— **收益极低**；
2. phosphine 那 1,609 条里，绝大多数是**催化剂配体**（如 Pd(PPh₃)₄ 里的 PPh₃）。
   把它算成"必需试剂"，会出现"没写 PPh₃ 就不许 Suzuki"这种**误杀** —— 扩口径反而有害。

这正好是「先测再改」省下的一次错误投入（否则要重跑 30 分钟 + 引入误杀）。

## 三、① 全量覆盖率（1,771,032 条，36 片，总耗时 3838 秒）

### 3.1 覆盖规模

| 指标 | 值 |
|---|---|
| 扫描 | **1,771,032 条**（全量） |
| 归类成功（= 覆盖率的分母） | **367,434 条（20.7%）/ 34 类** |
| 30 万级失败原因（全部计数，不静默） | 未匹配到 37 类模板 760,695；单反应物(不归类) 379,749；贡献者>2 122,492；产物数≥2 145,000+ |

### 3.2 引擎实际判零的类：6/37（全量数据 + 去离子 + 角色归并）

| 反应类型 | 样本 | 必需件 |
|---|---|---|
| `mitsunobu` | 7,919 | phosphine 60% + **azodicarboxylate 52%** |
| `reductive_amination_aldehyde` | 16,288 | borohydride 57% |
| `reductive_amination_ketone` | 5,794 | borohydride 56% |
| `ullmann_phenol` | 6,586 | carbonate_base 51% |
| `chan_lam` | 605 | pyridine 52% |
| `ester_sulfonic_schotten_baumann` | 9,051 | trialkylamine 52% |

回归：**37/37 类「不写试剂」全部放行**；Mitsunobu 只给 PPh₃ → 判零，给 DIAD 不误杀（与上一轮一致）。

### 3.3 ★ 全量跑暴露的两个问题（40 万条时看不出来）★

1. **小样本会把边界类误判**：
   40 万条时 Suzuki 的碳酸根覆盖率 **55.7% → 被判成必需件**；
   全量 177 万条（suzuki n=41,470）降到 **49.5%** → **判据消失**。
   → 这就是"覆盖率要跑全量"的价值：0.5 附近的类在 22.6% 抽样上会翻来翻去。
2. **两处口径 bug**（都已修，且有界）：
   - `summarize()` 只存每类 **top-12** 试剂 → 角色归并失效（Suzuki 的 top-12 全被
     `[Na+]/[K+]` 这类反离子占满，碳酸根被截掉）。已放宽到 **top-40**；
     分片件里存了完整计数器，所以只跑 `--merge-only` 重算即可（0 秒）。
   - **同一反应内同一碎片重复计数**：K₂CO₃ 拆成 `O=C([O-])[O-].[K+].[K+]` 后 `[K+]` 出现两次，
     实测 `ART` 的 `[K+]` 覆盖率算到 **126%**。根因已在 `accumulate()` 修（按反应去重），
     本次表格额外做 `min(1.0, …)` 保守截断（126% → 100%）。全表只有 **1 条**受影响。

3. **Suzuki 的边界案例（不调阈值去凑）**：碳酸根 **0.495**，差 0.005 没进判据。
   要不要为它把阈值从 0.50 降到 0.49 是**建模决定**，不是 bug —— 见下面的敏感性表。

### 3.4 阈值敏感性（全量表）

| 覆盖率阈值 \ 最小样本 | 5 | 20 | 50 | 100 |
|---|---|---|---|---|
| 0.35 | 19 类/34 件 | 18/31 | 18/31 | 17/27 |
| 0.40 | 17/26 | 16/24 | 16/24 | 15/22 |
| **0.50（引擎现值）** | 13/17 | **12/16** | 12/16 | 11/14 |
| 0.60 | 11/11 | 10/10 | 10/10 | 9/9 |
| 0.70 | 6/6 | 5/5 | 5/5 | 4/4 |

（表里是"按单分子覆盖率"数出来的类数；引擎实际是 **6/37**，因为还剔除了 `[Na+]/[K+]` 等
离子碎片、并把同功能分子按角色相加——两个方向的作用相反。）
读法：阈值从 0.5 降到 0.35，判零的类数从 12 涨到 18（**1.5 倍**）；升到 0.6 减到 10。
**「0.5」这个数是敏感的**，这条必须进局限。

## 四、③ 假阳性率的第一个数据点：0/17，但**这个 0 无信息**

`tools/fpr_probe_on_negatives.py`：
口径 = 取每条干净反例的 CXSMILES 反应物（去映射）喂正向引擎（**关条件门控**），
看是否预测出"文献说没生成"的那个产物。

| 指标 | 值 |
|---|---|
| 样本（干净反例） | 17 |
| 引擎预测出该产物（= 假阳性） | **0** |
| **引擎在这批底物上产出 ≥1 个候选产物的条数** | **1 / 17** ← 关键对照 |
| 有效分母 | 1（假阳性 0/1） |

**结论**：这个 0 不是"引擎不会误报"的证据，而是**引擎在这些反应上压根没有可用规则**
（整体覆盖率只有 28.6%，反例又多是膦酸、单宁酸盐这类冷门底物）。
→ **反例集上目前量不出假阳性率**，这是实测结论，不是推断。
