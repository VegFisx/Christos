# 第一百七十八轮：五条派生规则补丁 + 独立验证

> 用户确认「1 和 2 都做」：补 HMF，并补柴胡环醚、吴茱萸、马钱子、女贞子。
> 系统更新中断后继续。本轮只加规则，不改既有 73 条规则的 SMARTS、状态或证据。
> 规则冻结在本次补丁范围内解除。

## 1 这轮为什么不是"手写"

第 177 轮的两条规则是手写 SMARTS，另配 `validate_new_rules.py` 专门验证。
这一轮的五条**不是手写**：全部由文献里的「底物 → 产物」对经
**RXNMapper 原子映射 + RDChiral 模板抽取**派生，再倒转成 forward 模板。
派生脚本在 `_diag/derive_gap_templates*.py`（未入库）；派生结果写进
`rules/rules.json` 与 `rules/paozhi_evidence.json`，并保留 RXNMapper 的
派生说明（`notes` 与证据里的 `RXNMapper+RDChiral derived template` 条目）。

派生模板的可靠性不靠"看起来对"，靠三件事：

1. **自底物复现**：模板必须在原文献底物上给出目标产物；
2. **第二底物**：有同家族第二对文献时，用第二对验证泛化，而不是只拟合一条；
3. **专用负例**：产物本身、交叉糖、无关底物不得被同一条模板命中。

五条的证据等级都标 `secondary`：文献对给出转化方向，模板由 RXNMapper/RDChiral
派生；不是原始文献直接给出这条 forward 模板。第 177 轮的苄位规则也标
`secondary`，O-去甲基标 `primary`；本轮的共同点是证据支持"会发生"，
不等于支持"所有底物都按同一模板走"。

### 2.1 柴胡：规则名从"开环"改成"异构化"

模板最初命名为 `ring_opening_cyclic_ether_saponin_001`。holdout 的规则族
按 `isomerization/rearrangement` 记账，旧名会让结果被判成 `product_only`。
本轮只改新规则的名字，SMARTS 未动；改名后柴胡由 `product_only` 转为
`consistent`。这是一致性问题，不是为案例改规则。

### 2.2 马钱子：骨架命中，不是逐字全等

马钱子碱 → 异马钱子碱的产物在 E/Z 与质子化形态上与数据库记录不完全逐字相同。
验收按既有 holdout 口径用 InChIKey 前 14 位（骨架）判定；规则派生时也用同一口径。
因此报告里写"骨架命中"，不写"SMILES 全等"。

### 2.3 吴茱萸：产物是互变异构体

文献对给出的是 rutaecarpine 骨架；派生模板的产物是它的一个互变异构体。
holdout 的 InChIKey 前 14 位相同，故判 `consistent`。这是**骨架级**结论，
不是对具体互变异构体比例的预测。

### 2.4 HMF：果糖与葡萄糖必须分开

糖脱水/环化依赖吡喃环的立体化学。把果糖和葡萄糖强行合成一条模板，会在
交叉糖上误命中。本轮保留两条独立模板：

- 果糖模板含果糖吡喃环的立体环境，葡萄糖不匹配；
- 葡萄糖模板含葡萄糖吡喃环的立体环境，果糖不匹配；
- 蔗糖对两条都不命中（专用负例）。

地黄（九蒸九晒）用果糖模板闭环；黄精（酒蒸）的独立验证用例用葡萄糖模板闭环。

## 3 专用验证脚本

新增 `tools/validate_derived_rules.py`，只验证这五条派生规则，不读 30 例
holdout 的判定结果：

- 正例 7 项：柴胡 A→b1、柴胡 D→b2、士的宁→异士的宁、马钱子碱→异马钱子碱、
  吴茱萸碱→吴茱萸次碱、果糖→5-HMF、葡萄糖→5-HMF；
- 负例 7 项：三个产物自身、果糖/葡萄糖交叉、蔗糖对两条 HMF 规则；
- 配平：主产物 + 同批产物（含模板的 3 个 H2O）= 底物；
- 目标按 InChIKey 前 14 位匹配，与 holdout 口径一致。

结果：**PASS，14/14，0 failures**。

HMF 模板的 3 个水在引擎里会被去重成一个 Product；验证脚本用
`EXTRA_BYPRODUCTS = {"H2O": 2}` 补回另外两个水再配平。这是验证层的口径，
不是改模板。

## 7 女贞子：为什么这轮没补上

尝试用 `ligustroside → hydroxytyrosol` 派生模板。RXNMapper 给出的映射里，
反应物侧有两个片段（苷元 + 糖），RDChiral 抽出的模板要求两个反应物模板；
在单底物调用下直接报：

```
Number of reactants provided does not match number of reactant templates.
```

这条路径不能像前四条那样做成单底物 forward 规则。另一个"命中"来自通用模式下
的酯交换/氨解，不是文献里的水解路径，不能算闭合。

要补女贞子，需要**真正的多步序列**：先糖苷水解，再对苷元做后续转化；
或者把糖作为显式共底物/副产物纳入模板。两者都不是"再加一条 SMARTS"能解决的，
留作已记录缺口。

`C_miyan_adj` 是蜜炙（加蜂蜜辅料）。蜂蜜含果糖/葡萄糖，新的 HMF 模板
在蜜炙场景多给出一个 5-HMF 产物。对照组能说明它不是普遍污染：

- `C_miyan_noadj`（蜜炙、无辅料）仍是 45，没有增加；
- 其余 5 个炮制场景完全不变（45/45/83/45/45）；
- `guard_jiandao`（煎煮）仍是 824，没有变化。

因此 +1 是"HMF 规则在蜂蜜糖上生效"的定向变化，不是规则泄漏到所有场景。
