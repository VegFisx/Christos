## 1. 起因：一个挂了十几轮的数字

反应级验收一直报 **「覆盖规则 56 / 63」**。

我一直把它当成"还差几条，慢慢补"，**从没去看到底是哪几条**。

这轮去看了：

```
用例覆盖的规则: 56 条
未覆盖的【启用】规则: 2 条
    【对二酚氧化成醌】oxidation_diphenol_para_001
    【对醌还原成二酚】reduction_quinone_para_001
（另外 5 条是【已停用】的规则）
```

> **注意那个「63」的分母里含 5 条已停用规则。**
> 所以真实缺口是 **2 条**，不是 7 条。

## 3. 补用例

### 先验证期望产物，再写进去

吸取上两轮的教训（**手写复杂天然产物 SMILES 已经错过两次**），
这次**先把引擎实际产出的东西打出来，用它来写期望**：

| 规则 | 底物 | 产物 | 分子式变化 |
|---|---|---|---|
| 对二酚氧化成醌 | 对苯二酚 | 对苯醌 | C6H6O2 → C6H4O2 |
| 对二酚氧化成醌 | 9,10-蒽氢醌 | 9,10-蒽醌 | C14H10O2 → C14H8O2 |

| 对醌还原成二酚 | 9,10-蒽醌 | 9,10-蒽氢醌 | C14H8O2 → C14H10O2 |

## 4. ★ 加一道防线：不许再漏 ★

光补上不够——**下次加规则还是会忘**。所以在 `test_reaction_cases.py` 里加：

```python
active_ids = {r["id"] for r in rules if r.get("status") != "disabled"}
missing = sorted(active_ids - covered)
if missing:
    print(f"  ★ 有 {len(missing)} 条启用规则【没有验收用例】：...")
    raise SystemExit(1)
```

### 并且验证这道防线真的会红

第一次我的"绊倒测试"设计得不好：我把一条用例的规则改成别的，
但那条规则**还有另一个用例**，所以覆盖没掉 → 防线没红。

重做成"把一条规则的**全部**用例都改掉"：

```
篡改后：覆盖规则 57 / 58 条
        ★ 有 1 条启用规则【没有验收用例】：对醌还原成二酚
        exit=1   ✓ 防线正确触发

还原后：58/58   exit=0
```

> **加了防线就要验证它真的会红**——不然它只是个装饰。
