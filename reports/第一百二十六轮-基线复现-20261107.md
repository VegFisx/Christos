# 第一百二十六轮：58.73% 基线能不能复现

日期：2026-11-06

## 0. 一句话

配置复现了（候选分布逐项一致），**召回数字复现不了**：当前代码跑同配置得 **55.53%**，论文写 **58.73%**，差 3.2 pp。

## 1. 论文里这个数是怎么来的

论文 Methods 定义得很清楚（`manuscript-peerj-humanizer-20261030.md` 第 151 行）：

> The baseline retained the engine default of eight products per substrate pair, used no extra template pool, and left the compatibility prefilter off.

对应到当前代码：`CHEMCREACT_BENCH_LEGACY=1`（cap 8 + 预筛关）+ `CHEMCREACT_BENCH_NO_EXTRA=1`（不装 mined 池）。

历史结果文件里也有直接对应物：`reports/paper/results/forward_50k__legacy_on_full50k.json` = **0.5873**、`forward_50k__legacy_off_full50k.json` = 0.5623，都是 2026-10-30 跑的。

## 3. 差在哪（已知与未知）

- 立体开关不是原因：关掉反而更低（53.58%）。
- 第 84~125 轮的改动里，能影响「产物是否等于目标」的只有两类：模板套用后的产物规范化（`tools/rdkit_template_lib.py`）与 `also_rules`/`co_products` 相关改动。它们对**选定配置**只带来 +0.32 pp，对基线却是 −3.2 pp，方向相反，说明不是同一条路径。
- 尚未定位到具体一行——但候选分布一致这一点，把范围压到了「命中判定」而不是「产出多少」。

## 4. 对论文的影响（需要拍板）

三个选项：

1. **把基线改成 55.53%**（当前代码的真实值），并注明「与 2026-10-30 冻结值 58.73% 相差 3.2 pp，原因是产物规范化层改动」。差距从 32.96 pp 扩大到 35.46 pp。
2. **保留 58.73% 但标注为冻结值**，并写「在当前代码上按同配置重跑得 55.53%」。
3. **继续定位那 3.2 pp**（可能还要几个小时），再决定。

我的建议是 2：审稿人问的是「基线是不是自己搭的软柿子」，答案不变（58.73% 与 55.53% 都是同一套引擎的降档配置），把两个数都写出来反而更诚实。
