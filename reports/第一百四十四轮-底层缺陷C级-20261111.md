## 3. 没修的，以及为什么

- **B6**：`condition_model` 只训练了 `B-H` 一类（`TRAINED_CLASSES == ["B-H"]`），其余类台账留空。
  这不是 bug 是覆盖范围；要不要在台账里显式写「该类未建模」需要先定口径（空列现在表示「按类降级」）。
- **C11**：`tools/paper_bench_50k_forward.py:84` 对全部 10 类专利反应用同一个「煎煮」条件，
  还原类可能被气氛硬门判死，于是类别召回混了「条件不可达」与「模板缺失」。

  **本轮把它测掉了，结论是不成立**（`_diag/probe_c11.py`，每类抽 60 条，引擎配置相同，只换条件）：

  | 类 | 煎煮（水/100 °C/空气） | 还原条件（甲醇/25 °C/Pd–C/H₂） | Δ |
  |---|---|---|---|
  | 1 | 91.7% | 91.7% | 0 |
  | 2 | 98.3% | 98.3% | 0 |
  | 3 | 78.3% | 78.3% | 0 |
  | 4 | 63.3% | 63.3% | 0 |
  | 5 | 90.0% | 90.0% | 0 |
  | 6 | 100.0% | 100.0% | 0 |
  | 7 | 85.0% | 85.0% | 0 |
  | 8 | 98.3% | 98.3% | 0 |
  | 9 | 80.0% | 80.0% | 0 |
  | 10 | 76.7% | 76.7% | 0 |

  原因：基准走的是挖掘模板，`conditions/smartreact_engine.py:1444` 在「没有 ORD 条件数据」时
  直接返回 1.0 放行，条件门根本不参与；气氛硬门只对 curated 规则生效，而基准默认不装载 curated。
  所以这张逐类表里的低值（类 3、4、10）是**模板缺口**，不是条件不可达。
  这也顺带说明 A1 那次修复只影响「显式开 `--condition-gate`」的路径，基准数字不该动 —— 与实测一致。


## 4. 影响评估

本轮没有改常规路径的化学，所以「91.69 / 92.01 / 94.74 / 47.67 / 72.33」这些冻结数字不动。
变的是三件事：

1. **台账更完整**（130 行 `also_rules`、824 行 `template_smarts`）；
2. **重复计算不再发生**（C6、C4）；
3. **上限不再随便截**（C5）。

如果以后有人拿旧台账做规则族统计，`also_rules` 列会显示差异 —— 那是修复，不是回归。
