## 零、三件事的结论（先看这个）

| 任务 | 结论 | 关键数字（实测） |
|---|---|---|
| ② ORD 之外的**反例数据** | **找到了，而且是决定性的** | HTE（Buchwald–Hartwig）27,497 条里 **10,696 条收率 = 0**；用它首次量出：**假阳性 94.9%（强反例子集 93.1%）/ 召回 64.0% / 条件门控 AUC 0.530** |
| ③ **TCMAI 接入** | 技术就绪，**但我建议先别正式接** | 桥接模块跑通：甘草 40 成分 → 3,444 产物；可信度数字随接口一起给 |
| ① **ORD 自抽正向模板** | 见 §1（实验中/结论） | — |

**最重要的发现**：任务②不再是"没有反例"，而是"反例充足，**引擎照样答不对**"。
在 1,993 个 HTE 实测「所有条件收率全为 0」的底物对上，我们的引擎 **94.9% 声称能发生**；
而真正成功的对照只复现 64.0%；条件门控在 353,509 次「成功 vs 失败条件」比较上 **AUC 0.530**（等于瞎猜）。
→ 瓶颈不再是数据，是**引擎把"结构上能反应"当成了"会发生"**。

## 一、① ORD 自抽正向模板：**能顶上去，但有代价**

脚本 `tools/forward_template_mining.py`（40,000 抽样 / seed 固定 / train-test 按 md5 哈希隔离）。
口径全部写死在脚本头部；这里是结果。

### 1.1 规模与基准

| 项 | 值 |
|---|---|
| 抽样 | 40,000 条（`USING SAMPLE 40000 ROWS (reservoir, 20261012)`） |
| 可用（恰 2 个组分贡献原子 + 有映射产物 + 去重） | **26,884 条** |
| train / test | **13,569 / 13,315** |
| 跳过原因 | 贡献组分=1 8,745；=3 2,927；重复 747；≥4 1,244 |
| **基准覆盖率（现有 9,770 模板）** | train **29.7%**、test **30.0%**（与官方口径 28.6% 一致） |
| 基准漏掉的 train 反应 | 9,535 条 → 抽取 7,942 条（**过大分子跳过 1,593**，重原子>70 且慢） |
| 抽到的模板 | 7,150 次 → **去重 5,670 个**（落盘 `mined_forward_templates.jsonl`；其中支持数≥5 的 92 条、≥3 的 256 条；能编译成双反应物模板的 raw_K5=91 / raw_K3=254） |

### 1.2 增量（在 test 上验收，只看基准漏掉的那些反应）

基线 test 覆盖率 30.0%（13,315 条可测）。下表"整体增量"= 漏项命中率 × 漏项占比（因算力护栏只评了 4,000 条，属**外推**，已在 JSON 标 `extrapolated`）。

| 变体 | 模板数 | 漏项命中率 | **整体增量** | **推上去后覆盖率** | 宽松度（探针 500 条无关反应"有产出"率） |
|---|---|---|---|---|---|
| raw_K1（支持≥1，rdchiral 原样） | 600* | 13.7% | **+9.59 pp** | ~39.6% | 33.8% |
| raw_K2 | 600* | 13.7% | +9.59 pp | ~39.6% | 33.8% |
| raw_K3 | 254 | 10.7% | +7.51 pp | ~37.5% | 21.8% |
| **raw_K5（推荐）** | **91** | 7.0% | **+4.88 pp** | **~34.9%** | **7.8%** |
| gen_K1（泛化版） | 600* | 11.7% | +8.21 pp | ~38.2% | 43.2% |
| gen_K2 | 197 | 10.7% | +7.51 pp | ~37.5% | 38.0% |
| gen_K3 | 85 | 8.8% | +6.14 pp | ~36.1% | 33.6% |
| gen_K5 | 30 | 5.9% | +4.15 pp | ~34.2% | 12.6% |

\* K1/K2 都撞到 600 的模板上限 → 它们的增量是**下界**（模板更多时可能更高）。

### 1.3 结论（实测）

1. **答案是可以**：ORD 自抽的正向模板能把 test 覆盖率从 **30.0% 顶到 ~34.9%（支持≥5，保守）** 或
   **~39.6%（支持≥1，宽松）**。相对提升 +16% ~ +32%。
2. **代价是宽松度**：支持≥1 的版本会在 **33.8%** 的无关反应上"也吐产物"；
   支持≥5 的版本降到 **7.8%**。考虑到 HTE 已经证明现有库假阳性 94.9%，
   **推荐用支持≥5 的保守版**（91 个模板，+4.88 pp）。
3. **上一轮 pilot 的结论（+0.4%）被推翻**，原因在口径：
   旧 pilot 只对"**零覆盖反应中心**"抽模板、且要求**支持≥2**，
   等于自己把可用的模板绝大多数先筛掉了；本轮改成"**所有基准漏项**"抽 +
   按支持数分档，才看到真实增量（这正是"口径没定死 = 要重测"的又一例）。
4. 模板已落盘供下一轮接入：`reports/mined_forward_templates.jsonl`
   （字段 template / generalized / support）。

### 1.4 还没做的（诚实标注）

- 新模板**尚未接进引擎**，也**没在 HTE 反例上测过**它会不会把 94.9% 的假阳性推得更高 ——
  这是接入前必须做的一步（下一轮第一件事）。
- "过大分子跳过 1,593 条"意味着对天然产物尺寸的反应，本轮的模板挖掘是**缺位**的
  （而天然产物恰好是中药场景最关心的）。

## 二、② ORD 之外的反例数据：HTE 真实失败条件

### 2.1 数据来源与获取（实测可下载）

| 项 | 值 |
|---|---|
| 来源 | Zenodo **19635488** `schwallergroup/bh-hte-ood`（"Robust OOD Prediction of Buchwald–Hartwig Reactions"） |
| 许可 | **Apache-2.0**；包 1.84 MB，主表 40.4 MB |
| 主表 | `data/BH_HTE_Curated_Dataset_v20260219.csv`：**27,497 行 × 44 列** |
| 字段 | Aryl SMILES / Amine SMILES / Catalyst Name+SMILES / Base SMILES / Solvent Name+SMILES / **Yield** / Product SMILES / manuscript 的二分 `labels` |
| 本地位置 | `chemreact-staging/data/external/bh-hte-ood/…`（只读用；脚本 `tools/hte_negatives.py`） |
| 备份线索 | Zenodo 17634928（466 MB 聚类版）、19636649（1.34 GB 版） |

**为什么它比 ORD 强**：ORD 243 万条全是"做过的正例"；这张表 **38.9% 的行 Yield == 0**（HTE 实测没检出产物），
且**同一底物对不同条件既有 0 也有 >0** —— 这正是 ORD 完全没有的**条件级反例**。

### 2.2 反例集规模（实测）

| 口径 | 条数 |
|---|---|
| `NEG_COND` 条件级反例（行 Yield == 0） | **10,696**（写完 `reports/hte_negatives.jsonl`） |
| `NEG_SUB` 底物级反例（该底物对所有行全 0） | **1,993** 个底物对（共 5,752 对） |
| `POS_CTRL` 正对照（有对比的底物对里 Yield > 0） | **2,500** 条（取前 2,500） |
| 按来源的 0 收率比例 | HiTEA 2024 **60%**、Dreher 2014 58%、Dreher 2016 53%、JNJ 45%、Merck 43%、Roche 38%、AZ ELN 19%、Dreher Doyle 2018 6% |

### 2.3 ★ 引擎首次实测（这是本轮的核心数字）★

口径：把 (Aryl, Amine) 喂 `ReactionEnumerator.enumerate_pair`，
看能否产出记录的目标产物。**注意这是"不带条件"的模板库声称率**——正是要暴露的问题。

| 指标 | 值 | 含义 |
|---|---|---|
| **假阳性率**（1,993 个实测全 0 底物对上声称能发生） | **1,891 / 1,993 = 94.9%** | 引擎声称 95% 的"实测不反应"底物对会反应 |
| 引擎活性（产出任何产物） | 99.4% | 上面那个 95% 不是"没规则可用"造成的（对照成立） |
| **召回**（正对照上复现目标产物） | **1,599 / 2,500 = 64.0%** | 成功案例能复现 64% |
| **条件门控 AUC**（459 个同底物、不同条件的对比，353,509 次比较） | **0.530** | 0.5 = 毫无判别力；67.5% 的比较直接平局 |
| 负例上真正贡献反应类 | `B-H`（= Buchwald–Hartwig；`templates.txt` 里 categories 写着 X-Bromide + Amine） | 所以不是"瞎猜的杂类"，就是这个反应的模板过于宽松 |

**顺带纠正一处历史标注**：仓库里 `tools/diag_ord_promiscuity.py` 的注释写着
「命中榜第一是 B-H（**硼烷**），化学上可疑」——**B-H 不是硼烷，是 Buchwald–Hartwig**
（本轮实测：它的模板 categories 是 `X-Bromide_Phe` + `Amine_AcyclicSecondary…`）。
当时"可疑"这个直觉是对的，但**直到本轮拿到 HTE 反例，才第一次把它量化成 94.9% 假阳性**。

**结论（实测）**：
1. **反例数据问题解决了**（ORD 之外有 1 万条量级的真实失败条件，可下载、有许可）。
2. **但引擎答不对**：模板库只看官能团（芳卤 + 胺 → 芳胺），不看这个底物/配体/碱组合是否真的reacted；
   条件门控又几乎无判别力（AUC 0.53）。→ 这就是用户最初要的「判断反应会不会发生」的缺口，现在**有了尺子**。
3. 口径诚实性说明：HTE 表**没有温度列**，条件门控里温度统一用该类 ORD 中位数（B-H: 100 °C）；
   溶剂/碱来自表内字段。这是已知局限，不是隐藏假设。

### 2.4 ★ 稳健性检查（防止拿"弱反例"当证据）★

担心：某底物对"全 0"可能只是**只测了 1 个条件**。实测（`tools/probe_hte_neg_robustness.py`）：

| 全 0 底物对的测量充分度 | 对数 |
|---|---|
| 只测了 **1** 个条件 | **1,862** |
| ≥3 个条件 | 117 |
| ≥5 个条件 | **58** |
| ≥10 个条件 | 25 |

→ 所以 1,993 这个数字里**绝大多数是弱反例**，不该当主口径。
改用**测得充分的子集**（≥5 条件，58 对）重测：

| 子集 | 引擎声称能发生 | 活性 |
|---|---|---|
| 全部 1,993 对（多数只测 1 条件） | 1,891 = **94.9%** | 99.4% |
| **≥5 条件的 58 对（强反例）** | **54 = 93.1%** | 94.8% |

**结论不变**：即使只用"测了 5 个以上条件、全部 0 收率"的强反例，引擎仍然 93% 声称能发生。
→ 假阳性不是弱反例造成的，是**引擎本身没有条件意识**。
（另一个局限：表里每个底物对都只来自 1 个来源；跨来源的底物对为 0。）

### 2.5 反例来源的**完整调研**（覆盖目标里点名的三类来源）

见独立文档 `reports/第十四轮-反例数据源调研.md`（含 URL / 许可 / 大小 / **本环境可达性实测**）。
要点：

| 来源类型 | 实测结果 |
|---|---|
| HTE 实验失败条件 | ✅ 已下载并落地（10,696 条 0 收率） |
| **合成选择性负例**（RegioSQM20） | ✅ 已下载；535 底物 → **≈2,079 条合成负例**（换位点口径，测**选择性**不是活性） |
| 合成负例两种配方（negative_learning 代码） | ✅ 已下载代码；配方 = 换位点 / beam-search 前 3 预测 vs 真值 |
| **专利"比较例"** | ❌ **卡在入口**：figshare **403**、Google Patents 超时、PatentsView 返回 HTML；**未解决，不写成已完成** |
| HuggingFace | ❌ 本环境连接超时（环境限制） |
| ORD（手上） | ❌ 已耗尽（177 万条 → 17 条严格反例） |

**口径纪律**：三类负例**不能混用** —— 实验失败测**活性/条件**；换位点测**选择性**；
beam-search 合成负例只能做内部一致性。混用会把两个指标搅成一个说不清的数。

- **不接的理由**：HTE 的 94.9% 假阳性说明现在的输出是"结构上可能、实验上不发生"的候选清单。

- **要接就先接成开关（默认关）**，并把三个可信度数字随输出落盘。
- 演示里 40 个成分炸出 3,444 个产物（旧版 10 条规则下是几十个量级），TCMAI 侧的排序/限额必须重做。
