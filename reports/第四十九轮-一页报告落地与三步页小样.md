## 五b、药材"每味取 N 个成分"调查（用户提问，全部实测）

* **口径**（`sources/herb.py`）：SQL 按 `match_level='marker'` 优先、其次**分子量降序**排；
  Python 侧按结构 SMILES 去重；取满 `limit` 个唯一分子即停。
* **库内规模**：6,297 味药材；每味有效成分数中位 4、p90 33、最大 533（桑叶）。
  甘草 359 行→342 唯一；黄芪 152 行→146 唯一。
* **已知偏差**（实测例）：黄芪 limit=12 → 前 12 全是黄芪皂苷（MW 829~1031），
  **毛蕊异黄酮（calycosin）类小分子 marker 被截在门外**——"分子量降序"系统性偏向大皂苷。
* **隐藏第二闸门**：对子数 C(N,2) 超过 `max_pairs`（默认 4000）时按**名单顺序**截断
  （核心引擎 `smartreact_engine.py` L1092-1096）；名单顺序 = 上面那个 MW 序，
  所以"排后面的成分"会集体失踪。已有 `truncated` 标志（控制台会警告；报告里还没有）。
* **成本曲线（实测；2026-10-15 勘误）**：10-14 旧样例实为 **3 个成分** → 48 产物 / 2.1 s
  （当时库里甘草只解析出 3 个）；10-15 复跑 **12 个 → 552 产物 / 6.7 s**；
  **48 个 → 13,240 产物 / 147 s**（报告 8.6 MB 自动生成成功 = predict→报告全链路顺带验证）。
  产物≈对子数 8~16 倍、对子数=C(N,2)：全库 342 个 = 58,311 对，属小时级（**外推，推断**）。
* **待拍板**：① 无论选哪个档位，报告/台账里写明"取的是谁、共多少、谁没参与"；
  ② 增加"全部成分"档（`--limit all`）；③ 对子截断改**公平口径**（每个成分都摊到名额，
  不再是"前几个全排、后面全没"）；④ "分子量降序"是否换更中性的口径。
