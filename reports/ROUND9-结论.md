## 3. ★ 它立刻抓到一个真回归 —— 而且是我自己的工具造成的 ★

```
[美拉德简化] 副产物可疑: condensation 类反应产出 H2
             ★这是「编一个副产物把原子数凑平」的典型症状★
```

**查证结果：**

| 规则 | 第 1 轮（正确） | 第 6 轮被改成（错误） |
|---|---|---|
| 美拉德简化 | `co={O2:0.5}, by={H2O:1}` | `co={}, by={H2:1}` |
| 化学含义 | 糖的 CH₂OH 被**氧化**成 CHO | 说是**脱氢产氢气** |

**谁改的？** 第 6 轮跑 `derive_co_reagents.py --apply` 时，推导器对 `{H:-2}` 这种差值，
在非 `oxidation` 类别下一律建议「产氢气」，**把人工确认过的正确值覆盖掉了**。

**为什么校验器没拦住？** 因为两种解释**原子数完全一样**：

```
co − by = {O2:0.5} − {H2O:1} = {O:1} − {O:1,H:2} = {H:-2}   ← 氧化解释
co − by = {}       − {H2:1}  = {H:-2}                        ← 脱氢解释
```

**数字一模一样，化学完全不同。**

我还专门写了个脚本对比「加草稿前」与「当前」的备份，确认：

```
原始 24 条规则里配平值被改动的：1 条
其中疑似改错的：1 条
→ 正好就是校验器抓到的那条
```

## 4. 一起修了工具：会改数据的工具必须有「默认不覆盖」

**问题的根源不是推导器算错了，而是 `--apply` 会无条件覆盖。**

推导器给出的是「**最省事的那种配平**」，不等于化学上正确。
盲目覆盖会把人工确认过的值改坏。

**修法**：默认**跳过所有已有配平值的规则**，要覆盖必须显式加 `--overwrite`。

实测生效：

```
已跳过 30 条【已有配平值】的规则（默认不覆盖）
   如需强制覆盖，加 --overwrite（★先想清楚：推导值不一定比现值正确★）
```
