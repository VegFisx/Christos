## 1. ★ 正面修掉了那个最扎眼的问题：产物过滤器误杀

第 0 轮就发现的硬伤，这轮终于有了可运行的替代实现。

### 原做法：**删掉**小分子

```python
if mol.GetNumHeavyAtoms() < min_heavy:   # min_heavy=10
    return False
```

后果：**苯甲酸（9 个重原子）被静默删除**——而它正是乌头碱酯水解减毒的标志性产物。

### 新做法：**保留 + 分类**

```
价态非法            → 丢弃（这才是真正的坏数据）
分子量 < 2          → 丢弃（H+、单原子离子，根本不是分子）
小分子副产物         → 保留，打上 is_byproduct 标记
其余                → 正常产物
```

**「删掉不该删的」比「显示太多」危险得多——前者会静默改变结论。**

### 实测验收

| 分子 | 重原子 | 分子量 | 新实现 | 原代码 |
|---|---|---|---|---|
| 水 | 1 | 18 | 保留（副产物） | ★丢弃★ |
| 甲醇 | 2 | 32 | 保留（副产物） | ★丢弃★ |
| 二氧化碳 | 3 | 44 | 保留（副产物） | ★丢弃★ |
| 甲酸 | 3 | 46 | 保留 | ★丢弃★ |
| 乙酸 | 4 | 60 | 保留 | ★丢弃★ |
| 苯酚 | 7 | 94 | 保留 | ★丢弃★ |
| **苯甲酸** | **9** | **122** | **保留** | **★丢弃★** |
| 苯甲酸甲酯 | 10 | 136 | 保留 | 保留 |

**端到端确认真能产出苯甲酸**（不只是过滤器单测）：


### 级联的设计要点

1. ★ **每轮重新计算条件激活**（原 `cascade_reactions.py` 是开头算一次就固定）
2. ★ **只迭代不可逆反应**（这条原实现是对的，保留）
3. ★ **副产物不进前沿**——但**不从结果里删掉**，它们仍在产物表中
4. ★ **轮数衰减**：第 2 轮起置信度乘 0.85。离原始成分越远，推断链条越长，不确定性越大
5. **收敛判据**：一轮下来新的不可逆产物少于 `min_new` 就停

## 3. 端到端实测：19 / 19 全部通过

真实场景：附子（40 个成分，marker 优先）× 三种工艺 × 2 轮级联。

### 条件层的两种作用要分清（这是我第一版测试写错的地方）

一开始我断言"酸水解与煎煮产物集合不同"，结果**差 0 个**，测试红了。
查下来不是 bug，是**我的断言错了**：

- **硬门槛（气氛）→ 改变产物【集合】**
- **软打分（温度/pH/溶剂）→ 改变产物【排序】**

这个分工是设计使然，两者不该混为一谈。改成分别验证后全绿：

| 验证 | 结果 |
|---|---|
| **集合差异**：煎煮 345 个 vs 无氧煎煮 212 个 | 有氧独有 157 个 ✓ |
| **排序差异**：煎煮 Top5 与 酸水解 Top5 顺序不同 | ✓ |
| **阈值差异**：激活阈值 0.15 → 345 个，0.35 → 234 个 | ✓ |
| **级联收敛**：能停在有限轮内 | ✓ |
| **来源追溯**：产物带全字段 | ✓ |
| **五因子评分**：明细完整 | ✓ |

### 最有说服力的一个结果

```
【酸水解】pH 1.5 / 100°C / 120min / 加酸
  Top 5 全部是酯水解产物：
    0.910  C18H32O2  酯水解 ← Lipoaconitine
    0.910  C7H6O2    酯水解 ← Lipoaconitine    ← 苯甲酸
    0.910  C2H4O2    酯水解 ← Pseudaconitine   ← 乙酸

【煎煮】pH 6.5 / 100°C / 60min
  Top 5 是氧化/脱水类
```

**「换个工艺，产物排序就变了」——这才是这个项目真正的卖点，现在它是真的了。**

## 4. 踩过的两个坑（都记在代码注释里）

**坑一：SMILES 字符串比较会误判。**
测试里我写 `p.smiles == "OC(=O)c1ccccc1"` 判苯甲酸，结果**始终判为不存在**。
原因：RDKit/rdchiral 会规范化成 `O=C(O)c1ccccc1`。
必须用 `Chem.MolToSmiles()` 规范化后再比。**差点因此误报"引擎没产出苯甲酸"。**

**坑二：SQLite 的 `UNION ... ORDER BY` 不能按结果集外的列排序。**
`sources/herb.py` 第一版写了 `SELECT herb_id ... UNION ... ORDER BY LENGTH(herb_id)`，
被 SQLite 拒绝（UNION 结果集只有 herb_id 一列）。改成先精确匹配、取不到再模糊匹配。
