## 0. 一句话

只学「原子全部带映射号」的那 3% 反应，做出 40,000 条数据集；模型从底物结构逐键构造产物，
**产物完全命中 27.9%**，同批反应上模板引擎 top-1 只有 3.4%（recall 50.8%）。

---

## 1. 为什么只取 3%

键编辑能表达的只有「已有原子之间键的变化」。上一轮实测：5,000 条 ORD 反应里 **95% 有未映射原子**，
产物里凭空多出离去基团、试剂残基、盐——这些用改键造不出来，所以全量口径的上界只有 3.0%，
而那 3.0% 恰好等于「全映射反应」的占比（4.8%）。分层验证后确认：

| 子集 | 条数 | 施加器还原率（给真实编辑） |
|---|---|---|
| 全映射 | 239 | **61.9%** |
| 全量 | 5,000 | 3.0% |

因此本轮把任务重新定义成：**只覆盖全映射反应**，指标硬、可自证。

全量扫描估计：前 6 片 33,392 条里全映射 1,113 条 = **3.33%**；扫 286 片、取到 40,000 条
（跳过了 1,312,588 条非全映射）。

## 2. 数据

`tools/build_center_dataset.py`（新增 `CENTER_ALL_MAPPED=1`、`CENTER_OUT`）

- 输入：`reports/ord_shards_full/shard_*.jsonl`（286 片，带映射）
- 输出：`reports/center_dataset_mapped.jsonl` — **40,000 条反应 / 794,000 个候选对**
- 候选对 = 同分子图距离 ≤3 的原子对 + 跨分子全部对（上限 300）
- 标签：0 不变 / 1 成键 / 2 断键 / 3 升键 / 4 降键

- 负样本比 8:1

**施加器** `core/center_apply.py`：按映射号改键 → 只调被改过原子的显式氢（价态守恒）→
价态超限时用形式电荷吸收（电荷 +1 允许价态 +1）→ sanitize → 按碎片规范排序。

上界（喂**真实编辑**）：3,000 条抽样 **70.0%**。按编辑数分层：

| 编辑数 | 占比 | 上界 |
|---|---|---|
| 1 | 25% | 78.2% |
| 2 | 57% | 75.1% |
| 4 | 16% | 51.5% |
| ≥5 | 4% | 26–48% |

剩下的 30%：结构不同（23%，疑立体或碎片顺序）、sanitize 失败（7%）。

## 3. 模型与结果

`tools/train_center_model.py`（HistGBM 五分类；10,139 训练 / 9,861 测试，按 rid 哈希切分）

逐对（测试集）：

| 类别 | 精确率 | 召回 | 真值条数 |
|---|---|---|---|
| 不变 | 99.7% | 89.6% | 175,144 |
| 成键 | 53.2% | 96.1% | 7,060 |
| 断键 | 69.4% | 96.5% | 2,923 |
| 升键 | 36.8% | 93.2% | 2,807 |
| 降键 | 57.5% | 97.6% | 9,369 |

按反应：

| 指标 | 数值 |
|---|---|
| 反应中心完全命中 | **2,340/9,861 = 23.7%** |
| 产物完全命中 | **2,754/9,861 = 27.9%** |
| 施加失败（预测编辑产生非法结构） | 3,659/9,861 = **37.1%** |
| 上界（真实编辑） | 6,969/9,861 = **70.7%** |

> 产物命中略高于中心命中：有时键级变化算错但落点相同，产物仍对。

修过的一个真 bug：`to_order` 原先把「升键」一律当 1→2，把 2→3 也压成 2，
目标键级错；现在按反应物里该键的现有键级推一步。

## 4. 对照基线（同 500 条测试反应）

`tools/bench_center_vs_template.py`：

| 路线 | 指标 | 数值 |
|---|---|---|
| 模板引擎（默认池） | recall / top-1 / 集合恰好相等 | 50.8% / **3.4%** / 0.4% |
| 模板引擎（curated + 重排序） | recall / top-1 | 51.0% / **1.6%** |
| 学习型中心模型 | 产物完全命中（单分子输出） | **27.9%** |

读法（三条都要说清，否则数字会误导）：

1. 模板路线的强项是 recall（51%），但它给的是**列表**，真产物排第一只有 3.4%——位次中位数是 6、p90 是 12。
2. 学习型路线输出**一个**分子，27.9% 是「一次就对」。
3. 两者可组合：模板给候选集合，学习型给其中一个高置信解；本轮没做组合。

另：这批 ORD 反应的模板召回（51%）明显低于 USPTO 基准（92%），因为 ORD 反应更杂、
多步/多组分更多，且这里用的是「煎煮」条件而非专利条件。

## 5. 瓶颈与下一步

1. **37.1% 的预测编辑价态非法**（最便宜的一块）：按「每个原子剩余价态容量」排除非法编辑。
2. **上界 70.7%**：施加器的 23% 结构不同需要定位（立体？碎片顺序？）。
3. **联合精度**：逐对精确率 37–69%，但一条反应要所有编辑都对才算对。
4. **覆盖**：只覆盖 ORD 的 3%，其余 95% 需要别的机制（追加片段/序列生成）。

## 7. 约束解码（本轮补做）

做法：预测前先算每个映射原子还剩多少价态容量 cap = max_valence(元素, 电荷) - 当前价态，
然后按置信度从高到低接受编辑，任何一步会让某个原子的价态超过 cap 就跳过该编辑。

| 指标 | 直接 argmax | 约束解码 |
|---|---|---|
| 反应中心完全命中 | 23.7% | **35.0%** |
| 产物完全命中 | 27.9% | **32.1%** |
| 施加失败（非法结构） | 37.1% | **25.7%** |

产物命中 +4.2 pp，中心命中 +11.3 pp，非法结构从 37.1% 降到 25.7%。

剩下的 25.7% 不是价态超限，而是更隐蔽的失败（芳香体系重建、电荷位置错误），
需要更细的合法性判据，本轮没做。

## 8. 并联实验：模板候选 ∪ 学习型单解（判据先写死再跑）

判据（跑之前写在 	ools/bench_center_union.py 的 docstring 里）：
学习型命中的部分落在模板候选集合内的比例 < 70% → 互补，并联有意义；≥ 90% → 只能当排序器。

样本：同 500 条测试反应（前 20,000 条内 rid 哈希奇数半区）。

| 项 | 数值 |
|---|---|
| 模板命中 | 254/500 = 50.8% |
| 学习型命中（约束解码） | 145/500 = **29.0%**（输出结构合法 352/500 = 70.4%） |
| 两者都命中 | 97/500 = 19.4% |
| 只有学习型命中 | 48/500 = **9.6%** |
| **合并覆盖** | 302/500 = **60.4%** |
| 学习型命中落在模板候选内的比例 | **66.9%** |

结论：66.9% < 70%，**判据 A 成立——两条路互补**。合并覆盖 50.8% → 60.4%（+9.6 pp），
这 9.6 个点是模板路线根本到不了的（那些反应在模板池里没有可用模板）。

另一方面，三分之二的学习型命中仍落在模板候选里——说明它同时也**有排序价值**：
对模板已经覆盖的反应，学习型可以给候选打一个「结构上可构造」的信号。

两条路的分工因此清楚了：
- 模板负责**覆盖**（语料里出现过的转化，加新规则就能扩）
- 学习型负责**两件事**：① 补 9.6% 的盲区 ② 给已有候选排序

## 9. 学习型模型当排序器：top-1 3.4% → 20.0%

第一版（	ools/bench_learned_ranker.py）走「反查子结构匹配」，失败：真实产物只有 67% 能
匹配上底物查询，打分建立在错误对应上，top-1 掉到 0%。**这条路废弃，留作失败记录。**

第二版（	ools/bench_learned_ranker2.py）换前提：**不反查**。引擎发射产物时已经把命中的
模板 SMARTS 记进 Product.template_smarts（第 89 轮加的）。模板 SMARTS 本身就写明左侧哪些键、
右侧哪些键；把左侧拿去和底物做标准子结构匹配（模板左侧是具体 SMARTS，匹配可靠），
就能把模板的映射号翻译成底物原子下标，得到这一步的真实编辑集，再送进中心模型打分。

结果（同一批测试反应，默认池，条件「煎煮」）：

| 样本 | recall | 发射序 top-1 | 旧重排序器 | **学习型打分 top-1** |
|---|---|---|---|---|
| 150 条 | 41.3% | 3.4% | 1.6% | **23.3%** |
| 500 条 | 50.8% | 3.4% | 1.6% | **20.0%** |

在「真产物出现在候选里」的子集内，500 条上是 100/254 = **39.4% 排第一**。

这就是学习型模型的正确用法：**它不是替代模板，是给模板的候选打分**。
模板负责把答案放进候选池（50.8%），中心模型负责把对的那个顶上来（3.4% → 20.0%）。
