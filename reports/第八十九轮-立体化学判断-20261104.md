## 2. 这一轮做了什么

### 2.1 用现在的 70 条规则重跑旧体检

```
python -I rules/stereo.py --limit 800 --report reports/stereo_report_20261104.md
```

结果：70 条规则 / 800 底物（带手性 443）。

> 结论：规则层面是干净的。旧结论在新规则集上依然成立。

### 2.2 新写「逐跳立体判断」：对真实产物问同一个问题

新脚本 `tools/judge_stereo_hops.py`：读一次运行的台账，逐跳判断——

```
旁观手性中心 = 底物的指定手性中心 − 落在规则作用范围内的那些
保住 = 产物（主产物 + co_products 各片段）的指定手性中心数 ≥ 旁观数
```

五档：`保住` / `部分丢失` / `整层丢失` / `底物无手性` / `无法判断`。

**踩的坑（重要）**：第一版只数主产物那一行的手性中心，结果 24 条被判「部分丢失」。
原因和 `rules/stereo.py` 头部写的一样——水解/断裂类反应把分子拆成两片，
主产物行只是一片，另一片在 `co_products` 里。把 `co_products` 一起数之后，误报全部消失。

### 2.3 实测：开不开立体开关，差一整层

同一个任务（甘草 limit 6、单轮），只改 `CHEMCREACT_STEREO_CANON`：

|---|---|---|

也就是说：**默认配置下，凡是可判的产物，立体信息 100% 丢光**；
打开开关后，可判的全部保住。

### 2.4 47% 的跳「无法判断」是什么

`无法判断` 384 条，逐条查原因（`_diag/diag_stereo_unknown.py`）：

| 规则名 | 条数 | 原因 |
|---|---|---|
| `esterification` / `mitsunobu` / `mined_*` | 384 | 这些是 9,770 条 mined 模板，**台账只记类别名，不记具体模板 SMARTS**，没法反查作用范围 |

这不是判断逻辑的缺陷，是**台账信息不足**。要补的话，得让引擎记住用过哪条 mined 模板（写入台账一列），
属于引擎侧改动，这一轮没动。

### 7.1 那 3 条「整层丢立体」的真相：不是立体问题，是模板删原子

`mined_top_055 / mined_top_002 / mined_top_005` 三条，判据报「底物 8 个手性中心 → 产物 0 个」。
顺着 `template_smarts` 查下去，结论和立体无关：

```
mined_top_055  SMARTS: O-[C;H0;D3;+0:1](-[C:2])=[O;H0;D1:3]>>[C:2]-[CH2;D2;+0:1]-[OH;D1:3]
  底物 C36H38O16  →  产物 C10H12O3        （element_delta = -26 | -26 | -13）
```

直接拿这条 SMARTS 在 RDKit 上跑那个底物，`RunReactants` 只返回 **1 个分子**（就是那个 C10H12O3 断片），
因为模板的产物侧只写了小片段，**其余 26 个碳、13 个氧被直接删掉**。
同一底物 + 同一规则在台账里也只有 1 行，说明另一半没有以任何形式（主产物/伴生产物）落档。

这类模板是 ORD 里「只记了主产物」的 mined 模板，套到比原始反应大得多的天然产物上就会「吃掉」分子。
所以这 3 条**不是引擎丢立体**，是**模板保真度**问题：

- 判据本身没错（它如实报告「产物里没有这些手性中心」）；
- 但归因要写成「mined 模板删原子」，不能写成「立体丢失」。

**待办**：给这种跳加一个可观测标记（比如产物相对底物的原子保留率 < 70% 就标 `原子丢失`），
先只观测、不拦，等全量基准跑完再一起评估。这条没写进任何交付数字。
