# 第一百三十轮：炮制目标结构补录（S0 + S1）

2026-11-07 · 本轮只动验证层与证据字段，不动引擎规则

## 一句话

六个炮制案例里原先只能比分子式的三个，现在一个升到骨架级、两个仍缺目标结构；同时查清了一件更要紧的事：**炮制对照一直读的是没有立体的 `smiles` 列**，而生产路径本来就优先 `isomeric_smiles`——错在验证工具，不在引擎，也不在模板。

## 一、做了什么

### S1 目标结构从 PubChem 补录

新增 `tools/fetch_target_structures.py` → `data/target_structures.json`。每个条目带 `cid` / `title` / `formula` / `smiles` / `inchikey` / `skeleton_prefix` / `url` / `fetched_at`，公式与库内记录冲突则不收录。

- 收录：苍术苷酸（atractylosidic acid，CID 442005，C30H46O16S2，`FYQXODZRNSCOTR-QLKRWLHJSA-N`）。
- 未收录：THSG 苷元、JNB 开环酸——PubChem 没有对应名录条目（`2,3,5,4'-tetrahydroxystilbene` 查到的是 oxyresveratrol，`Jolkinolide B` 只有 C20H26O4 本身）。原因写进 `unavailable` 字段，不拿近似结构顶替。

`tools/validate_paozhi_paths.py` 的 `match_target` 新增 `"pubchem"` 分支：**先比全键（含立体），再退到骨架前 14 位**，命中深度记在 `match_target.last_level`，状态新增 `skeleton_only`（"骨架一致，立体未区分"）。

### 立体种子

`tools/fetch_seed_structures.py` → `data/seed_structures.json`，按 PubChem 名称取 6 个种子的 isomeric SMILES，公式须与 `tcm.db` 一致才收录（实测 6/6 一致）。

验证工具现在优先用立体种子，并把 `seed_smiles_source` 写进结果（`pubchem:isomeric` 或 `tcm.db:flat`）。

### S0 证据分级

`rules/paozhi_evidence.json` 里有两条中文期刊来源没有 DOI（这两刊 DOI 注册滞后）。不编 DOI，改为显式声明：

| 字段 | 值 |
|---|---|
| `doi` | `null` |
| `identifier` | 期刊 年, 卷(期): 页 |
| `access` | 取到的是摘要页还是全文 |
| `evidence_level` | `secondary` |

规则级 `evidence_level` 取所有来源里最强的一个：`demethylation_n_001` 只有这一条来源 → `secondary`；`decarboxylation_001` 另有一条 1973 年 FEBS Letters（DOI 已核验）→ 仍 `primary`。

## 三、两个查清的根因

### 1. 问题出在验证工具读了哪一列（生产路径本来是对的）

`compounds` 表同时有两列结构：`smiles`（无立体，31,646 行全部没有 `@`）和 `isomeric_smiles`（30,964 行非空，其中 19,043 行带 `@`）。用 InChIKey 复核，`isomeric_smiles` 算出来的键与 `inchi_key` 列**逐字相同**。

```
HBIN000001  isomeric -> HZLWUYJLOIAQFC-SMRQUVCNSA-N   inchi_key -> HZLWUYJLOIAQFC-SMRQUVCNSA-N   match
HBIN000002  isomeric -> RHWSKVCZXBAWLZ-OCAPTIKFSA-N   inchi_key -> RHWSKVCZXBAWLZ-OCAPTIKFSA-N   match
HBIN000008  isomeric -> CIIYOYPOMGIECX-HZSPNIEDSA-N   inchi_key -> CIIYOYPOMGIECX-HZSPNIEDSA-N   match
HBIN000009  isomeric -> GYBZIPUTSFKFHR-NSHDSACASA-N   inchi_key -> GYBZIPUTSFKFHR-NSHDSACASA-N   match
```

- 生产路径 `sources/herb.py:211-222` **一直优先用 `isomeric_smiles`**（拿不到才退回 `smiles`），`core/query_base.py:1095` 也是 `COALESCE(isomeric_smiles, smiles)`。
- 错的是 `tools/validate_paozhi_paths.py` 的 `db_row()`：它直接 `SELECT smiles`，绕过了生产路径的取列逻辑，所以炮制对照一直是拿平面结构在比。已改为与生产一致的取列方式，并在结果里记 `seed_smiles_source`。

结论修正：不是"生产输入没有立体"，是**验证工具读错了列**。这一条比补录本身更要紧——之前所有"只到分子式级"的判断都建立在这个错误上。

### 2. CATR 脱羧产物差在哪一个中心

换成立体种子后，脱羧产物键是 `FYQXODZRNSCOTR-UPWBHRCRSA-N`，目标是 `FYQXODZRNSCOTR-QLKRWLHJSA-N`：骨架相同、立体层不同。

```
PubChem 苍术苷酸：13 个手性中心，13 个已定义
我们的产物：      13 个手性中心，12 个已定义，未定义的是原子 37
```

原子 37 就是脱羧那一步新得的碳：丙二酸型碳上原来两个羧基相同、不算手性中心，脱掉一个换成氢之后才成为手性中心，而"从哪一面加氢"模板给不出。所以产物是**骨架正确、12/13 个中心正确、新中心未定**——和论文里两个乌头碱案例是同一类现象。

## 四、没解决的

- `Jolkinolide B` 开环酸、`THSG` 苷元在 PubChem 无名录条目 → 仍只能分子式级。要升级得找到带结构的文献或权威库条目。
- `isomeric_smiles` 只覆盖 30,964/31,646 行（19,043 行真正带手性）；剩下 682 行没有这一列，仍退回平面 `smiles`。哪些成分属于这 682 行、是否影响结论，还没查。
- 碳化 / 异构化 / 缩合这三类炮制变化没有可映射的结构对，规则仍写不出来。
