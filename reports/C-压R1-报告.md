# C：压 R1 残基路线（把可用率推过 50%）—— 报告（2026-10-11 第九轮）

> **可用率 41% → 44%；路线层面可用 45.1% → 51.4%（过半）。**
> R1 残基路线命中从 164 降到 137。

---

## 一、R1 是什么、为什么难压

R1「残基路线」= 前体与目标的**最大公共子结构 ≥ 目标重原子的 80%**，
也就是「把目标换个基团再变回来」。它是**假路线的最大头**。

前一轮（B）已经在**递归阶段**避开了它们：不去拆残基型前体。
但它仍然会在**一步到位**时成路——
把目标换个基团 + 一个能买的小分子，两个前体都可买，就凑成了一条「路线」。

---

## 二、做法：一步到位也按「拆得干净」排序

新增 `_residue_frac()`：方案里最大的残基度 = 前体与目标的 MCS / 目标重原子数。
然后**在候选里**按残基度升序排——拆得越干净越优先成路。

```
scored.sort(key=lambda x: (not 全部可得, -可得前体数))
-> 再对前 mcs_topk 个候选按 residue_frac 升序重排
```

**性能坑（实测）**：MCS 很贵。第一版对**全部**候选算，
耗时从 417s 涨到 **647s（+55%）**。
改成只对前 **40 个**候选算之后回落到 **526s（+26%）**，可用率完全不变。

---

## 三、实测（100 个 ORD 产物，depth3 beam4 max_routes3）

| 指标 | 基线 | B 之后 | C 之后 |
|---|---|---|---|
| 形式成功率 | 45.0% | 82.0% | 80.0%（-2pt） |
| **化学可用率** | 26.0% | 41.0% | **44.0%** |
| 用户看到的第一条就可用 | 26.0% | 41.0% | **44.0%** |
| **路线层面可用** | 39.2% | 45.1% | **51.4%** |
| R1 残基路线命中 | 87 | 164 | **137** |
| 耗时（100 目标） | 302s | 417s | 526s |

**读法**：
- 形式成功率掉了 2 个点（80% vs 82%）——用 2 个点的「找得到」换了 3 个点的「可用」，划算；
- **路线层面过 50%**：给出的路线里，一半以上化学上站得住；
- 第一轮把 R1 从 87 打到 164 是因为**找到了更多路线**（分母变大），
  C 轮把绝对数从 164 压到 137，说明排序确实在起作用。

## 四、C 轮之后的完整口径

### 判据（单一来源：`retro_search.step_usability`）

| 规则 | 含义 |
|---|---|
| R1 残基路线 | 前体与目标 MCS ≥ 目标重原子 80% |
| R2 前体更大 | 前体重原子数 > 目标（已在 B-1 从源头过滤） |
| R3 惰性小分子 | 目标 >15 重原子且前体 ≤2 重原子（已在 S5 过滤） |
| R4 荒谬前体 | CO2/碳酸(氢)根/甲酸/单质小分子当大目标的骨架来源 |

### 三层防线

1. **切断阶段**：丢前体比目标大的方案（B-1）、丢含试剂元素/惰性小分子的方案（S3/S5）；
2. **递归阶段**：不拆残基型前体（B-2）；
3. **排序阶段**：残基度高的排后面（C-1）、可用路线永远排第一。

### 当前能力（诚实版）

给一个分子：
- **80% 的情况能给出至少一条形式完整的路线**；
- **44% 的情况至少有一条化学上站得住的路线**；
- **你看到的第一条就是可用的**（44% 的情况下，排序保证）；
- 每条路线都带 `usable` 标记和不可用原因。

## 五、还欠着的

1. **耗时代价 +26%**：526s/100 目标 = 平均 5.3s/分子。
   交互场景可接受，但要更快的话可以把 `mcs_topk` 从 40 降到 20 试试；
2. **R1 仍是最大头（137 次）**：说明「换基团」是模板库与生俱来的倾向，
   靠排序压不完。要根治得改模板抽取（把只保留骨架不变的那类模板标出来）；
3. **正向的「反应能不能发生」仍然 0 进展**；
4. **接 TCMAI 未做**。
