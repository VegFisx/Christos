# 待办 2 · 手写反应规则的「来源体检」（用户 2026-10-17 拍板方向，暂不实现）

> 背景：用户指出 **DSH 之前手写反应规则，导致初版论文在导师那吃了大亏**。
> 本轮查实：`rules/rules.json` 共 **64 条**（58 启用 + 6 停用），其中
> **论文 TableS1 22 条（11 原样 + 11 修正）**、**自写 42 条（SMARTS 无外部出处）**；
> 而 `rules.json` **没有 `source` 字段**（0 条带出处）。条件档（煎煮/水提/…）也全是手写，无实验校准。

## 目标

把「手写规则」从**暗处**搬到**明处**：每条规则要么有实证、要么明说没有并默认关；
**论文主结果只依赖可溯源数据**（mined 模板，100% 挂 ORD reaction_id）。

## 四步（按成本从低到高）

1. **ORD 实证体检**（最便宜、最该先做）
   * 对每条规则的 SMARTS，去 **ORD 1.77M 条真实反应**里找实例：出现过吗？多少次？什么条件？
   * 产出 `data/rules_provenance.json` + `reports/第七十五轮-规则来源体检.md`（**64 行表**：
     规则 id / 名称 / SMARTS / ORD 命中数 / 示例 reaction_id / 条件样例 / 判定）。
   * 判定三档：**有实例** / **无实例** / **无法判定**（SMARTS 太宽匹配爆炸时单列）。
2. **分档 + 开关**：新增 `--rules-source mined|all`；无实证规则标 `unverified`。
   *★ 默认值要用户拍板*：改成 `mined` 会改变现有行为（项目规矩：新开关默认关）。
3. **条件档证据化**：用 ORD 的 `conditions`（温度/溶剂/催化剂）统计每类反应的真实分布，
   把 `conditions/templates.py` 的手写温区换成**数据分位数**；保留「无数据放行」标注。
4. **论文写法**：方法学明写「主结果只依赖 mined 模板」；手写规则作为**可选层、默认关**，
   补充材料附 64 行体检表。

## 第一步的脚本设计（待写）

```
tools\audit_rules_against_ord.py
  输入：rules\rules.json、ORD parquet（只读）
  做法：把每条 SMARTS 当**反应模板**，在 ORD 反应的**反应物侧**做 RunReactants 匹配
        （先取 6 万条做冒烟，确认命中率与耗时，再全量 1.77M）
  输出：data\rules_provenance.json + 64 行 Markdown 表
  纪律：失败逐条计数并打印；匹配爆炸（>10 万）的规则单独标「太宽」
```

## 风险

* SMARTS 大多写成"产物模板"（rdchiral 习惯），反向套到反应物上可能**天然匹配不到** →
  需要先核对 `reversible`/方向约定，否则会把"格式不对"误判成"无实证"；
* ORD 反应物侧含试剂/催化剂，需要按 `reaction_role` 过滤（用 `role=REACTANT`）；
* 全量匹配耗时未知：先 6 万条冒烟估时，再决定是否分片。
