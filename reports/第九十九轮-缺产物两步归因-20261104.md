# 第 99 轮：缺产物两步归因（是不是我们自己筛掉的 / 模板库里到底有没有）

日期：2026-11-04
口径：3,000 条测试反应里**完全没生成**目标产物的 226 条（7.53%，见第九十八轮）。

## 0. 一句话

两条都不是「化学能力不够」：**0 条被过滤器丢掉**；**42% 的缺产物其实有模板能生成它，只是模板没被装进引擎**（默认装载 14,140 条 mined 模板，完整库 41,619 条）。把装载放宽后，226 条里能救回 **61 条（27%）**。

## 1. ① 是不是被我们自己的过滤器筛掉

给引擎加了零开销诊断钩子（`SmartReactEngine.debug_drops`，默认 `None`；置成 list 后记录每一处丢弃的 `{reason, smiles, rule}`），五类丢弃点：`gate` / `extent` / `cap` / `dedup` / `classify`。

`python -I tools\diag_miss_filters.py`（38 s，226 条 × 两种配置）：

| 去向 | 条数 |
|---|---|
| gate（条件门控判不发生） | **0** |
| extent（进程门，默认关） | **0** |
| cap（每对产物上限） | **0** |
| dedup（结构去重吞掉） | **0** |
| classify（判 keep=False） | **0** |
| **放大 `max_products_per_pair=4096` 后变出来** | **17** |

→ 结论：**没有一条是被门控/去重/分类丢的**。17 条（7.5%）是被「每对产物上限」截断，属于可以调参的空间。

## 2. ② 模板库里到底有没有能做这件事的模板

`python -I tools\diag_miss_templates.py`（165 s）。方法：对每条 miss，先从 46,652 条可解析模板里挑「产物片段 ⊆ 目标产物」的候选（**这个方向不能反**：模板产物侧只写变化片段，未匹配原子由反应物保留），再把这些模板真的套到反应物上（含双底物换向），逐产物比对 canonical SMILES。

| 判定 | 条数 | 占比 |
|---|---|---|
| `template_fires`（库里有模板，离线能生成目标） | **95** | 42.0% |
| `reactant_mismatch`（产物片段对得上，反应侧对不上） | 131 | 58.0% |
| `no_template_at_all` | 0 | 0% |

→ 结论：**没有一条是「库里彻底没有」**。131 条属于模板反应侧写得比实际反应更窄（通用性不够），95 条则是**模板存在但引擎没用上**。

## 3. 那 95 条为什么没用上

先查装载：默认 `extra_template_min_support=10`、`extra_template_limit=20000`，实际装载 **14,140 条**（完整库 41,619 条）；单底物 `mono_template_limit=6000`，实际装载 **1,045 条**。

95 条命中的模板里：support ≤ 10 的 **49 条**（被支持度下限直接排除）、按 support 排序落在前 20,000 条之外的 **80 条**（被条数上限截断）。

放宽实测（226 条，同一批）：

| 配置 | 救回 |
|---|---|
| 默认 | 0 |
| `prefilter=False` | 0 |
| `extra_template_min_support=1, limit=6000` | 7 |
| `extra_template_min_support=1, limit=60000` | **43** |
| 上面 + `mono_template_limit=60000, mono_include_co_reagent=True` | **61** |

双底物换向（`apply_pair(b,a)` 也试一遍）**0 增益** → 不是顺序问题。

## 4. 结论

1. 缺产物的主因是**模板装载截断**（支持度下限 + 条数上限），不是化学规则缺失，也不是我们的过滤器。
2. 装载放宽能把 miss 从 7.53% 压到约 5.5%（226 → 165 条），代价是候选数与耗时上升，**排序质量是否变差还没测**。
3. 剩下 131 条是模板反应侧过窄（SMARTS 写死），属模板质量问题，不是配置问题。
