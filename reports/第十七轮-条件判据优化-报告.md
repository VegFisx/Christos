## 一、阶段A：① 结构特征 + ② 交互项 —— **主口径没有增益**

### 口径（与 `tools/hte_condition_model.py` 逐字一致，为保证可比没动过）
HTE curated 27,497 行 → 评估集 = **有对比的底物对 459 对 / 17,246 行**（成功 10,365 / 失败 6,881）；
`GroupKFold(5)` 按底物对分组；指标 = **同对内 micro / macro AUC**；比较数 ≈ 35~40 万次/格。

### 基线复现（★ 先证明口径没跑偏）
| 复现项 | 本轮实测 | 文档基线 | 结论 |
|---|---|---|---|
| `F0a` = one-hot(催化/碱/溶剂名) + 底物 Morgan，logreg | **0.592** | 0.592 | ✅ 精确复现 |
| `F0b` = one-hot + 底物描述符，hgb，`yield_ge_10` | **0.646** | 0.646 | ✅ 精确复现（→ 文档那个 0.646 就出自这个配置） |

### 特征块 / 特征集定义（已写死在脚本头，且与同轮子任务一致）
`NB`=类名 one-hot · `SUB`=底物 Morgan(512) · `DESC`=底物描述符(6×2) · `SB`=**催化剂/碱/溶剂 Morgan(512)**（① 的核心）·
`QM`=QM 浮点向量(50 维) · `ADD`=8 个 `Additive_*` 列 · `INT`=**显式交互项**（类名 one-hot[k] ⊗ DESC，② 的核心）
`F0a=NB+SUB` · `F0b=NB+DESC` · `F0=NB+SUB+DESC` · `F1=F0+SB` · `F2=F1+QM+ADD` · `F3=F2+INT`

### 六条结论（全部【实测】，除注明外）
1. **主口径 Yield>0 没有增益。** 6 个特征集 × 2 个模型共 12 格，最好 **0.600** —— 就是加满特征之前那个缩放过的基础模型。**加催化剂/配体结构、QM、交互项之后，"最坏/最好"都还在基线附近晃。**
2. **次口径 Yield≥10 有真实增益：0.646 → 0.672（+0.026）**，两个模型方向一致（logreg 0.608→0.624 = +0.016）。
3. **增益来自 `QM`(50 维) + 8 个 `Additive_*` 特征，不是来自催化剂/配体指纹，也不是来自交互项**：F2→F3（加交互项）在 hgb 上是 0.672→0.672，**零变化**。
4. **①里的"催化剂/碱/溶剂 Morgan 指纹"（SB）没有稳定增益**：`yield_ge_10` 上 0.658→0.645（变差），`yield_gt_0` 上 0.554→0.580（变好），方向矛盾 → 判为噪声级，**不采用**。
5. **②交互项唯一亮点是 macro**：`yield_gt_0` logreg macro 0.585→0.606，micro 无变化。
6. **★ 指标层的意外发现（值得下一轮确认）**：hgb 的 **micro 0.554 与 macro 0.650 严重分离**（差 0.10）。
   说明"同对内 micro AUC"被**少数比较数极多的底物对主导**了。换句话说：**现在这个 0.592 可能同时低估了排序能力、又掩盖了真实短板**，
   单看 micro 一个数不足以判断"判据好不好"。
7. 【推断】+0.026 **未做显著性检验**（要做需保存逐行分数重跑，hgb 一轮约 48 分钟）。它可信度中等：两模型、两口径方向一致，且基线被精确复现。

## 二、⑤ 自抽模板绕过条件门控 —— **试了一种修法，实测失败；并查出一个口径 bug**

### 根因（【实测】，上轮已确认）
`cond_table`（37 类）里没有 `mined_extra` → `cond_activation()` 走「无 ORD 条件数据，放行」→ **返回 1.0**。
即：这 590 条模板吐的产物**完全不受温度/溶剂/必需试剂影响**。

### 试过的修法：「非孤儿」规则（**我的建模选择，标【推断】**）
> 语义：自抽模板只用于**丰富一个已被条件门控认可的（底物对, 条件）**，不能凭空创造一个 37 类门控认为不会发生的反应。
> 实现：同一底物对必须至少有一条 37 类结果通过门控，才允许追加 `mined_extra` 产物。
> 开关：`SmartReactEngine(extra_requires_accepted_pair=True)`（**默认 False = 你拍板的 K1 行为不变**）。

### 实测结果（HTE NEG 1,993 对 / POS 2,500 条，`tools/hte_fpr_after_integration.py`）
| 配置 | 假阳性 | 召回 | 负例产物/对 | 其中自抽贡献 | 【孤儿对】(产物全来自自抽) |
|---|---|---|---|---|---|
| baseline（K1 关） | 94.9% | 64.0% | 1.39 | 0.01 | 0.0% |
| mined_K5 | 94.9% | 64.0% | 1.39 | 0.01 | 0.0% |
| **mined_K1（当前默认）** | 94.9% | **69.2%** | **1.87** | 0.50 | 0.1% |
| **mined_K1 + 非孤儿规则** | 94.9% | **64.0%** | 1.73 | 0.36 | 0.0% |

**结论：【实测】这条路是错的。** 非孤儿规则只削掉自抽负例产物 0.50 → 0.36/对（989 → 715 条），
却把召回增益**全丢掉**（69.2% → 64.0%）。原因是 **HTE 负例对本来就 99.4% "活性"**（37 类引擎乱报），
所以"必须有一条 37 类结果通过门控"这个条件在负例上几乎永远成立 → 过滤不了负例；
而 mined_extra 的召回增益恰恰**全部来自 37 类判零的那些对**（【孤儿对】在负例上只有 0.1%，在正例上却是增益来源）。
→ **依赖 37 类门控救不了"绕过门控"这个问题**，必须让自抽模板自己有条件意识。

### ★ 同时查出一个口径 bug（已修）
第十六轮把 `extra_templates_path=None` 的含义改成了「走默认路径（默认开）」，
于是 `hte_fpr_after_integration.py` 里传 `None` 期望"关闭"的 **baseline 配置静默变成了 K5 档**（上面表格里两行数字完全相同就是这个原因）。
**已在 `tools/hte_fpr_after_integration.py` 里显式化**（`use_extra = extra_path is not None`，并显式传 `use_extra_templates`）。
影响评估【实测】：因为 K5 在 HTE 上零变化，**之前报告里引用的 94.9% / 64.0% / 1.38 等数字未受影响**，但标签是错的——已修。

### 两条"路已经断了"的前置发现（避免下次白试）
- 【实测】`mined_forward_templates.jsonl` **只有 3 个字段**（template/generalized/support），**没有反应类型** → 不能按类路由。
- 【实测】ORD parquet 的 `reaction` 列**不是类型名**，是**序列化的 Reaction proto 字节**（177 万条**全唯一**）→ "按 ORD 类型路由"这条路不存在。

### 正确修法（【推断】）→ 已执行，**但独立验证显示数据基础不足**

**做法**：重新挖掘模板时，为每条模板记录它来源 ORD 记录的条件分布（温度分位数 + 溶剂计数），
让门控变成「**这条模板实际在什么条件下被做出来过**」，不依赖类名。产物 `reports/mined_forward_templates_v2.jsonl`。

**★ 我独立验证的结果（`tools/check_v2_template_conditions.py`，不依赖子代理自述）：**

   ★口径是 **per yield measurement**，**不是** per record —— 已核对 `ord_condition_dataset.py:325-347`），
   而 100 < v ≤ 130 有 42,522 个、v > 130 有 27,528 个；**入表条件写死 `0 < v ≤ 100`** →
   入表的 **925,943 行全部是正例**。（附：`fail_yield_out_of_range = 38,430` 是**记录数**，小于三个 band 之和 70,859，
   因为 band 按测量点计数、且一条记录可含多个测量点。）
   → **结论：ORD 不能当"会不会发生"的训练集，也不能靠它补负例来混训**；它只能做 **yield 回归 / 正例标尺 / 覆盖率标尺**。
   要做绝对判据，负例只能来自 HTE（10,696 条实测 0 收率）或专利"比较例"（入口仍未解决）。

### ★ 所以 ④ 改成测「门控的误杀率」—— **结果改写了整个判断**

**做法**：拿 ORD 里**真实做过、有收率**的反应当「真·会发生」的标尺，用它自己记录的温度/溶剂/催化剂跑我们的引擎，
看条件门控会不会把它**判零**。三配置（显式传参，不依赖默认值）：A=纯模板库，B=模板库+门控，C=当前默认。
抽样：duckdb 按【行】reservoir，15000 行 / 覆盖 178/178 片 / seed 固定（`id_hash=5cbb696c0476`）→ **qualified 4,495 条**。

| 子集 | 命中 A / B / C | 命中率 A / B / C | B 判零率 | **★ 误杀率 =(hitA−hitB)/hitA** |
|---|---|---|---|---|
| S_all（n=4495） | 742 / 737 / **942** | 16.51% / 16.40% / **20.96%** | 0.40% | **5/742 = 0.67%** |
| S_temp 有温度（n=932） | 86 / 85 / 130 | 9.23% / 9.12% / 13.95% | 0.64% | 1/86 = 1.16% |
| S_notemp 缺温度（n=3563，缺省 100 ℃） | 656 / 652 / 812 | 18.41% / 18.30% / 22.79% | 0.34% | 4/656 = 0.61% |
| S_ice 0 ℃ 冰浴（n=116） | 9 / 9 / 15 | 7.76% / 7.76% / 12.93% | 0% | 0/9 = 0% |

**三条结论（全部【实测】）：**
1. **★ 门控的误杀率只有 0.67%（5/742），而且不是主要风险源。** 方向对比：**HTE 假阳性 94.9% ↔ ORD 误杀 0.67%** —— 门控"太宽"的问题比"太严"严重两个数量级。
2. **★ 真正的瓶颈是模板覆盖，不是门控**：即使在 A 配置（门控全关）下，**71.3%（3203/4495）的真实文献记录一个产物都枚举不出来**；
   门控只判零了 0.40%。→ **"判断会不会发生"现在最大的漏是"根本没枚举到"，不是"被门控拦掉"。**
3. **配置 C（自抽模板默认开）在真实文献上也是净收益**：命中率 **16.51% → 20.96%（+4.45 pp）**，相对 B **+205 条命中、丢 0 条**，误杀仍是同一批 5 条。
   → 也就是说：**你拍板的 K1 默认开，在两个独立标尺上都是"提召回不增误杀"**（HTE 召回 +5.3 pp，ORD 命中 +4.45 pp）。

**误杀机制（【实测】）**：5 条误杀**全部**是「**容差带边界衰减到恰好 0.0 被 `step()` 当判零**」——`cond_activation()` 在 `[lo−30, hi+30]` 内线性衰减，
到边界正好 `0.0`，而 `step()` 对 `act <= 0.0` 一律丢弃（原因串却写"降权"）。其中 **4 条**更巧：温度缺失 → 实验里代缺省 100 ℃，
恰好 = `mitsunobu` 上限 70 + 容差 30。**敏感性实测**：缺省改 25 ℃ 后误杀降到 **1/742 = 0.13%**（S_notemp 0/656）——
**所以真正由"记录的真实温度"造成的误杀只有 1 条**（esterification 在 −30 ℃ = 下限 0 − 容差 30）。
> 【推断】下一轮可做的小修（**本轮没做，因为收益 ≤0.13% 而已**）：①温度缺失时门控**不判零**（放行），别拿假设温度去比窗口；
> ②衰减留一个下限（如 0.05），让"降权"不再等价于"判零"。

**顺带测到的口径事实（【实测】，下一轮要用）**：
- **64.74%（9711/15000）的 ORD 记录进不了"单一底物对"口径**（碱/硼酸/叠氮被标成 REACTANT 角色）→ 只有 **29.97%** 可用；放开口径是明确的下一步。
- **只有温度能判零**：`cond_activation()` 里 `catalyst` 出现 **0 次**、溶剂最多降权到 0.6。→ **我们所谓"条件判据"目前实际上只是"温度判据"**。
- **命中率与收率反向**：收率 <30% 的记录命中 22.3%，收率 >80% 的只有 11.9%（高收率文献多是大分子/特殊催化，模板覆盖更差）→ 按收率筛样本会给召回评估带来偏差。
- 试剂门控的误杀率**本轮测不到**（ORD 该数据集 REAGENT 角色可得率 0%，引擎走"没写试剂不检查"分支）。

### 六条结论（全部【实测】）
1. **★ 第三次、独立地确认：特征扩展（①②）有害。** 在绝对 OOD 口径上，最优的是**基线特征 F0**：
   hgb `F0 0.820 > F1 0.811 > F2 0.808`；lr `F0 0.808 > F2 0.804 > F1 0.792 >> F3 0.682`。
   **★ 子代理正式合并件（池化口径）复核后的修正**：**F3 的崩溃是 lr 专属**（lr_F3 池化 **0.6310**）；
   **hgb_F3 池化 0.8057 并不崩**，但仍低于 hgb_F0 的 **0.8166**。
   → 「**F0 最优**」成立；「**F3 崩**」**只对 lr 成立**，不能当成普遍结论。
   这与 §1（同对内 micro AUC 无增益）**互相独立**，两条完全不同的评估路径得出同一个结论 → **该方向可以判死。**
2. **★★ 拒识（abstention）是本轮唯一"明显可用"的产物。** 同一个 hgb_F0 模型：
   **全量硬判精度只有 0.729；只对最有把握的 60% 给判决 → 0.836；只对 20% → 0.928**（hgb_F1 到 **0.960**）。
   → **把"会不会发生"从全量硬判改成「高置信度才判 + 其余输出"不确定"」，不需要任何新特征就能拿到 93–96% 精度。**
   这是可以直接接进产品形态的改变（候选清单 + 排雷），且**与本轮其他失败项无关**。
3. **★ 校准：池化看着变好，逐 split 并没有 —— 池化的改善是假象（子代理正式件复核）**：
   hgb_F0 的**池化** ECE 从 0.0691 → Platt **0.0336** / isotonic 0.0456（Brier 反而从 0.1768 升到 0.1801）；
   但**逐 split ECE 平均没有改善**（−0.0220 ± 0.0097，**只有 13/40 个 split 变好**）。
   → **池化 ECE 的下降主要来自"抹平折间的尺度差"，校准器不跨 OOD 簇迁移。**
   含义：**拒识阈值必须随校准后的概率重定**，不能拿一个全局阈值硬套。
   （我上一版写的"原始 ECE 0.086 → Platt 0.108 变差"是**逐 split 均值**口径，与此不矛盾——两个口径指向同一件事。）
   → 【推断】下一轮该做的是**按模型选择是否校准**，而不是无脑校准。
4. **对稀疏特征做 StandardScaler 是有害的**：lr 全线下降（0.808→0.767、0.792→0.720、0.804→0.715），ECE 从 0.115→0.186 恶化。这是个明确的反模式。
5. **目标口径影响很大**：换成 `Yield>0`（`lryp_*`）后 AUC 持平（0.816）但 **AU-PRC 升到 0.865**，全量精度从 0.729 升到 **0.817**。
   → 【推断】正例/负例的界定方式对"当清单用"的体验影响比模型选择更大。
6. **★ 与论文基线的对照要换文件（子代理复核纠正了我上一版）**：任务给的 `results/Data_Source_best.csv` 是
   **8 类「数据源分类」任务**，不是本口径；**同口径（labels 二分类）的基线在 `results/JnJ25_False_Train_DRFP_best.csv`：
   rf 0.6656 / gb 0.6632 / knn 0.6519**。
   我们的 hgb_F0 池化 **0.8166** 比它高约 0.15，**但仍不可直接比**（特征集/切分/池化方式都不同）。
7. **★★ 这个 OOD 切分的本质必须知道（子代理复核，会改变适用范围的结论）**：
   该切分实质是 **source transfer**（it0 fold1 的 test 有 **88% 是 JNJ HTE 2024**、fold3 有 60% 是 Dreher Doyle 2018；
   各 Source 的 labels 正类率在 **0.070 ~ 0.788**）。
   **一个不含任何化学信息的捷径——只用 train 里该 Source 的正类率——平均 AUC 就有 0.619 ± 0.084**，
   与论文 DRFP 基线 0.666 **同量级**。
   → **绝对概率里含大量「先验漂移」，不能被当成纯化学判据**；§「③ 的落地形态」那个判决器必须带着这条警告使用。
8. **★ 拒识的代价要说全**：hgb_F0 覆盖 20% 时精度 0.928，但**只捞到全部正例的 15.3%**（100% 覆盖时为 0.669）。
   → 「只判最有把握的 20%」= **高精度、低召回**，适合**排雷/否决**，**不适合「找全所有能发生的反应」**。

> 保留下方更早的**窄配置探针**（只有 1 个 iteration / 4 个 split、只跑 lr）作方法记录——它的方向（F3 < F0）与上面的全量结论一致。

**★ 交叉验证（【实测】）**：我先前用**另一个进程、另一次运行**独立跑过 iteration_0 / lr / F0，
现与子代理分片里 iteration_0 的 4 个 split 逐条对比（`tools/crosscheck_abs_iter0.py`）：
`0.627940 / 0.913756 / 0.880516 / 0.707735` —— **差值全部为 0.00e+00，逐条吻合**。
→ ③ 的头条数字（以及上面的 AUC/ECE/拒识表）**来自可复现的两次独立运行**，不是单次结果。
