# 第一百六十二轮：训练半区模板覆盖——94.99%，差 1 条到 95%

> 方向：不再用 ORD 低支持度模板做 rescue，而是从 **USPTO-50k 训练半区**（反应级排除官方 test）
> 挖通用正向模板，作为覆盖层。
> 结果：**召回 94.99%（4,743/4,993）**，比默认 92.19% 高 2.80 pp；
> 候选只从 33.48 涨到 **35.07**，top-1 几乎不动（73.72→73.70），top-5 90.31→91.51。
> **离 95.00% 差 1 条反应**；与 ORD rescue 并集是 96.05%，但候选回到 ~70。

## 1 协议（可复核）

1. 官方 test：`reports/paper/data/uspto50k_official/raw_test.csv`（4,993 条可评）。
2. 训练池：`uspto50k_mapped.jsonl` 中 **signature（规范化底物集合 + 全产物集合）不在官方 test**
   的行。按反应级排除，不按专利 id（id 会重复：5,001 行只有 4,182 个唯一 id）。
   - mapped 50,000 行 → 排除 5,068 行 test（含重复）→ **训练 44,932 行，抽取失败 0**。
3. 每条训练反应用 RDChiral 抽 retro 模板，翻成 forward（底物>>产物），按相同 SMARTS 计 support。
   - 5.2 ms/条，240 s；**11,453 个唯一模板**（support≥2: 3,938；≥5: 1,304）。
4. 覆盖层用 `core/rescue.py` 的 `RescuePool`（原子环境预筛 + 真实反应应用），
   与引擎 `_rescue_apply` 同构：单底物 + 两两逐 job。
5. 引擎新增 `rescue_path` 参数（默认 None = 原 ORD 池，行为不变）；bench 新增
   `CHEMCREACT_BENCH_RESCUE_PATH` / `CHEMCREACT_BENCH_RESCUE_MAX_SUPPORT`。

## 3 泄漏审计（为什么这不是记忆）

对 390 条默认 miss 中 train 模板补回的 **140 条**：

| 检查 | 结果 |
|---|---|
| 训练池有同一**主产物**（去立体） | **0 / 140** |
| 训练池有同一**底物集合** | **0 / 140** |
| 训练池有同一（底物集合 + 主产物，去立体） | **0 / 140** |
| 官方 test 反应本身进入训练池 | 已在入口按 signature 排除 5,068 行 |

也就是说：补回的产物与底物在训练池里都没出现过；模板是在**局部反应中心**层面泛化，
不是把测试反应记下来。

另外，390 条 miss 里：
- 精确（含立体）命中 140（35.9%）；
- **去立体命中 231（59.2%）**——还有 91 条是「骨架对了、立体不对/未指定」。
  这是下一步最便宜的增量来源，但也说明模板法对**新生成手性中心**天然缺信息。

## 4 结论

1. **模板来源比低支持度 rescue 重要得多**：train 模板 +2.80 pp、候选 +1.59；
   ORD rescue +2.26 pp、候选 +37.9。前者 top-1 不掉，top-5 还涨 1.2 pp。
2. **94.99% 与 95.00% 的差别只有 1 条反应**（0.02 pp），不应被当成方向性结论；
   真正有意义的是从 92.19 到 ~95 的跃迁。
3. **并集 96.05% 是实测命中集合**，但候选成本未合并实测；按两层增量相加约 72/反应（推断）。
   如果必须写「≥95%」，并集是唯一已实测过线的配置；但它不是好产品默认。
4. **协议边界**：模板来自同语料的训练半区（标准监督协议），不是跨语料。
   50k 泄漏控制基准（91.69%）不能直接套用这个库——需要另建「模板源与评测集不相交」的 50k 划分。
5. 立体是下一个杠杆：91 条 flat-only miss 说明「骨架对、立体丢」，修模板/产物的立体传播
   可能在不加候选的情况下再补几个点；但这属于新问题，不在本轮范围。
