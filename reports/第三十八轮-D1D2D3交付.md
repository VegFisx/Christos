## D1：方向层「可计算判据」（已落地，但实测覆盖增益 = 0）

**做了什么**：把方向判决从「查手写类别清单」扩到**从反应本身算出来**——
新增 `direction.shape_from_co_products()`：同批副产物里出现**一分子水**（规范化 SMILES == `O`）
=> 这一步是脱水/缩合形状 => 水相判「方向可疑」，非水相判「方向明确」，介质不明判「平衡」；
来源标 `co_product_shape`（可审计）。**也覆盖自抽模板 `mined_*`**（原立场是一律未定）。

**口径（写死）**：只认「生成水」这一侧；其它小分子（乙醇/HCl…）一律不判 —— 两向都留了自检。

**实测（必须如实说）**：
* 单元级：`judge("mined_mono", 水相, co_products=("O",))` -> **方向可疑 / co_product_shape**；
  换成 `("CCO",)` -> 仍 **方向未定**（不误判）。
* **端到端覆盖增益 = 0**：甘草 demo 552 条路径里，`co_products` 列**没有任何一条含一分子水**
  （实测：370 esterification + 182 mined 全部 False）-> 方向分布仍是 **370 可疑 / 182 未定**，与上一轮一字不差。
* **所以这条判据目前只在「副产物里确实带水」的模板上生效。** 要把覆盖率真正提上去，
  下一步必须拿到**反应物侧**（元素收支 ΔH/ΔO）——引擎里是 `comp_a/comp_b + 模板产物` 才知道的；
  但**模板可能自带试剂**，直接用两侧算会算错，所以要先测「模板反应式是否完整」，再算。**没硬上。**

### 问题 1（严重）：单底物模板把反应物**算了两遍** -> 元素收支判据给出假判决

单底物模板构造的是 `reactant_a == reactant_b == 同一个分子`（`smartreact_engine.py:535-537`），
而我原来写的是 `_element_totals([get_mol(comp_a), get_mol(comp_b)])` —— 于是**底物被计了两次**，
Δ 系统性偏向"脱水形状"。实测（修正前）：水杨酸单底物反应被记成 Δ=(-7,-4,-3)，正确的是 (0,+2,0)。

**已修**：改成 `[get_mol(_ca)] if _ca == _cb else [get_mol(_ca), get_mol(_cb)]`（按规范化 SMILES 去重）。

**数字更正（甘草 demo，552 条路径）**：

| | 方向可疑 | 方向未定 | 其中 element_delta_shape |
|---|---|---|---|
| 修正前（错） | 509 | 43 | 139（Codex 实测其中 88 条是 mined_mono，60 条口径错） |
| **修正后（正确）** | **449** | **103** | **79** |

-> **真实增益 = 79 条（不是 139）**：182 条原本"未定"里有 79 条拿到了方向判决，其余 103 条仍无判据。

**仍然存在的口径限制（Codex 指出，本轮未修）**：Δ 是**单个产物**对**整个反应物侧**算的；
当模板一次产出多个片段时，"损失"会被高估。收紧办法：要求其余产物都是小分子（≤2 重原子）才允许按形状判。

另按 Codex 意见补了**可审计性**：`element_delta` 现在进台账（`PATH_FIELDS` 新增该列），
`element_delta_shape` 这个判据终于能对账。
