## 一、①规则修复（已完成，回归全绿）

### 改了什么

`core/smartreact_engine.py`：
* 新增 `_reagent_role()`：把试剂（名字或 SMILES）判到**功能角色**
  —— metal_catalyst / phosphine_ligand / carbonate_base / alkoxide_base /
  amine_base / phosphate_base / water / acid / hydride_reductant / azodicarboxylate
* `_reagent_match(want, got, allow_role=False)`：新增角色级比较，**默认关闭**
* `cond_activation` 里**只有"降权 0.5"那一路**打开它；
  **【必需试剂判零】那条路（Mitsunobu 缺 DEAD 那种）保持严格**，不放宽

|---|---|---|
| 1.0 | 357 | **1,546** |
| 0.5（试剂不匹配降权） | **2,467（82%）** | **0** |
| 0.6（溶剂不在 ORD 偏好） | 176 | 384 |

（修后仍有 0.5 的 2,736 条来自**另一个**来源：溶剂门控与必需试剂判零，见下方"未解决"。）

## 二、②数据信号上限（`tools\probe_condition_signal.py`，严格留组交叉）

**口径**：同一组底物（同一对 aryl/amine）内，预测"这条记录有产物（Yield≥0.5）"与"零产率"；
给某组打分时**只用其它组的统计**（避免同组泄漏 —— 第一版没做留组，AUC 虚高到 0.64）。

| 特征 | AUC（留组） | 成对比较 |
|---|---|---|
| **催化剂 catalyst** | **0.5889** | 143,813 |
| 溶+催+碱（组合） | 0.5668 | 143,813 |
| 碱 base | 0.5141 | 143,813 |
| 溶剂 solvent | 0.5078 | 143,813 |
| 来源 source | 0.5000（全 ties） | 143,813 |
| 添加剂 additive | 0.4983 | 143,813 |

**同一套条件在同一组内"既成又败"的组合：712 / 1,238 = 57.5%**

→ 也就是说：**一半以上的失败，不是"条件选错了"造成的**（同一套条件在别的组里能成，
在这个组里就是不成）→ 那是**底物特异性/未测变量**，不是条件层能补的。

## 三、结论与要拍板的事

| 问题 | 答案 |
|---|---|
| 规则该不该修？ | **该修，已修**：它让分数有了物理含义（0.5 的"名单不匹配"惩罚消失），回归全绿 |
| 修完判别力上去了吗？ | **没有**：AUC 0.519 → 0.497 |
| A 方案（ML）值不值得做？ | **上限约 AUC 0.59**（催化剂带来的），且 57.5% 的失败不可由条件解释 |
| 我的建议 | **不追求"判别力"**；改做**"暴露依据"**（原 B 计划）：让用户看到分数是"温度窗口命中/溶剂不匹配/试剂角色不匹配"，而不是一个孤零零的 0.5 |

**要你选**：
* **选 A**：我按上面口径训模型（留组交叉、只报 AUC），预期 AUC ≈ 0.57~0.60。做完给你数字。
* **选 B（我建议）**：不训模型；把 activation 的**依据**如实暴露到查询式交互里
  （改文案 + 加一列），并把这个"上限"写进交接文档。**半天内、零风险。**
* **选 A+B**：先 B，再 A。
