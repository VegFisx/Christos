## 2. 基准库的构建（泄漏控制，写死）

1. **复现校验**：用 `retro_cluster_eval.py`（min-freq=3, per-bucket=3）在不做剔除的情况下重聚类，
   得到与现有生产库**完全相同的 3,228 条模板集合**（集合相等，已实测）。
2. **剔除**：凡"产物侧（去映射号后）命中 USPTO-50k 任一产物"的抽取记录**一律删除**——
   共删 3,007/56,047 条；再按同一算法重聚类 → **3,065 条**（`lib_uspto50k_excl.jsonl`）。
3. 该库中**不存在任何一条**来自 USPTO-50k 反应的模板实例（按产物级；反应级更严的下界见 §4）。
   -> 对 50k 的任何评测都是"实例未见"条件下的评测。
4. 泄漏量化（原始库对照）：50k 产物出现在原抽取记录的比例 **4.96%（2,480/50,016）**；
   完整反应签名一致 **1.11%（555/50,016）**。评测时对 `in_sources` 子集单独报告。

## 3. 指标定义

* **any-hit 覆盖率**：对目标产物套用全部模板；若**存在**一个切断，其前体集合（去映射号规范化）
  与 50k 记录的**反应物集合严格相等**，记命中。
* **top-k（k=1/3/5/10/50）**：同一产物的全部切断按 **【模板出现频次 freq 降序, smarts 字典序】** 排序
  （确定性、可复现；**不是**打分/排序产品，亦不引入化学评分），取正确切断的最好名次 ≤ k 记命中。
* **化学可用性构成**：对抽样产物（按反应类别分层，每类 ≤300，种子 20261014）的全部切断，
  用**与生产完全相同的 `retro_search.step_usability`**（R1 残基 / R2 放大 / R3 惰性 / R4 荒谬）逐条判定；
  另记 元素覆盖比 ratio 与黑名单标记，供"确定性替代判据"与"黑名单效果"分析。
* **黑名单**：`reports/retro_template_blacklist.json`（51 禁 + 3 豁免 + 3 no-op；默认关的开关）。
  在 50k 上逐条扫描命中与可用性（这是该名单的第三次分布外检验：56 目标 -> COCONUT 64 -> USPTO-50k）。

* **正向单步召回**（第三块）：输入 = 记录的**反应物**（1~3 个）当底物，正向引擎跑 **1 轮**；
  命中 = 记录产物出现在候选集合（**不排序**）；同时报候选规模与分类别回收率；
  条件档案固定"煎煮"（条件只影响标注、不影响本轮生成口径）。**如实声明**：只给反应物、
  **不给催化剂/试剂**，因此 C-C 偶联类反应天然吃亏（分反应类别报告）。

## 4. 必须一起报告的注意事项（写死，防选择性报告）

* 模板数量 3,065 是"剔除后"的；与生产库 3,228 的差异（-163）全部来自泄漏剔除。
* 50k 的反应物集合严格相等是**严口径**：多组分级联/三组分记录天然不可能被单步模板命中；
  论文须声明在单步口径下讨论。
* `step_usability` 对中等分子使用**限时 MCS**（2 s 超时）——判定随机器负载漂移，
  已做专门实验量化（`instability.json`，安静/高负载/安静 三轮重判）。
* 并行评测会提高 MCS 超时率；各结果文件都记录 USTAT（超时计数），随论文一并披露。
* 反应类别分布、类内命中率逐类报告（`coverage_summary.json` 的 `by_class_any_hit`）。
