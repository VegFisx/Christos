## 三、现状的核心判断（我的判断，不是实测）

1. **"判断反应会不会发生"这件事，现在还没做成**：
   引擎实际在做的是「这两个官能团能不能反应」（结构可行性），不是「这个底物+这套条件下会不会发生」。
   证据：HTE 上假阳性 94.9%（活性 99.4%）——它**几乎对任何一对芳卤+胺都说"能反应"**。
2. **瓶颈不是数据，是条件意识**：反例数据已经充足（1 万条量级），但现有条件门控 AUC 只有 0.530；
   数据学出来的判据能到 0.592~0.646，**显著更好但绝对值仍弱**（0.8 才算能用）。
3. **覆盖率与精度是两笔账**：ORD 自抽模板能把覆盖率顶 +5~+10 pp，但宽松版会多吐 36% 的假产物。
   目前**没有免费午餐**。
4. **逆合成那条线做得顺、数字好看，但它不是用户最初要的核心能力**（第一轮报告第七节已经警告过）。

## 四、必须知道的坑（本会话踩过的，都写进纪律了）

| 坑 | 实例 | 铁律 |
|---|---|---|
| 口径没定死就开测 | 覆盖率测了 4 次；"缺 DEAD 判零"因口径 bug 差点误判"数据不支持" | 先把口径写进脚本头部 |
| 静默失败 | 原覆盖率脚本每处 `continue` 都不计数 | 批量脚本必须累计失败并打印 |
| 手写数据 | `hobt`/`dcc` 别名 SMILES 是错的（判据会判零 → 误杀） | 化合物/试剂一律从库或权威来源取 |
| 原子映射被抹掉 | `canon_nomap()` 结果再做映射运算 → 静默空集 | 一律用 `tools/mapped_chem.py`，提交前跑 `audit_mapped_safety.py`（必须 ERROR 0） |
| 立体化学拆分 | DEAD 的 `/N=N/` 与 `N=N` 算成两个试剂 → 覆盖率腰斩（59% vs 18%） | 试剂比较/统计一律 `isomericSmiles=False` |
| 解析伪影当反例 | ORD 的 `yield==0` 里 379/404 是层析梯度被解析成收率 | 先打印原始记录再下结论 |
| 引号 | 本会话我又踩了 3 次（ASCII 引号写进中文串） | 中文引号只用「」；写完立刻 `ast.parse` |
| 进程太久 | rdchiral 在复杂分子上 ~1 条/秒 | 抽取/挖掘要加时间预算 + 重原子上限 |
| Windows 编码 | `test_conditions.py`/`audit_template_chemistry.py` 曾因 GBK 跑不起来 | 脚本自己 `reconfigure(encoding="utf-8")` |

10. **ORD 表的使用边界（实测）**：无 reaction_class、几乎全正例、温度只有 28.46% → 只能当 **yield 回归 / 正例标尺**，
    **不能**当"会不会发生"的负例训练集。（注：`reagent_*` 两列也是 0%，但见第 9 条——试剂可从"非贡献组分"恢复。）
