## 四、最有价值的几个发现

### 1. 论文补充材料的规则表有实质问题（`论文规则表-问题清单.md`）

对照 `docs/supplementary/TableS1_reaction_rules.csv`，用**它自己写的说明**去验它自己的 SMARTS：

| 类别 | 条数 | 例 |
|---|---|---|
| 原子不守恒 | 2 | β-酮酸脱羧**没写 CO₂**；缩醛水解**丢了一个醇** |
| 产物结构错 | 2 | 醌还原产物分子式**多 2 个氢**；烯酮水合**加成方向反了** |
| **整类底物漏匹配** | 3 | 糖苷水解 `[C:8]` 只认脂肪碳 → **酚苷全不匹配**（中药糖苷绝大多数是酚苷） |
| 过窄 / 过宽 | 3 | 脱水**认不出乙醇**；脱甲基**抢了酯水解的活** |
| **说明承诺但从未实现** | 1 | 醌还原说明写「丹参酮、大黄蒽醌」，但 SMARTS 只认两个羰基**直接相连**的邻位 |

### 2. 新旧引擎的实际差异（`新旧引擎正面对比.md`）

**最可靠的一个数字**：拿你项目里**真实的旧引擎**和新的兼容层，在同一批真实药材上各跑一遍。

```
药材：甘草 + 附子 + 干姜（各 20 个成分）
旧引擎                344 个去重产物
新引擎（煎煮条件）      455 个
新引擎（全规则激活）    620 个

同口径（新引擎全规则激活 vs 旧引擎）：
    两边都有 180    只有旧引擎 164    只有新引擎 440
```

**并且证明了「没有回归」**：对那些 SMARTS 没改过的规则，
把产物上限放大后，「只有旧引擎」全部归零 —— **新引擎产出的是超集**。

> ⚠️ 另一个常被引用的数字「**44.6%**」（`新旧引擎影响量化.md`）**口径不同、且被低估**：
> 它只统计了**10 条改过 SMARTS 的规则**在 SMARTS 层面的差异，
> **完全没算**新增的 40 条规则、陪跑试剂修复、运行时守恒守卫、条件激活层。
> 那份文档开头已加了说明。


### 3. 三个反复出现的失败模式

| 模式 | 次数 | 例 |
|---|---|---|
| **加基因接错原子** | 4 | Michael 硫醇/胺、烯酮水合、α,β-不饱和羰基水合 |
| **氢数写死** | 5 | 逆羟醛、醇醛缩合、酮-烯醇化、脱水、胺类三条 |
| **靠灌试剂凑平** | 3 | 美拉德、醚化、醌还原 |

> **共同点：原子数完全对得上，四道闸门全部放行。只有"用已知答案去卡"才能发现。**

### 4. SMARTS 的五个陷阱（都踩过并记进注释）

```
[C:]      只匹配脂肪碳        → 酚苷/酚酯全不匹配，要写 [#6:]
[CX4H:3]  氢数写死            → 乙醇/乙醛/丙酮不匹配
默认键     只认单键或芳香键     → 跨双键的路径匹配失败，要写 ~
[C;R]     约束要写在映射号前    → [C:2;R] 无效，[C;R:2] 才对
[X]       算含氢总连接数       → [CX3H] 匹配 2 个重原子邻居 + 1 个 H
```
