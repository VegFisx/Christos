## 1. 起点：一条排不掉的过度匹配

上一轮补「对醌还原」时，发现它会顺带匹配**甾体 3,6-二酮**这类结构，
产物配不平（少 2 个氢）。

试过 6 种 SMARTS 约束都排不掉：环内键 `@`、环成员 `R`、递归 SMARTS、
六元环 `r6`、反应物侧环闭合……

### 这轮先把「为什么」看清

写脚本把匹配到的原子逐个打出来：

| 底物 | 两个 C=O 碳**共处一个环**吗 |
|---|---|
| 对苯醌 | **有**（同一个六元环） |
| 9,10-蒽醌 | **有**（同一个六元环） |
| **甾体 3,6-二酮** | **★无——在两个不同的环里★** |

**真醌的两个 C=O 在同一个环里；甾体的是两个环各一个。**

试着用环闭合强制"同一个环"——**但反应物侧加环闭合会让产物价态非法**
（RDKit 把闭合带进产物）。7 种变体全部失败。

## 2. ★ 换一层解决：引擎里的运行时守卫 ★

与其继续跟 SMARTS 较劲，不如**在引擎里守一道**：

> 规则声明了 `co_reagents` / `byproducts`，那么
> **底物 + 陪跑试剂 − 副产物 == 产物** 必须成立。
> 不成立就说明这个产物是错的，**直接丢掉**。

这是**通用防线**——不止管这一条规则，任何规则（现在或将来的）产出配不平的产物都会被当场拦下。

### 实测

```
甾体3,6-二酮（配不平）  → 0 个产物   ← 被拦下
对苯醌                 → C6H6O2      ✓ 放行
9,10-蒽醌              → C14H10O2    ✓ 放行
邻苯醌（不该匹配）      → 0 个产物   ✓
→ 4/4
```

## 3. ★★ 写守卫的过程中，我自己的测试集抓住了我两个 bug ★★

### bug 一：编辑时把循环重复插了一遍

改完跑回归，**反应级验收立刻从 62/62 掉到 61/62**：

```
✗ eli_dehydration
    期望 ['CC=CC']；实际产出 2 个: ['C=CCC', 'O']
```

查下来——**我在插入守卫时，把 `valid` 的循环重复写了一遍**，
每个产物被 append 两次，于是 `out` 提前触到数量上限，
第二个产物组根本轮不到。

```
valid = []
for part in parts:      # ← 原有的
    valid.append(...)
for part in parts:      # ← 我编辑时重复插入的
    valid.append(...)
```

**删掉重复，62/62 恢复。**

### bug 二：「守卫关闭」的路径没真正关闭

多片段底物（盐）要被放行，我写成：

```python
left = _atom_counts_of_smiles(sub.smiles) if _guard_on else {}   # left = {}
...
for formula, n in (rule.get("co_reagents") or {}).items():        # ← 又加回来了
    left[el] = left.get(el, 0.0) + c * v
```

那个盐的规则有 `co={H2:1}`，于是 `left` 变成了 `{H:2}`（**非空**），
`_counts_differ` 的"任一边为空就放行"短路**失效**，照样误杀。

**改成守卫关闭时彻底不构建 `left`，误杀从 35 组降到 0。**

> 教训：**"关闭"要关彻底。** 设了空值之后又被后面的代码填上，
> 比不关还难查——因为代码看起来是对的。
