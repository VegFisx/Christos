# ①② 路线可用率 + 可用性打分 — 报告（2026-10-11 第七轮）

> **结论：形式成功率 45% 里，真正化学可用的是 26%。**
> **通过打分排序，用户看到的第一条路线可用率从 21% 提到 26%（= 可用率上限）。**

---

## ① 路线可用率：先校准判据，再量数字

### 判据迭代（这一步差点毁掉整个结论）

| 版本 | 判据 | 自校验结果 |
|---|---|---|
| v1 | 前体重原子数之和 >= 目标 -> 判「无进展」 | **6 条已知合法路线全被误杀（4/10）** |
| v2 | 前体是否为目标的超结构（子结构判定） | 7/10 |
| **v3** | **最大公共子结构(MCS) >= 目标重原子的 80%** | **9/10（6 条合法全过）** |

**v1 错在哪**：缩合/取代反应本来就会让前体原子数之和超过目标。
例：沙洛酚 <- 酪胺 + 水杨酸（酰胺偶联脱一分子水），原子数之和必然大于目标。
用「原子数之和」判「无进展」，等于把**所有**缩合反应都判死。

**教训**：评测判据必须先用【已知正确的样本】校准，否则量出来的 0% 是判据的 0%，不是系统的 0%。
校准用例在 `tools/check_usability_criteria.py`（6 条合法 + 4 条退化）。

### 判据 v3（每条路线逐步检查）

| 规则 | 含义 |
|---|---|
| R1 残基路线 | 某前体与目标的最大公共子结构 >= 目标重原子的 80% -> 「把目标换个基团再变回来」 |
| R2 前体更大 | 某前体重原子数 > 目标 |
| R3 惰性小分子 | 目标 >15 重原子且前体 <=2 重原子（CCl/CO/水） |

### 实测（100 个 ORD 产物，depth3 beam4 max_routes3）

| 指标 | 数值 |
|---|---|
| 找到路线（**形式成功率**） | 45/100 = **45.0%** |
| 至少一条可用路线（**可用率**） | 26/100 = **26.0%** |
| 路线总数 / 可用 | 120 / 47 = **39.2%** |
| 规则命中 | R1 残基路线 87、R2 前体更大 29 |

**所以之前那个 45% 要这样读**：45% 是「拼出了形式完整的路线」，
其中真正化学说得通的只有 **26%**（其余 19 个点是 R1/R2 那种换基团/逆向放大）。

## ② 可用性打分：把判据接进搜索排序

**改动**（`retro_search.py`）：
- 新增 `step_usability()` / `route_usability()`（与评测同一套判据，避免两处口径不一致）
- `Route` 增加 `usable` / `unusable_reason` 字段
- 排序键改为 `(not usable, 步数, -终点数)` -> **可用路线永远排在前面**

**效果（同口径复测）**

| 指标 | 改动前 | 改动后 |
|---|---|---|
| 形式成功率 | 45.0% | 45.0%（不变） |
| 至少一条可用路线 | 26.0% | 26.0%（不变） |
| **第一条路线就可用** | **21.0%** | **26.0%** |
| 路线层面可用率 | 35.0% | 39.2% |

**读法**：搜索能力没变，但**「只要存在可用路线，用户看到的第一条就是可用的」**
（21% -> 26%，正好补上那 5 个点）。

实测例子（`CCNC(C)=O`）：改动后路线 1 = `CC(=O)O + CCN`（酰胺偶联，可用），
另外两条 R2 路线被排到后面并标注不可用原因。

## 三、数字全景（全部实测）

| 环节 | 起点 | 现在 |
|---|---|---|
| 单步模板召回（留出集） | 10~12.5% | **83~97%** |
| 端到端形式成功率 | 4~5% | **45%**（深度3）/ 52%（深度4） |
| 端到端**化学可用率** | 未测 | **26%** |
| 用户看到的第一条可用 | 未测 | **26%**（= 可用率） |
| 单目标耗时 | ~3s | 0.02~2.3s |

**这两个口径以后必须一起报，不能只报 45%。**

## 四、下一步建议

1. **继续压 R1 残基路线（87 次命中，最大头）**：
   现在只是把它们排到后面，没有阻止搜索走进去。可以在递归分支选择时就惩罚
   「前体与目标 MCS 占比 >80%」的分支，把预算花在真正的拆解上。
2. **R2 前体更大（29 次）**：这类是「逆向放大」（如 `NC1(c2ccccc2)CC1 <- NC1(c2ccc(F)cc2)CC1`），
   应该在切断阶段就过滤，而不是靠排序兜。
3. **接 TCMAI**：现在有 26% 可用率 + 每条路线带可用性标注，
   作为「实验性」功能是诚实可用的（界面必须显示可用性标注和不可用原因）。
