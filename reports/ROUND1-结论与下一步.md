校验器的判据：

```
原子(底物) + 原子(co_reagents)  ==  原子(SMARTS产物) + 原子(byproducts)
```

并且区分两种性质完全不同的失衡：

- **漏写片段**（产物原子 < 底物）：如 β-酮酸脱羧没写 CO₂ → 补一个分子式即可
- **凭空造原子**（产物原子 > 底物）：SMARTS 模板结构性写坏 → **必须重写规则**

## 2. ★ 本轮最重要的发现：RDKit 在环内断键时会复制原子

这不是猜的，是设计实验证伪出来的。

同一套酯水解 SMARTS，分别喂链状酯和环内酯：

| 底物 | 类型 | 结果 |
|---|---|---|
| 苯甲酸甲酯 | 链状酯 | 配平 ✓ |
| 乙酸乙酯 | 链状酯 | 配平 ✓ |
| ε-己内酯 | **环内酯** | **★凭空造原子，多出 C4H10★** |
| γ-丁内酯 | **环内酯** | **★凭空造原子，多出 C2H6★** |

产物 `C5H10O2 + C5H12O` 两个片段互相重叠——RDKit 没能正确切断环键。

### 修法（已实测）

用 SMARTS 的 **`!@`（非环键）** 约束被断开的那根键：

```
原： [C:1](=[O:2])[O:3][C:4]
改： [C:1](=[O:2])[O:3]!@[C:4]
```

| 写法 | 链状酯 | 环内酯 |
|---|---|---|
| 原写法 | 配平 ✓ | ★造原子★ |
| **`!@`** | **配平 ✓** | **不匹配（正确）** |
| `@`（环键） | 不匹配 | 仍造原子 |
| `[!R]` 递归 | **算错**（乙酸乙酯少 C1H2） | 不匹配 |

`[C:4;!R]` / `[C:4;!r5]` 这种原子级约束在本版 RDKit **直接编译失败**，不能用。

### 附带结论

**环内断键必须单独写"开环规则"**，其产物要写成一整条链，不能用"断成两个片段"的写法。
这正好解释了为什么原始的 `src/reaction_rules.py` 里同时有 `ester_hydrolysis` 和 `lactone_ring_opening` 两条规则——那个设计意图是对的。

### 代价：覆盖面收窄（这是正确的取舍）

加了 `!@` 之后，环状底物不再被这些规则命中，`匹配底物` 数下降：

| 规则 | 加 `!@` 前 | 加 `!@` 后 |
|---|---|---|
| 缩醛水解 | 400 | **15** |
| 半缩醛水解 | 44 | **3** |
| 酰胺水解 | 97 | **58** |
| 硫酸酯水解 | 4 | **3** |

**这不是退步，是把"错的答案"换成"不回答"。**
环状糖苷、内酯、环状缩醛、内酰胺的转化，要由专门的开环规则来处理。宁可漏，不可错。
