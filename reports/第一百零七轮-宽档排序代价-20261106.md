# 第一百零七轮：宽档的排序代价（top-k / MRR）

日期：2026-11-06
口径：`tools/bench_topk.py`，同一 3,000 条抽样（seed 20261014），煎煮条件，1 轮，立体默认开。

## 0. 一句话

宽档把召回从 92.47% 提到 **95.27%**，但 top-1 从 42.67% 掉到 **40.20%**、top-5 �� 67.67% 掉到 **56.97%**、MRR 从 0.5465 掉到 **0.4922** —— **它是「多给候选」换召回，不是「排得更好」**。

## 1. 两个配置的实际差别

| 项 | 默认档 | 宽档 |
|---|---|---|
| `extra_template_min_support` | 10 | 1 |
| `extra_template_limit` | 20,000 | 60,000 |
| `mono_template_limit` | 6,000 | 20,000 |
| `mono_include_co_reagent` | 否 | 是 |
| `max_products_per_pair` | 32 | 128 |

## 2. 结果（同一批 3,000 条，0 报错）

| 指标 | 默认档 | 宽档 | 差 |
|---|---|---|---|
| 召回（候选集合内有期望产物） | 92.47% | **95.27%** | **+2.80 pp** |
| top-1 | **42.67%** | 40.20% | −2.47 pp |
| top-5 | **67.67%** | 56.97% | −10.70 pp |
| top-10 | **80.03%** | 65.47% | −14.56 pp |
| MRR | **0.5465** | 0.4922 | −0.0543 |
| 命中位次中位 | 2 | 2 | 0 |
| 排第一占比 | 42.67% | 40.20% | −2.47 pp |
| 平均候选数 | 21.3 | 47.0 | +25.7 |
| 耗时 | 261 s | 565 s | ×2.2 |

\* `hit_rank.share_rank1` 与 `top1` 同源，两个文件里的值分别是 0.4267 / 0.402。

## 3. 为什么掉

候选数从 21.3 涨到 47.0。新增的 2.8 pp 命中**几乎都落在第 6 位之后**：top-5 掉 10.7 pp 而召回只涨 2.8 pp，说明新模板挤进候选池的同时，也把原来排在前面的正确产物往后推（容量守恒）。

这和第一百轮 3 条配置的结论一致：**放宽装载本身会让召回掉 5 pp**（因为 cap 32 装不下），把 cap 放到 128 才净赚 +2.8 pp —— 但那 2.8 pp 是「多给一倍候选」买来的。

## 4. 对论文与产品的意义

1. **默认档不动**。宽档只作为「高召回模式」的可选开关（`--mined-wide --maxprod 128`），论文里必须同时报召回与平均候选数（39.2 / 47.0），不能只报 94.25%。
2. **不能写「预测更好」**。宽档的 top-1、top-5、top-10、MRR 全部低于默认档，任何「更准」的措辞都站不住。
3. 全量 50k 宽档召回 94.25%（`forward_50k__wide128m20k.json`）与这里 3,000 条的 95.27% 不是同一分母，报告里要分开写。

## 5. 复现

```powershell
python -I tools/bench_topk.py --n 3000 --mined-wide --maxprod 128
```

产物：`reports/bench_topk_wide128_20261106.json`（默认档结果仍在 `reports/bench_topk_20261104.json`，未覆盖）。
