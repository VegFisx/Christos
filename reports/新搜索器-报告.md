# 换搜索器 —— 端到端 5% → 45%（2026-10-11 第五轮）

> **这一轮把上一轮"瓶颈转移"的判断变成了实际收益：端到端成功率 4% → 45%，而且快了一个数量级。**
> 全部数字**实测**；口径写在下节；每个数都能用同目录的脚本复算。

---

## 一、口径

| 项 | 定义 |
|---|---|
| 目标 | 100 个 ORD 真实反应**产物**（MW ≤ 500、单组分、重原子 ≥ 8），与 ①轮 bench 同一筛选函数 |
| 终止集合 | 旧（COCONUT 277,268 + tcm.db）+ ①砌块 32,341（**不变**） |
| 命中判据 | 找到一个切断方案，其**全部前体**都在终止集合里（"一步到位"） |
| 成功 | 搜索能在深度上限内拼出一条完整路线 |
| 两组差异 | **只换模板库与搜索策略**，其余全部相同 |

## 二、实测阶梯

| 配置 | 端到端成功率 | 速度 |
|---|---|---|
| 旧：SmartReact 反转 9,770 条 + 单步 | 4.0% | 295s / 100 目标 |
| 只换模板库：新 3,025 条 + 单步 | **15.0%** | **18s** / 100 目标 |
| ＋多步搜索（深度 2，beam 4） | **30.0%** | 71s / 100 目标 |
| ＋多步搜索（深度 3，beam 4） | **45.0%** | 213s / 100 目标 |

**深度 3 的路线步数分布**：1 步 15 条 / 2 步 10 条 / 3 步 20 条
→ 三分之二的路线需要 ≥2 步。**"单步就 5%"这个天花板本来就是搜索策略造成的。**

### 三个结论

1. **换模板库 = 3.75 倍提升，而且快 16 倍**
   9,770 条 → 3,025 条，候选少了 69%，命中反而更高。
   原因：旧库是"正向模板反转"，新库是 rdchiral 从原子映射反应**按逆方向抽 + 聚类**。
2. **多步回溯才是真正的放大器**：15% → 30% → 45%。
   每加深一层大约 +15 个百分点（边际递减）。
3. **★ 不要合并旧模板库 ★**（实测）
   12,795 条（新+旧）时每条目标 **9.6 秒**，比只用新库（0.7 秒/目标）慢约 10 倍，
   而旧库的单步能力已被证明差得多（召回 10% vs 97.5%）。**新库单独用。**

## 三、搜索器长什么样

`tools/bench_multistep.py` 里的 `search()`，约 40 行：

```
expand(分子, 路径, 深度):
  1. 套模板拿到所有切断方案
  2. 打分：先看有没有"全部前体可得"的方案 -> 有就直接成路（一步到位）
  3. 到深度上限或预算用完就返回
  4. 否则挑【最不可得的前体】里**分子量最大**的那个递归拆
     （一次挑 beam 个候选，按分子量排序）
保护：节点预算 3000 + 每目标 60 秒硬上限
```

关键点：
- **一步到位优先**：先扫全部方案找能直接收口的（旧版扫前 200 个就放弃，漏过正确答案）
- **递归只挑一个前体**：不展开笛卡尔积（否则爆炸）
- **挑最大的不可得前体**：它最可能是骨架主体
- **硬上限**：单目标 60 秒 / 3000 节点，保证可用性
