# 第三十三轮：条件层诊断 —— 为什么"不该反应的也说能反应"

> 日期：2026-10-13。承接第三十二轮的判卷结果（负例假阳性 90%）。
> 本轮**只新增诊断工具与报告**，未改任何引擎代码。
>
> **⚠ 本报告初版的"根因"写错了，已在 §三bis 更正（2026-10-13 同日）。**
> 初版写的是"条件层对 `B-H` 没有 ORD 条件数据，走无数据兜底" —— 实测**37 类全都有数据**。
> 真实原因是**试剂检查用"固定名单字面匹配"**。这条错误正是 `AGENTS.md` 第 1 条
> （推断不能当结论写进交付物）的实例，故保留更正过程，不悄悄改掉。

## 〇、30 秒读完

1. **假阳性不是"噪声模板乱说"**：54 个假阳性**全部**由 37 类里的 `B-H` 生成，
   **自抽模板一条没参与**（`tools\diagnose_false_positive.py` 实测）。
2. **条件是有的，判别力是没有的**：用 10,345 条**真实条件**逐条算 `B-H` 的 activation，
   只得到三个取值：**0.5（82%）、1.0（15%）、0.6（2%）**（`tools\diagnose_condition_layer.py` 实测）。
3. **它因此没有判别力**：同组底物换条件（换溶剂/碱/催化剂），
   **300 组里有 125 组（42%）activation 完全不变**；
   同组内"高产率 vs 零产率"的成对判别力 **AUC = 0.519（≈ 瞎猜）**。
4. **★ 真正的根因（见 §三bis）**：`0.5` 这个值来自引擎的**试剂检查**——
   它要求"条件里写的试剂"能在**6 个固定名字**里字面匹配上；
   而 HTE 用的是现代配体/碱（`tBuXPhos-Pd-G3`、`tAmOK`、`LiHMDS`…），**一个都对不上**，
   于是 27,497 行被压成同一个惩罚值。**这是"口径太粗"，不是"没有数据"。**

**结论**：第三十二轮那个 90% 假阳性，**病根在条件层的试剂检查口径**，
既不是方向层的问题，也不是"模板太激进"。

## 一、第一层诊断：假阳性从哪条路径来

`tools\diagnose_false_positive.py`：把 60 个负例里 54 个假阳性逐对重跑，看生成目标产物的规则。

| 项 | 实测 |
|---|---|
| 生成目标产物的规则 | **`B-H` × 54（100%）** |
| 自抽模板（`mined_extra` / `mined_mono`）参与假阳性 | **0 次** |
| 一个目标产物由几条规则生成 | 全部 **1 条**（54/54） |

→ 排除"多路径碰巧命中"和"自抽模板绕过门控"这两种解释。
问题集中在**37 类规则的条件门控**上。

## 二、第二层诊断：条件层到底会不会"看条件"

`tools\diagnose_condition_layer.py`：用 CSV 里**每条记录自己的真实条件**
（溶剂名 / 催化剂 / 碱，温度取假设值），逐条调用 `SmartReactEngine.cond_activation("B-H", cond)`。

样本：组内记录 ≥ 8 条的 **300 组 / 10,345 行**。

### ① activation 只有三个取值

| 取值 | 条数 | 占比 |
|---|---|---|
| **0.5** | 8,508 | **82.2%** |
| **1.0** | 1,590 | 15.4% |
| **0.6** | 247 | 2.4% |

均值 0.579，标准差 0.180 —— **一个连续条件量，输出的是三个台阶。**

### ② 换条件，引擎眼里常常"没区别"

| 项 | 实测 |
|---|---|
| 组内标准差 = 0 的组 | **125 / 300 = 41.7%** |
| 组内标准差均值 / 最大 | 0.124 / 0.250 |

即：**同一对底物、把 DMSO 换成甲苯、把碱换掉，有 42% 的情况 activation 一动不动。**

### ③ 成对判别力：等于瞎猜

| 项 | 实测 |
|---|---|
| 同组内（高产率 ≥0.5 vs 零产率）**AUC** | **0.5192** |
| wins / ties / losses | 19,197 / **110,934** / 13,682 |

**注意那个 ties**：110,934 次比较里两边分数**完全相同** —— 这正是"只有三个常数"的直接后果。

### ④ 但它不是完全没信息

| 溶剂 | n | activation 均值 |
|---|---|---|
| DMSO | 2,712 | 0.503 |
| 1,4-Dioxane | 2,638 | **0.601** |
| t-AmOH | 2,124 | **0.643** |
| Toluene | 1,557 | 0.609 |
| DMA | 613 | 0.517 |

→ 溶剂方向上是**有信号的**（DMSO 低、t-AmOH 高），但被压成了三档，
而且**这个信号来自 ORD 别的反应类的窗口，不是 `B-H` 自己的**。

## 三、这个结论意味着什么

| 之前的猜测 | 实测结论 |
|---|---|
| "引擎缺方向性" | **不完全是**：该反应时它 100% 能预测到（第三十二轮）；错的是"不该反应时也说能" |
| "自抽模板太激进" | **否**：假阳性里自抽模板 0 参与 |
| "条件层需要调参" | **不是调参问题**：它输出的是 3 个常数，**没有可调的东西** |
| "条件层没有数据"（初版结论，**错**） | **37 类全都有 ORD 条件数据**；病根是试剂检查用**固定名单字面匹配** |

## 三bis、★ 根因更正：不是"没数据"，是"名单太窄"（2026-10-13 补）

`tools\_probe_activation_branches.py` 实测：

| 项 | 实测 |
|---|---|
| 37 类里**有** ORD 条件数据的 | **37 类；无数据的 0 类**（初版说"7 类无数据"也是错的） |
| `B-H` 条目 | `n_ord_matched=786`；`temp_C` = [-78, 250]（中位 100）；`solvents` = [toluene, water, 1,4-dioxane, DMF, EtOH, EtOAc]；`auxiliary_reagents` = 6 个名字（triethylamine / potassium carbonate / cesium carbonate / DIPEA / water / sodium tert-butoxide）；`catalysts` = [Pd2(dba)3, Pd(OAc)2, BINAP] |
| 三个常数的出处（3,000 条真实条件） | `1.0` = 全对得上；**`0.5` = "条件里的试剂不在该类反应的 ORD 常用试剂里"→降权**；`0.6` = "溶剂不在 ORD 偏好"→降权 |

**机制**：那条试剂检查（`cond_activation` 的 auxiliary_reagents 分支）要求
"条件里写的试剂"能在**6 个固定名字**里字面匹配上。
HTE 用的是现代配体/碱（`tBuXPhos-Pd-G3`、`tAmOK`、`LiOtBu`、`LiHMDS`、`P2Et`…），
**一个都不在那 6 个名字里** → 全部被打成 0.5。

→ **27,497 行 HTE 被压成一个常数惩罚**，这就是 AUC=0.519、11 万次比较分数相同的直接原因。

**注意**：引擎里另有更强的检查（"缺必需试剂 -> 判零"，Mitsunobu 缺 DEAD 那种），
那条**没有被本问题污染**（实测 HTE 里它没触发）；出问题的是**降权 0.5 那条**。

## 四、下一步（用户 2026-10-13 已拍板：「3」= 两个都做）

| 序 | 做什么 | 验收 |
|---|---|---|
| **① 先修试剂检查（规则）** | 把 `cond_activation` 里"字面匹配 6 个固定名字"换成**按角色判断**（Pd-膦催化剂算不算金属；醇盐/胺/碳酸盐算不算碱） | 用同一套判卷器复测：activation 取值数、组内方差、**AUC 是否从 0.519 上去**；且 `test_required_reagent_gate.py` / `measure_reagent_gate_effect.py` 不得回退 |
| **② 再训 ML 学残差** | 规则修完仍有判别力缺口时，用 HTE 27,497 行（含 10,696 行零产率）训"条件可行性"模型 | **留出集 AUC** + 分组拆分防泄漏；只学规则修不动的残差 |
| **③ 顺带暴露 activation 来源** | 在查询式交互里标出依据（温度窗口 / 试剂角色 / 无数据），而不是只给一个 0.5 | 用户不再把"常数惩罚"误读成"判断" |

**边界提醒**：②③ 属**条件可行性门控**（判断该不该发生），**不是产品排序** ——
与"打分停工"的决定不冲突，但仍以①的验收数字为准：**先看规则能修到多少，再决定模型值不值得上。**
