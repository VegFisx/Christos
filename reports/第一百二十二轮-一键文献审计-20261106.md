# 第一百二十二轮：一键文献审计（`tools/audit_literature.py`）

日期：2026-11-06
背景：第 120 轮核了元数据、第 121 轮核了引句，是两个独立脚本；本轮把三步串成一条命令，
并给出可当门禁用的退出码。

## 0. 一句话

现在一条命令、约 100 秒，跑完「DOI 真的假的 → 标题期刊年份对不对 → 引句在不在原文里」，
退出码 0 表示**没有新问题**，1 表示**出现了需要处理的新的 DOI/引句问题**。

## 1. 用法

```powershell
python tools\audit_literature.py              # 完整（元数据 + 引句），约 100 s
python tools\audit_literature.py --quick      # 只查元数据，约 50 s
python tools\audit_literature.py -o reports\literature_audit.json
```

**只读**：不改任何证据文件。要把结果写回证据文件，仍用 `tools\apply_citation_check.py`（单独调用）。

## 2. 退出码语义（关键）

| 退出码 | 含义 |
|---|---|
| 0 | 没有**新**问题（已知的 3 条未注册 DOI 已在证据文件里标 `doi_valid: false`，不算故障） |
| 1 | 出现了新的「DOI 未注册」或「引句在可读文本里找不到」 |
| 2 | 脚本自身失败（网络全断、API 变更等） |

设计理由：如果把已知的 3 条未注册 DOI 也算失败，这个命令永远是红的，门禁就没意义了。
所以判据是"**新**问题"——证据文件里已明确标注、且写进报告的问题视为已登记。

## 3. 当前基线（2026-11-06 实测）

```
DOI 记录：verified 12 / metadata_mismatch 4 / not_found 3 /
          no_claimed 1 / verified_notitle 1 / not_in_crossref_resolvable 5
引句判定：verbatim 14 / minor_diff 1 / abstract_verbatim 6 /
          abstract_absent 2 / no_full_text 2

DOI 未注册（含已知 3 条已标 doi_valid:false）: 3
其中新出现（需要处理）: 0
致命（引句在可读文本里找不到）: 0
警告（元数据不一致 / 中文库 DOI）: 9
警告（只核到摘要 / 拿不到文本）: 4
退出码 0
```

- `not_found 3`：`10.7501/j.issn.0253-2670.2025.09.010`、`10.7501/j.issn.0253-2670.2026.06.008`（这两篇**文章确实存在**，见第 120 轮：出版社 PDF/摘要页可访问）、`10.13422/j.cnki.syfjx.20250561`（待查）。
- `not_in_crossref_resolvable 5`：中文库 DOI，doi.org 能解析、Crossref 不收录，属正常。
- `metadata_mismatch 4`：期刊名缩写差异（如 `J Ginseng Res` vs `Journal of Ginseng Research`），非错误。
- `abstract_absent 2` + `no_full_text 2`：4 条拿不到可读正文的引句（机制细节 2 条、1973/1983 旧刊 2 条）。

## 4. 本轮对 `verify_citations.py` 的改进

原来「Crossref 查不到」一律记 `not_found`，会让中文库 DOI 看起来像坏 DOI。
现在 Crossref 失败后会再用 `doi.org` 解析一次：

- 301/302/303/307/308 → `not_in_crossref_resolvable`（DOI 是真的，只是中文库不向 Crossref 报送）
- 其余（404 等）→ `not_found`（真未注册）

这个区分是第 120 轮 `apply_citation_check.py` 里手工维护 DOI 名单的自动化替代。

## 6. 还没做

2. `--quick` 只跳引句，DOI 解析仍要联网；离线环境下应直接读缓存 JSON。
3. 未接进任何自动化（如提交前钩子）；目前靠手动跑。
