# 第一百五十轮：学习型路线为什么停在 3.3%

> 一句话：把「产物原子集合」这个 oracle 拿掉之后，学习型单答案的精度从 36% 掉到 3.3%；
> 之前那些漂亮数字（30.9%、+4.0 pp、89.3% 上界）都站在同一个 oracle 上，不能当产品结论。

## 1 落差是怎么来的

`core/center_suggest.py` 一开始跑出 3.3%，但同一模型在带映射的官方反应上是 36%。
我按顺序排除了四个嫌疑：

| 嫌疑 | 验证 | 结论 |
|---|---|---|
| 特征口径与训练不同 | 直接复用 `build_center_dataset._atom_feat/_nbr_feat/_ord` | 不是（254/255 特征吻合） |
| 候选对集合不同 | `_diag/dbg_pairset.py` 用 oracle 限制成「产物里也出现的原子」 | 不是（仍 3.3%） |
| 比较口径不同 | `_diag/dbg_canon_match.py`：`_demap` 与 `canon_set` 97/100 一致 | 不是 |
| **施加时的原子白名单** | `_diag/dbg_whitelist.py`：全保留 vs 按产物原子集合删 | **是** |

`_diag/dbg_whitelist.py` 的两个数字：

```
keep every atom:     5/150 = 3.3%      # 真实部署条件
oracle atomic strip: 10/150 = 6.7%     # 允许偷看「产物保留哪些原子」
```

## 2 那 36% 是怎么算出来的

`tools/bench_center_official.py` 走 `_row()` 路径，它用**产物侧映射号**做两件事：

1. 决定保留反应物的哪些原子（把离去基团当残渣剥掉）；
2. 决定判等时分子里该有几个原子。

这两件事都需要**知道产物**。所以那 36%（以及 30.9%、并集 +4.0 pp、上界 89.3%）
里都混着「答案的原子集合」这个信息。把它拿掉，精度就是 3.3%。

这不是实现 bug，是**任务定义**的问题：键级编辑只能表达「保留全部原子的转化」，
而真实反应大量伴随原子离去（水解、脱羧、氧化断链）。
要么给模型一个「删除原子」的动作空间，要么改成生成式序列模型——两者都是天级工作量。

## 3 保留什么

- `core/center_apply2.py`（施加器）：**80.9%** 的上界是真的（不含任何 oracle），
  未来结构化模型可以直接复用。
- `reports/center_dataset_uspto.jsonl`（26,202 条带 RXNMapper 映射的反应）与
  `tools/map_uspto50k.py`（50,000 条全部映射，置信度中位 0.769）：数据资产。
- `core/center_suggest.py`：实验代码，**不接引擎、不加开关**。
- 负面结论：在「键编辑 + 逐对独立分类」这个表示下，学习型打不过模板路线
  （模板召回 92.19%、top-1 72.6%）。继续调这个表示的边际收益已经接近零。
