## 三、怎么判「这是种名还是药材名」

**不用正则猜。** 实测英文俗名 `Abyssinia Coralbean`、`Algerian Iris` 能骗过"两个大写单词"式正则。

改成：**拿 COCONUT 的 5.1 万种名当字典**比对，先严后宽四步：

1. 精确 —— 前两词原样命中
2. 拼写归一 —— `ae/oe→e`、`ph→f`、叠字母压缩、`y→i`
   （`Glycirrhiza` ↔ `Glycyrrhiza` 归一后都是 `glicirhiza`，直接命中）
3. 词集命中 —— 吃掉变种/亚种后缀
4. 近似 —— 同属候选里 difflib ≥ 0.88

去命名人：**只取前两个词**。因为 HERB 里写的是 `Glycyrrhiza Uralensis Fisch`——`Fisch` 后面
**没有句点**，按"去缩写"识别不掉。

自检 9/9 通过（`python sources/coconut.py`）：

```
OK  'Glycyrrhiza uralensis'         → glycyrrhiza uralensis  种名精确
OK  'Glycirrhiza uralensis'         → glycyrrhiza uralensis  种名拼写归一
OK  'Glycyrrhiza Uralensis Fisch'   → glycyrrhiza uralensis  种名精确
OK  'Radix et Rhizoma Glycyrrhizae' → (非种名)
OK  '甘草' / 'Liquorice Root' / 'Abyssinia Coralbean' → (非种名)
```

1. **本工作区 grep 必须带路径。** `rg -n "coconut" --glob "!libs/**"`（无路径参数）返回**空**，

### 9.8 ★ 「查找同名字段」做成开关（用户 2026-10-16 修正）

> 「设计一个查找的窗口，让用户**自由选择查不查找**输入这个字段，然后用户可以选择

我第一版把查找做成了**强制**（输入中文名只要同字段 ≥2 条就弹窗），用户纠正后改成**开关**：

| 状态 | 行为 |
|---|---|

| **勾**「查找同名字段」 | 先弹查找窗口，列出两组候选，你勾完再跑 |
| 拉丁**属名**（`glycyrrhiza`） | 无论勾不勾都弹窗口 —— 属名本身没有可跑的实体 |

窗口里的两组：

* **[药材]** —— HERB 里名字含该字段的全部条目（炮制品 / 同名 / 药用部位）。

  梅州甘草 / 欧亚甘草 / 圆果甘草 / 云南甘草 / 胀果甘草）。
* **[基元植物]** —— 上面这些**药材条目背后的物种**，`甘草` → 16 条

### 9.17 ★ 剂量 = 重复输入份数（用户 2026-10-16 截图提出）

> 用户原话：「如你所见，跑成分预测，通过这样的反复输入同种药材名，用户可以实现计量加权。
> 这样的功能可以添加嘛」

**先说今天的实际行为（有浪费）**：`build_inventory` 对 `spec.seeds` **不去重**（第 476 行），
所以同一个药材名输入 k 次 → 它的成分被当 k 批底物塞进去，**重复占用对子预算**、
而且还可能产出重复行。这不是"剂量"，是白烧算力。

**改成的语义**：**份数 = 输入次数**。

1. 桥接层先按名字统计份数（`doses`），**每个名字只取一次成分**（重复输入不再重复占预算）。
2. `selection[名字]` 增加 `n_doses` / `limit_effective`；`switches` 记 `dose_budget` 与整个 `doses` 表。
3. 打印与网页摘要都显示 `（输入 2 次 = 2 份）`；产物台账的来源标签带 `×2`。
4. **开关 `--dose-budget`（默认关）**：打开后该药材的成分配额 ×k ——「剂量大的药多带成分」。
   关掉时与旧行为一致（每味各取 `--limit` 个），只是份数照样记录。

**实测**（`--herb 甘草头,粗毛甘草,甘草头 --limit 3`）：

| 开关 | 甘草头 | 粗毛甘草 | 底物/对子 |
|---|---|---|---|
| 关（默认） | 输入 2 次 = 2 份 → 取 **3** 个 | 取 3 个 | 6 底物 / 15 对 |
| 开 `--dose-budget` | 输入 2 次 = 2 份，**配额 ×2** → 取 **6** 个 | 取 3 个 | 9 底物 / 36 对 |

**说清楚"加权"能是什么、不能是什么**：本系统是**枚举可能性**，不是算产率 —— 所以份数
只能用来①记录来源、②放大该药材的成分配额。**不能**拿它去"按浓度筛选/排序产物"，
那会跟"不打分、不排序、不删产物"的铁律冲突。要做"主次/产率"那是另一套模型（动力学/热力学）。

网页第 1 步新增勾选框「重复输入 = 剂量份数」；`ui.py` 透传 `--dose-budget`。

### 9.21 ★ C 项落地：中药的 OB 排序开关（用户 2026-10-16）

`--herb-order marker|ob`（默认 `marker`，与旧行为一致）。

* `marker` = 库标注指标成分优先 → 分子量降序（原样）
* `ob` = 按 TCMSP 的 **OB 降序**（无 OB 者靠后），并打印
  `254 个有 OB 值，其中 132 个满足 OB≥30% 且 DL≥0.18 —— 只排序，未做任何筛选`

实现落在 `herb.compounds_of_herb(order_tcmsp=...)`：SELECT 多取 `ob_score/drug_likelihood`
两列（顺带修了两处解包），给每个 Compound 挂 `ob/dl/tcmsp`；**只排序，不筛选**。
网页「每味取几个成分」旁边新增「成分排序」下拉。

⚠ 必须记住的口径：**OB/DL 答的是"能不能口服吸收、像不像药"，不是"含量高低"**。

### 9.22 ★★ 又一个危险 bug（本轮抓到）：方剂名子串把药材名劫走

### 9.25 ★★ 「库缺药材」的规模与解法：不用补库，加一条物种兜底通道（用户 2026-10-16）

> 用户问：「还有多少有这样的问题的药材？怎么解决？」

**规模（分层量，别被 74.6% 吓到）**：

| 层级 | 数量 |
|---|---|
| 别名表的规范名 | 8,022 |
| 其中不在 tcm.db | 5,982（74.6%）——**但绝大多数是《中华本草》收录的冷门植物** |
| ★ 用药典当尺子：药典 2025 收载药材（617 味）里库缺 | **52 味** |
| ↳ 其中现有规则已能落到基原（炮制品/加工品） | **40 味**（制何首乌→何首乌、姜半夏→半夏、大蓟炭→大蓟、南板蓝根→板蓝根、大皂角→皂荚…） |
| ↳ **真正缺的** | **12 味** |
| ↳ 12 味里药典正文有拉丁学名且 **COCONUT 有对应物种** | **8 味** |

**解法：不用补库，建一条「库外中文名 → 物种 → COCONUT」的兜底通道。**

`tools/build_herb_species.py` 从药典 md 的**正文**抽「中文药名 → 拉丁学名」
→ `data/herb_species.json`：**617 味里 547 条抓到拉丁、523 条在 COCONUT 命中物种**。

★ 这里踩了一个坑：药典**不写【来源】小标题**，拉丁学名直接写在
「本品为蓼科植物[[杠板归]] **Polygonum perfoliatum L.** 的干燥地上部分。」正文里。
第一版按 `【来源】` 找，实测 **0/400 命中**，看着像"药典没有学名"，其实是解析写错。

**接线**（`chemreact.py`）：HERB 路线取不到成分、**或只是"字面包含"匹配到近名字条目**时，
改用药典物种兜底。实测：

| 输入 | 之前 | 现在 |
|---|---|---|
| `杠板归` | 被"字面包含"匹配成**「杠板归根」**（另一种药材），4 个成分 | 药典正品 `Polygonum perfoliatum` → **14 个成分**，并打印"HERB 只匹配到近名字条目…改用正品" |
| `蓝布正` | 直接报未收录、**中止跑批** | `Geum aleppicum / japonicum` → **88 个成分** |
| `瓜子金` | 同上 | `Polygala japonica` → **82 个成分** |
| `甘草` / `白鲜皮` | 342 / 85 | **完全不变** |

分支才会把它设成 `"herb"`），导致下游所有 `route == "herb"` 的判断落空、
`selection[h].source` 也标错。已在 HERB 分支落定。

小驳骨（Gendarussa vulgaris，COCONUT 里没有）、艾片（冰片类加工品）、

### 9.26 ★★ 修正 9.25 的设计错误：炮制品就是炮制品，不许拆成基原（用户 2026-10-16 指出）

> 用户原话：「这样的规则不行吧，这些很明显有的对应的是炮制品的名字，而你直接给我对应到
> 基元上了。**炮制品就是炮制品，不要再映射了**。herb 数据库里有炮制品的化学成分信息，
> 药典也有。」

**我错在哪**：9.25 里我把"去掉炮制前缀能对上基原"当成了**已解决**（"40 味现有规则已能
落到基原，不用补库"）。这是把**两种独立药材**当成别名了 ——
`制何首乌`/`姜半夏`/`大蓟炭` 在药典里各有条目、各有自己的成分表，
换成 何首乌/半夏/大蓟 的成分是**换了一个东西**。

**修正：加一道"炮制品闸"**（`sources/processed.py` + `data/chp_processed.json`）。

炮制品清单怎么来的（**数据驱动，不靠我猜前缀**）：

1. 取名药典名录里的 617 味药材；
2. 带炮制标记（前缀 制/炙/炒/焦/煅/煨/蒸/煮/醋/酒/盐/蜜/姜/清/麸/土/米… 或后缀 炭/霜/曲）
   **且**去掉标记后仍是另一个药典药材 → 初判为炮制品；
3. ★ **第二道判据：必须与基原同物种**（用 9.25 建的药典物种映射）。
   这道判据当场抓出两个**危险假阳性**：

   | 名字 | 初判基原 | 物种对比 | 结论 |
   |---|---|---|---|
   | 土木香 | 木香 | Inula helenium vs **Aucklandia lappa** | ✗ 剔除（是两种植物） |
   | 土茯苓 | 茯苓 | Smilax glabra vs **Poria cocos** | ✗ 剔除（完全不同） |

   名字里的"土"不是炮制标记 —— 差一点就把两味不同的药合并了。

**最终 20 个炮制品**：制何首乌 / 制天南星 / 制川乌 / 制草乌 / 千金子霜 / 大蓟炭 /
姜半夏 / 巴豆霜 / 清半夏 / 炒瓜蒌子 / 炙甘草 / 炙红芪 / 炙黄芪 / 焦栀子 / 焦槟榔 /
煅石膏 / 绵马贯众炭 / 荆芥炭 / 荆芥穗炭 / 鹿角霜。

**闸门行为**（三处同时生效）：

| 情形 | 行为 |
|---|---|
| 库里有这一味（如 `炙甘草` = HERB006982） | **用它自己**的条目（11 个成分），不碰基原 |
| 库里没有（如 `姜半夏`） | 打印「⚠ 是**药典收载的炮制品**（基原：半夏）——炮制品就是炮制品，不替换成基原；本库暂无这一味」→ **中止跑批** |
| 出现在**方剂组成**里 | 只标注「方剂药材 X 本库暂无 → 本次跳过，其余照跑」，**不中止整方**（方剂是数据，不是用户打错字） |

`herb._resolve_herb_ids`（别名/模糊/前缀那几条）与 `formula._resolve_one` 都加了同一道闸。

**代价，如实记**：药典方剂组成的解析率 **98.2% → 97.5%**，差的就是那 **97 个 token**
（制何首乌 50、姜半夏 18、清半夏 15、制天南星 9、荆芥炭 3、炒瓜蒌子 1、大蓟炭 1）。
它们现在是**如实报「库缺」**，而不是被基原顶替 —— **这个下降是应该的**。
