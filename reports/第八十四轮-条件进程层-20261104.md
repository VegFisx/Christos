## 0. 一句话

以前条件只回答「这条反应**会不会**发生」，不回答「在 5 min 还是 24 h 下**跑到什么程度**」。
本轮补上第二问：同一条反应，在给定时间/温度/pH/催化剂下算出反应进程 `extent ∈ [0,1]`，
跑不到可检出程度（`< 0.10`）的产物不产出。**默认关闭**，所以既有一切数字逐位不变。

## 1. 先证明问题真的存在（实测，不是猜）

`_diag/diag_cond_sensitivity_A_20261104.py`：固定规则库（64 条非 disabled），
只改条件，看有多少条规则的激活状态翻转（阈值 0.15）。基准 = 煎煮 100 °C / 60 min / pH 6.5 / 无催化剂 → **49 条激活**。

| 改一个条件 | 翻转条数 | 分数变化 |
|---|---|---|
| 温度 25 °C | 28 | — |
| 温度 150 °C | 14 | — |
| 温度 250 °C | 30 | — |
| **时间 5 min** | **0** | **0 条** |
| **时间 1440 min** | **0** | **0 条** |
| pH 2 | 0 | 18/64（均值 0.078） |
| pH 12 | 1 | — |
| **催化剂 acid / base / metal** | **0** | **0 条** |
| 溶剂 none | 29 | — |

结论句（可直接引用）：**「5 min 与 24 h 的产物完全一样；催化剂完全不影响；pH 只影响 1 条规则。」**

代码侧根因：`core/smartreact_engine.py:1359 cond_activation()` 只做温度硬门 + 溶剂类别 + 必需试剂三件事；
`time_min` 与 `pH` 在 `core/smartreact_engine.py:698-713` 被读进 `cond_table` 后**从未被使用**。

另外发现一处**语义错误**（不是本轮引入）：`cond_activation` 的温度窗口来自 ORD「实际做过的温度」，
所以 250 °C 反而把 hydrolysis/esterification 判**关**（超出 ORD 上限），25 °C 反而把缩合判**开**。
这是「温度参与了、但方向不对」的证据，本轮没有改它——它属于激活层，改它会动所有既有基准，留作下一轮的独立议题。

## 2. 设计：extent 层

新增两个文件，全部参数在 JSON 里，代码不写死数字。

**`conditions/kinetics.json`**（`schema: chemreact-kinetics/1`）

| 参数 | 值 | 依据 |
|---|---|---|
| `q10.value` | 2.0（区间 1.8–3.0） | 教科书经验值，**建模选择** |
| `catalyst_speedup` | acid/base 10、metal 30、enzyme 100、photo 10、none 1 | 量级判断，**建模选择** |
| `ph.span` / `ph.floor` | 3.0 / 0.15 | 高斯衰减宽度，**建模选择** |
| `ph.optimum` | acid 2、base 12、neutral 7、acid_base 两侧最优 | 常识 |
| `gates.extent_min` / `extent_major` | 0.10 / 0.50 | 可检出 / 主要产物 的建模阈值 |
| `no_data_policy.extent` | 1.0 | 没有 ORD 条件数据的反应类，**保守放行**（宁可漏判不误杀） |

**`conditions/extent.py`**

```
e = 1 - exp( -(t / t_ref) · Q10^((T - T_ref)/10) · 催化剂倍数 · pH 倍数 )
```

参照点 `(T_ref, t_ref)` = 该规则 `condition_profile` 的默认温度/时间，定义 **e = 1 - 1/e ≈ 0.632**。
即「照着这条反应自己的典型条件做一次」= 63% 进程；时间加倍 → 86%；时间减半 → 39%。

**踩坑并修正（必须记住）**：第一版 pH 用**绝对值**（不归一），煎煮(100 °C/60 min/pH 6.5) 的 hydrolysis 只得 **0.139** ——
因为 `acid_base` 在中性落到 floor 0.15，等于把「中性水解本来就该发生」误杀。
改成 `f(pH) / f(参照 pH)`（参照 = profile 的 pH default）后 煎煮 = **0.632**。
理由写进 docstring：**参照点本身就该是「e≈0.63 的参照实验」**，所以 pH 必须按比值算。

## 7. 局限（别当成已经解决）

1. **参数是建模选择，不是实测拟合值。** `kinetics.json` 里每条都标了区间；没有用 ORD 的产率数据校准。
2. **只覆盖「已激活的反应」。** activation 那层的温度语义错误（ORD 覆盖范围当动力学用）**本轮没改**，
   所以「250 °C 把水解判关」依然存在；两层的口径要下一轮统一。
3. **催化剂只在条件里写了才加速**（`catalyst` 字段/试剂匹配），不会从辅料里自动推断。
4. **pH 只对声明了 pH_preference 的 profile 生效**；ORD 反应类里 **0/37 有 pH 数据**，所以走 cond_table 的路径 pH 一律不折减。
5. **extent 不参与打分与排序**：本轮只做「产出/不产出」+ 档位标记。是否把 extent 乘进 `scorer` 是下一轮的独立决定（会动所有排序与基准）。
6. **Web UI 未接**：`ui_page.html` 没有对应勾选框，目前只能走 CLI / `RunSpec.condition_extent`。
7. 炮制严格模式下 11 条证据规则全是单底物，extent 对它们的意义仅限「时间/温度是否够」；
   真正的辅料化学仍需有文献证据的双底物规则（场景层，按约定留到最后）。
