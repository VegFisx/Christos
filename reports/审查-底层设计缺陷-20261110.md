# 底层设计缺陷审查（2026-11-10）

> 触发：压力字段 `pressure_atm` 定义了却从没被读。用户要求排查同类「简单但致命」的错误。
> 方法：四个只读审计（条件层 / 数据层 / 引擎热路径 / 配置管线）+ 我自己实测复核。
> 结论：**同类错误还有 20 条**，其中 5 条会直接让对外数字失真。

---

## 0 一句话

最贵的一条不是压力，是**条件层里只有温度在起作用**：时间、pH、催化剂在默认路径上对产物集合完全无影响（实测：60 min / pH 6.5 与 5 min / pH 1.5 的 824 个产物逐字相同），而我们对外一直说「条件参与产物生成」。

---

## 1 这类错误的共通形状

| 形状 | 这次抓到的实例 |
|---|---|
| 字段/参数定义了，没人读 | `pressure_atm`、`concentration_M`、`cond_model` |
| 参数传了，路上掉了 | `--condition-extent` 没进引擎构造 |
| 开关存在，但真开关是另一个 | `CHEMCREACT_CONDITION_EXTENT` 覆盖了构造参数 |
| 用字符串/子串当判据 | `"降权" in why` 把「无降权」判成降权 |
| 静默过滤不报警 | 内连接丢 14.9% 边、`LENGTH>3` 丢乙醇 |
| 无 ORDER BY 就 LIMIT | 名称检索拿不到 ethanol / quercetin |
| 默认值不是中性值 | `DEFAULT_CONDITIONS` = 100 °C 水 |

## 2 A 级：会让对外数字失真

### A1 时间 / pH / 催化剂在默认路径完全不起作用 ★最贵

**证据（我实测）**
- 甘草 · `--limit 6 --rounds 1 --cond 煎煮` → **824** 个产物
- 同参数 `--time-min 5 --ph 1.5` → **824** 个产物，**集合逐字相同**
- 同参数 `--cond 室温浸泡`（25 °C）→ **752** 个产物（144 个只在 100 °C 出现）

即：**温度有效，时间与 pH 无效**，且 `extent` 列恒为 1.0。

**原因链（四处叠加）**
1. `integration/tcmai_bridge/chemreact.py:1081` 把 `--condition-extent` 写进 `RunSpec`；
2. `core/query_base.py:531-557` 构造 `SmartReactEngine(...)` 时**没有传** `condition_extent`；
3. `core/smartreact_engine.py:431-434` 只要 `CHEMCREACT_CONDITION_EXTENT` 存在就**覆盖**构造参数；
4. `core/smartreact_engine.py:1716-1719` 在 `gating_allowed()` 为 False（`kinetics.json` 的 `validation.gate_enabled=false`）时**强制** `extent_gate=False`。

**影响**：论文与 AGENTS 里「time / pH / catalyst 真正参与产物生成」（第 84 轮目标）在生产路径上不成立。界面三个页面上的「反应进程标注」勾选框是空操作。

### A2 台账「降权」统计把从不降权的记录算成降权

`core/query_base.py:1786-1789`：

```python
if ("降权" in w) or ("不在" in w) or ("超出" in w):
    return GATE_PENALTY
```

「ORD 条件窗口内，**无降权**」「按高温加速处理，**不降权**」都含「降权」子串 → 判成降权。正上方第 1772-1774 行的注释恰好写着「分类必须显式写，不能靠关键字碰运气」——注释写了，代码没改。

**实测**：14 条路径里 12 条被判「降权（86%）」，而同一份 CSV 里 `activation` 全是 1.0。

### A3 内连接静默丢掉 14.9% 的药材-成分边

`sources/herb.py:209-216` 的 `JOIN compounds c ON hc.ingredient_id=c.ingredient_id`：12,500 个 HBIN 编号在 `compounds` 里没有对应行，**16,461 / 110,686 条边消失（14.9%）**，2,435 / 6,452 味药受影响（白木香 97/228、丹参 76/338、没药 121/601、甘草 47/406）。`crawl_progress` 却显示这些药都是 done。**没有任何警告**。

### A4 小分子整类被过滤

`sources/herb.py:214`（另见 `:342`、`:381`、`core/query_base.py:1099`）的 `LENGTH(c.smiles) > 3` 去掉 28 个真实成分、100 条关联、79 味药：乙醇 `CCO`（乌梅、姜黄）、二甲硫醚 `CSC`（大蒜）、甲醛 `C=O`、氢氰酸 `C#N`、`Br`、`[B]`、`II`。而它**没有**过滤掉 102 行 `"Not Available"`（长度 13），所以另写了一串黑名单。

### A5 全大写 SMILES 被当成分子式

`core/query_base.py:1053-1058` 的 `_looks_like_formula` 正则命中所有全大写 SMILES：`CCO`、`CC`、`CO`、`CN`、`C1CC1`。`resolve_molecule("CCO")` 返回 `kind=分子式`，随后按分子式文本与 `CalcMolFormula` 比对 → **乙醇查不到**。

## 5 复核过、确认没问题的

- **确定性**：同一命令跑两次，1,294,438 字节的台账 SHA256 完全相同。
- **InChIKey**：`sources/` 与 `core/` 里没有 14 位骨架截断，全部用 27 位；骨架比较只出现在验证脚本里且显式声明。
- **配置层**：仓库里没有 `config.json` 之类的文件层，环境变量 > 硬编码默认，不存在「旧配置遮蔽新环境变量」。
- **闸门读者**：`release_gate.py` 读的键与四个基准脚本写的键逐一对应（`n_reactions`/`recall_1step`/`n_scored`/`top1`/`mrr`/`rate`/`cases[]`）。
- **单位**：ORD 温度统一摄氏（无 F/K 混入），时间统一分钟，所有温度进公式前都 `+273.15`。

## 6 建议修复顺序（未动手）

1. **A1**：让 `--condition-extent` 真的到引擎，把「判活」与「标注」拆成两个开关（当前合成一个）。
2. **A3 + A4**：数据层的两个静默过滤——先统计再决定丢不丢，丢了要报警。
3. **A2**：`classify_activation` 改成显式分类（注释里已经有正确设计）。
4. **A5 + B1**：SMILES/分子式判定顺序、名称检索加 `ORDER BY` 与精确优先。
5. **B2 + B3**：Evidence/别名取行的确定性（同一输入必须同一行）。
6. C 级按是否影响对外数字排：C3（原子守恒）、C1（共底物池）、C5（cap 单位）优先。
