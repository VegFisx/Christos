# 湿实验 / 文献数据接口规格（v1）

> 目的：把「真实样品里到底有什么」的数据，变成引擎能直接比对、能复现、
> 能进留出集的格式。数据来源可以是湿实验，也可以是文献抽取——两者用同一张表。
> 这份规格不碰规则、不碰引擎，只定义输入。

## 1 一行是什么

**一行 = 一个样品里的一个化合物。**

同一份样品测了 5 个成分就是 5 行；同一成分 3 个重复就是 3 行（用 `replicate` 区分）。
「未检出」也要有一行（`amount=0`，`detection=not_detected`），否则没法算转化率。

## 2 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `sample_id` | 是 | 样品唯一编号（湿实验：批次-时间点-重复；文献：DOI+表号+行号） |
| `source_type` | 是 | `wet_lab` / `literature` |
| `citation` | 文献必填 | DOI 或「期刊, 年, 卷, 页」；湿实验填实验记录编号 |
| `herb` | 是 | 药材名，必须能在 tcm.db 的 `name_cn` 或别名里找到；复方写 `formula:<方名>` |
| `template` | 是 | 条件模板名，与 `conditions/*.json` 一致（如 `煎煮`、`炮制·醋炙`） |
| `solvent` | 是 | 自由文本，但尽量用引擎词表：water / ethanol / acetic acid 6% … |
| `temp_C` | 是 | 数字；室温写 25；未知写空并在 `notes` 说明 |
| `time_min` | 是 | 数字；文献只给「蒸 3 小时」就写 180 |
| `pressure_atm` | 否 | 默认 1 |
| `atmosphere` | 否 | air / N2 / vacuum / steam |
| `replicate` | 是 | 1,2,3…；文献单次测定写 1 |
| `compound_name` | 是 | 原始名称 |
| `compound_id_type` | 是 | `inchikey` / `smiles` / `cas` / `name_only` |
| `compound_id` | 是 | 按上一列给；**优先 InChIKey**（tcm.db 里有现成的） |
| `role` | 是 | `marker`（原成分）/ `product`（产物）/ `intermediate` / `internal_standard` |
| `amount` | 是 | 数字；未检出写 0 |
| `unit` | 是 | mg/g、µg/mL、% 、relative（峰面积比）… |
| `method` | 是 | HPLC-UV / LC-MS / LC-MS/MS / GC-MS / NMR … |
| `detection` | 是 | `confirmed_standard` / `tentative_msms` / `tentative_uv` / `not_detected` |
| `lod` | 否 | 检出限，单位同 `amount` |
| `notes` | 否 | 流动相、柱子、文献表号、任何异常 |

## 3 采样设计（将来真做湿实验时的最小集）

- 药材 2–3 味，标志物清楚（甘草、丹参、黄芩这类）；
- 每味：原药材 + 1 个代表性工艺（水煎 100 °C；或醋炙/蜜炙）；
- 时间点：**≥5 个**（0, 15, 30, 60, 120 min）；
- 温度：至少 2 个（80 / 100 °C）；有条件的做 3 个；
- 每点 3 个重复 + 1 个空白（溶剂）+ 1 个内标；
- 每个样品测：标志物 + 引擎预测的前 5 个产物（按规则命中排序挑）；
- 结构确认：有标准品的用标准品；没有的用 MS/MS 比对，标 `tentative_msms`。

## 4 文献抽取口径（没有湿实验时的主要来源）

只收同时满足以下条件的文献行：

1. 写明药材、工艺、溶剂、温度、时间（缺一项就进不了条件层）；
2. 成分有明确结构（名称+分子式，或 InChIKey/SMILES/CAS）；
3. 有**定量或半定量**数据（含量、峰面积比、相对含量都行）；
4. 「未检出」也记录（amount=0）；
5. 图里读数只有在有坐标轴刻度时才允许，并在 `notes` 注明「digitized」。

不允许：把「某成分下降」直接当成「变成了引擎预测的那个产物」——那是两件事。

## 5 与引擎的对接

- 条件：`herb + template + solvent + temp_C + time_min + pressure_atm + atmosphere`
  直接填进 `Conditions`；
- 判命中：引擎在同样底物上生成的产物，与表中 `role=product` 的行按
  **InChIKey 前 14 位**比对；`name_only` 的行不能算命中；
- 判漏：`role=marker` 在产物侧完全没出现，且文献报告它下降 >50%；
- 留出：文献行按 DOI 整篇分组，同一篇不能同时进调参集和留出集。

## 6 能支持什么 / 不能支持什么

能：
- 确认某条规则在真实基质里是否触发（定性）；
- 在满足 §十二 要求时拟合 extent（同批样品、单温度 ≥5 点、≥3 温度）；
- 给引擎提供真正的留出案例（按文献分组）。

不能：
- 2 个时间点就谈动力学；
- 没有标准品就谈绝对产率；
- 只凭「母体下降」就断言某条具体反应路径。

## 7 文件与校验

- 存储：CSV（UTF-8，首行表头）或 JSONL（每行一个对象）；
- 校验：`python tools\validate_input_dataset.py <file.csv|file.jsonl>`；
- 校验只查格式与词表，不评价化学对错。
