# 第九十六轮：排序实验与「发射序」列为排序依据（2026-11-04）

## 0. 一句话

试了 support 先验：**对 top-1 没有帮助**；但顺带测出更值钱的一件事——
**引擎自己的枚举顺序（发射序）比我们手写的打分器更准**（top-1 42.67% vs 32.50%），
于是把发射序落成台账一列 `seq`，生产展示顺序改用它。

## 1. 怎么测的（口径先定死）

- 样本：`reports/paper/data/uspto50k_canon.jsonl` 按 seed 20261014 打乱后取前 3,000 条（与第 94 轮同一批）。
- 每个候选的字段：产物规范 SMILES、规则名、activation、模板 SMARTS、模板 support、引擎发射序。
- 先把候选**缓存**到 `reports/cand_cache_3000.jsonl`（`tools/collect_candidates.py`，265 s），
  之后所有排序公式都在缓存上离线比较（`tools/rank_experiments.py`，秒级），不再重跑引擎。
- 指标：recall_any（命中率，只与候选集合有关）、top-1/5/10、MRR。**所有公式 recall_any 相同**，只有排序不同。

## 2. 结果

| 排序方式 | top-1 | top-5 | top-10 | MRR |
|---|---|---|---|---|
| **引擎发射序** | **0.4267** | 0.6767 | 0.8003 | **0.5465** |
| scorer（旧生产口径） | 0.3250 | 0.5485 | 0.7094 | 0.4421 |
| scorer + support 先验 | 0.1635 | 0.3941 | 0.5025 | 0.2855 |
| 发射序 + 0.2×support | 0.2543 | 0.6874 | 0.8188 | 0.4431 |
| support 单独 | 0.1635 | 0.3977 | 0.5038 | 0.2870 |
| 非 mined 加成（权重网格最优） | 0.4065（调参半） | 0.6449 | — | 0.5227 |

权重网格（scorer / 发射序 / support / 非mined 四维，40 组，调参半挑、验证半报）最优也只有
top-1 0.4356（验证半），**与纯发射序持平，没有超过**。

## 3. 两个结论

1. **support 先验无效**：单独的 support 排序很差（0.1635），加权混进去会拉低 top-1。
   原因实测：`Product.template_support` 在这条路径上**根本是 0**——
   抽 40 条反应 805 个产物，`template_support>0` 的 **0 个**，但 `template_smarts` 805/805 都有。
   （support 只在 `core/smartreact_engine.py` 的三组分模板路径填 `product_support`。）
2. **scorer 是负资产**：手写权重（Tanimoto + 规则 priority + activation）反而不如「引擎枚举先后」。
   发射序隐含了「模板库按出现频次整理 → 先枚举的更常见」这个先验，比我们硬编码的权重更接近真相。

## 4. 做了什么改动

- `core/engine.py`：`Product` 新增 `seq: int = 0`（同轮内第几个被枚举出来）。
- `core/smartreact_engine.py::step`：产物入列表时 `_p.seq = len(out)`。
- `core/query_base.py`：`PATH_FIELDS` 加 `seq`；每条路径 `ent` 记 `seq`（同一 (规则,轮) 取最小）；
  台账/JSON 的展示排序从 `(round, rule_name)` 改成 `(round, seq, rule_name)`。
- `tools/bench_topk.py`：默认按发射序算指标，`--by-score` 保留旧 scorer 口径对照。
- `core/scorer.py`：保留 `support` 权重（未知时不影响任何数字），但**生产不依赖它**。

## 5. 回归

- `bench_topk --n 3000`：recall_any 0.9247（不变）、**top-1 0.4267**（旧 0.3250）、top-5 0.6767、top-10 0.8003、MRR 0.5465、候选 21.3、0 报错、260.8 s。
- 炮制 8 场景烟雾：43 / 43 / 46 / 43 / 81 / 43 / 43 / 824 —— 与第 89 轮新基线逐项一致（`seq` 只加列）。
- `tools/audit_mapped_safety.py`：ERROR 0 / WARN 13 / 自检 8 通过 0 失败。

## 6. 局限

- 发射序是**实现副产品**，不是化学判据；它可能只在「测试集与模板库同源（都是 USPTO）」时好用。
  换成天然产物/煎煮场景是否还准，**没有测**。
- top-1 42.67% 仍是「候选对但排不到第一」占多数；单靠排序提升有限，瓶颈在判据（热力学、反应中心）。
- support 先验要真正可用，得先让 `template_support` 在 mono/extra 路径填上，再重测——本轮没做。

## 7. 复现

```powershell
python -I tools\collect_candidates.py --n 3000 --out reports\cand_cache_3000.jsonl
python -I tools\rank_experiments.py --cache reports\cand_cache_3000.jsonl
python -I tools\bench_topk.py --n 3000              # 发射序
python -I tools\bench_topk.py --n 3000 --by-score   # 旧 scorer 口径
```
