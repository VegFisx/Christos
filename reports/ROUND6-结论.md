## 1. 先造工具，再写规则

手写 22 条新规则的正确 SMARTS + 配平系数，人肉推极易出错。
所以我先造了 **`tools/derive_co_reagents.py`** —— **让校验器反过来告诉我缺什么**：

```
配平要求   底物 + co_reagents == 产物 + byproducts
所以       co_reagents − byproducts == 产物原子 − 底物原子 == diff
```

diff 就是缺的东西：`{O:1, H:2}` → 补一个水；`{H:-2}` → 氧化脱氢或脱氢。

### 工具的第一件事是验证它自己

拿它跑已有的 24 条规则，**它独立推出的 17 条 `co_reagents` 与我第 1 轮手工推的完全一致**。
互为印证，说明工具可信。

### 过程中修了工具自己的两个 bug

| bug | 后果 | 修法 |
|---|---|---|
| 用 GCD 归一化差值 | `{H:-2}` 被压成 `{H:-1}`，4 条规则被误判"模式不认识" | **删掉归一化**——原始差值本身就是化学计量数 |
| 用 rdkit 原生引擎 | 与校验器（rdchiral）结果不一致，环内断键时算出错误差值 | 改用 rdchiral，与校验器对齐 |

## 3. ★★ 本轮最重要的教训：原子守恒可以被"编一个副产物"糊弄过去 ★★

我写的「分子内脱水成醚」（二元醇 → 环醚）产物 SMARTS 是：

```
[O:1]1[CX4:2][CX4:3][CX4:4][O:5]1
```

环是 `O1-C2-C3-C4-O5-O1` —— **含一根 O-O 键，成了 1,2-二氧戊环**。
二元醇脱水成环醚，环里只应该有**一个**氧。

**但它通过了自动校验。**

为什么？因为推导器为了让原子数对上，给它配了 `byproducts={'H2': 1}`（说这个反应产氢气）。
**数字完美对齐，化学完全错误。**

> ### 结论：**校验器是必要条件，不是充分条件。**
>
> 自动配平能挡住"漏写原子"，挡不住"产物本身就是错的"——
> 因为任何原子缺口都可以靠编一个副产物填平。
>
> 这条必须记住：**新规则上线前，除了跑校验器，还要人工看一眼产物结构是否合理。**

修法（1,4-丁二醇 → 四氢呋喃）：

```
反应物  [OX2H:1][CX4:2][CX4:3][CX4:4][CX4:5][OX2H:6]
产物    [O:1]1[CX4:2][CX4:3][CX4:4][CX4:5]1 . [OH2:6]
环      O1-C2-C3-C4-C5-O1    ← 5 元环，只有一个氧 ✓
```

修完**原生配平**（361 个底物 100% 配平），不再需要编副产物。

## 4. 工具抓出来的其它真错误

| 规则 | 工具判定 | 真相 |
|---|---|---|
| 内酰胺开环 | 无底物匹配 | 我的 SMARTS **少了一个碳**——γ-丁内酰胺是五元环，我只写了 2 个碳 |
| 酚酸脱羧成酚 | 无底物匹配（连水杨酸都不匹配） | **是重复规则**——已有的「芳香酸脱羧」`[c:1][CX3:2](=[OX1:3])[OX2H:4]` 本来就匹配所有芳香羧酸（含酚酸） |
| 硫醇偶联成二硫 | 无底物匹配 | **引擎的结构性限制**：成二硫需要两分子硫醇，而本引擎只支持单反应物规则 |
| 差向异构化 | 通过校验 | 但 SMARTS 两边**完全相同**，是恒等变换，不产生任何新分子——校验器抓不到这种错 |
| 硝基还原成胺 | ATOM_CREATION | 确认凭空造原子 H+3 O−2 |

**另一个教训**：「丙二酸型脱羧」被判定"无底物匹配"，我一度以为它写错了。
**手工探针一测（丙二酸、乙酰乙酸）全部配平**——只是 2500 个样本里恰好没有 β-二羰基酸。

> **"样本里没有底物" ≠ "规则是错的"。** 校验器只能证伪，不能证实。

## 5. 发现一个引擎的结构性限制

**本引擎只支持单反应物规则**（`static_checks` 明确拒绝多反应物模板）。

挡住了一整类重要反应：

| 被挡住的反应 | 为什么重要 |
|---|---|
| **酯交换** | 醇提（乙醇作溶剂）时非常关键——乙醇会和酯生成新酯 |
| 酯化（分子间） | 有机酸 + 醇 → 酯 |
| 醇醛缩合（分子间） | 碳碳成键 |
| 席夫碱生成 | 醛 + 胺 |
| 二硫键形成 | 两分子硫醇 |
| 糖苷化 | 糖 + 醇 |

而且技术上还有一个障碍：**rdchiral 的 `rdchiralRun` 只接受单个反应物对象**，
所以多反应物规则可能得回到 rdkit 原生引擎——那又会撞上环键复制原子的老问题。

**这是下一轮值得单独攻的一个点。** 攻下来的话，能再加 15~20 条高价值规则。
