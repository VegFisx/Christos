# 第一百五十一轮：候选级基准表（交接单 §9.1）

> 一句话：把 12k 反应 / 257k 候选 / 59 维特征 / 真值落成一张 8.7 MB 的 parquet，
> 一个新排序想法从「现搭数据集」变成 **1.7 秒出指标**；重放 `rank_model_v2` 的测试集数字
> 逐位相同（top1 0.7801 / top3 0.9563 / top5 0.9860，n=5584）。

## 1 做了什么

| 文件 | 作用 |
|---|---|
| `tools/build_candidate_table.py`（新） | 建表：流式读 `rank_dataset_v2.jsonl`，物化 29 维特征，回填反应元数据，写 parquet + meta |
| `tools/candidate_table.py`（新） | 读表 / 组装 59 维矩阵 / 反应级汇总 / top-k·MRR 评估 |

**反应元数据 100% 精确对齐**：按 `build_rank_dataset.py` 的洗牌与过滤规则复现 rid →
原始 USPTO 行，`replay=11996 / want=0 / none=0 / mismatch=0`，没有一行靠模糊匹配兜底。

## 3 两个顺带发现

1. **存 float32 会让同一模型掉 0.47 pp。** 首版表用 float32 存特征，重放只有 top1 0.7754；
   诊断（`_diag/probe_cand_precision.py`）显示特征最大差仅 4.8e-7（`log_sup`/`p_mw`/`s_mw`），
   但足以让梯度提升树的分箱边界挪位。改成 float64 后逐位复现。
   **规则**：凡是给模型喂的特征表，浮点一律 float64，别为省几 MB 降精度。
2. **`train_ranker_v2.evaluate` 的 MRR 被截到 top-5**（循环 `range(min(5, len(order)))`，
   第 6 名以后的命中不计入 MRR）。所以 pkl 里记的 0.8684 不是全序 MRR；同一批数据全序是 0.8702。
   本轮没有改它（改了会让已发布记录的指标变化），只在表里用全序并写进口径。
   若要统一，应单独一轮改并重训记录。

## 4 怎么用（新想法的标准路径）

```python
import candidate_table as CT
df, meta = CT.load()
X, names = CT.feature_matrix(df, meta)
CT.evaluate(df)                      # 发射序基线 0.4706
CT.evaluate(df, score=...)           # 换任何分数
```

计时（实测）：load 0.41 s / 建特征 0.12 s / 评估 0.03 s / 跑 v2 模型 + 评估 1.17 s，合计 **1.72 s**。
重建整表 39 s。

## 5 边界

- 表是**快照**：规则 / 模板 / 引擎一改就重建，否则评的是旧引擎。
- 只有 USPTO 12k 子集，不含 TCM。
- 956 个反应没有正例（`true_rank=-1`），评估按 `n_pos>0` 筛。
- 表能回答「同一个候选池里怎么排得更好」；**不能**回答「该不该发生」（AGENTS §11.8）。
