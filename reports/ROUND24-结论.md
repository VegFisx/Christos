## 3. ★ bug 一：产物归属随底物顺序变 ★

查下来：

```
产物集合: 153 vs 153  集合相同=True
★ 归属不同的产物: 23 个（15%）
```

同一个产物 SMILES 可能由**多个底物**产出，而代码是「**谁先产出谁记名**」：

```python
if p.smiles in exclude_smiles or p.smiles in seen:
    continue
```

**谁先，取决于调用方传底物的顺序。**

### 为什么这会毁掉整条链路

`source_smiles` 参与**打分**（一致性因子）→ 分数变 → 级联的**前沿选择**变 →
下游探索区域变 → **整条链路的输出都不可复现**。

### 修法

```python
for sub in sorted(compounds, key=lambda c: c.smiles):   # ← 加个排序
```

**效果：级联的对称差从 5 变成 0。**

## 4. ★★ bug 二：你看到的 Top-20 里有 3/4 是任意的 ★★

```
产物池 1293 个
不同分数值只有 120 个
★ 有并列的产物 1272 个（98%）
两种顺序的 Top-20 只有 5/20 相同
```

**多样性排序在并列时按列表顺序破平**：

```python
for p in remaining:                      # ← 按列表顺序
    adj = p.score - penalty * used[p.rule_id]
    if best_adj is None or adj > best_adj:
        best = p
```

而 98% 的产物存在并列 → **Top-20 里 3/4 由列表顺序决定**。

> 这是**用户直接看到的那一层**。而它有一大半是偶然的。

### 修法

```python
remaining = sorted(pool, key=lambda p: p.smiles)   # ← 先排序
# 只在【严格大于】时替换 → 并列时自然取 SMILES 最小的
```

### 效果

```
✓ 多样性排序与前序无关   首个相同=True  完全相同=True
```
