# 第九十四轮：泄漏检查 + 排序指标（92% 到底是什么）

> 一句话：92.01% 是**候选集合命中率**，不是预测准确率。
> 抽样 3,000 条实测：**top-1 = 42.67%**、top-5 = 67.67%、top-10 = 80.03%，平均 21.3 个候选。
> 泄漏方面：9,770 条基础模板的出处反应与 50,016 条测试集**完全相同者 0 条**；
> 命中所用的 mined 模板 support 中位数 **1,341**（86.4% 的命中靠 support ≥100 的通用模板）。

## 1. 泄漏检查（B）

脚本 `tools/check_template_leakage.py`，结果 `reports/template_leakage_20261104.json`，21.8 秒。

把 `libs/smartreact/data/templates.txt` 的 `example` 列（每条 mined 模板的出处反应，9,770 条，坏行 0）与测试集 50,016 条都做规范 SMILES 后比对：

| 口径 | 命中 | 占比 |
|---|---|---|
| A 底物集合 + 产物都相同（出处反应就是这道题） | **0** | **0.00%** |
| B 底物集合相同、产物不同 | 0 | 0.00% |
| C 底物侧有任意模板可用 | 0 | 0.00% |

C 也是 0 说明这不是「联表写错」的假 0：两边分子集根本不相交（模板产物重原子中位 30、测试产物中位 26，
大小相当，不是「小分子比大分子」的必然结果）。

**结论**：基础模板库没有逐字记住这 50,016 条反应。
但要说清楚边界——这只证明「没有相同的**分子**」；模板是 SMARTS，**类级**的「见过这类反应」无法排除，
而且这是所有模板方法的共性，不是本系统的特殊问题。

## 2. 命中的模板有多「通用」（B 的补充）

引擎的候选还来自 `reports/mined_forward_templates_full_s5.jsonl`（41,619 条，挖自 ORD，带 `support`）。
抽 200 条测试反应单轮跑（`tools/analyze_leakage_support.py`，16.2 秒）：

| 项 | 值 |
|---|---|
| 命中率 | **93.0%**（186/200，与全量 92.01% 一致） |
| 命中来源 | 基础模板 `templates.txt` **83** 条、mined_ord **103** 条 |
| mined 模板 support | 中位 **1,341**、p10 **56** |
| support ≤2 / ≤10 的占比 | **0% / 0%** |
| support ≥100 的占比 | **86.4%** |

**结论**：命中不是靠「只见过一两次」的窄模板，而是靠高支持度的通用反应规则。
support 中位 1,341 意味着这条模板在 ORD 里对应上千个反应——这是「会这类反应」，不是「记得这道题」。

## 3. 排序指标（A）

脚本 `tools/bench_topk.py`，抽样 3,000 条（seed 20261014，与全量同档配置），262 秒：

| 指标 | 值 |
|---|---|
| 候选集合命中（recall_any） | 92.47%（与全量 92.01% 对齐） |
| **top-1** | **42.67%** |
| top-5 | 67.67% |
| top-10 | 80.03% |
| MRR | 0.5465 |
| 命中位次中位数 | 2 |
| 平均候选数 / 中位 / p90 | 21.3 / 19 / 37 |
| 引擎报错 | 0 |

**怎么读**：给 20 个候选时，真产物有 92% 在里头；但如果只取第一个，只有 **42.7%** 对。
命中位次中位数是 2，说明「差一点」的情况很多——**这是排序问题，不是覆盖率问题**。

## 4. 结论：能不能说「有良好预测效果」

**不能按「预测准确率」说；能按「候选生成 + 排序」说，且排序是明显短板。**

| 说法 | 是否有数据支持 |
|---|---|
| 候选里 92% 含真产物 | ✅ 50,016 条全量实测 |
| 没有逐字记忆测试反应 | ✅ 严格同反应 0/50,016，命中模板 support 中位 1,341 |
| top-1 预测 43% | ✅ 3,000 条抽样实测 |
| 系统预测效果「良好」 | ❌ 需要 top-1 大幅提升 + 盲测 + 误报率 |

外部对照（只作量级参照，不是同口径）：模板/图方法在 USPTO-50k 上的 top-1 常见 50~90% 区间，
top-10 常见 85~93%。本系统 top-10 80% 属于偏下，top-1 43% 属于中下。

## 5. 排序为什么弱（可动的地方）

候选分来自 `core/scorer.py::score_product`，主要吃规则 priority、`activation`（条件匹配）、热力学与模板支持度。
已知可加但**目前没进分数**的强信号：

1. **模板 support**（已有，中位 1,341）：support 高的模板更可能是「常规反应」，应作先验加分。
2. **extent / 反应进程**（第 84-85 轮做的）：现在只用于门控，没进排序。
3. **规则族先验**：正向预测里 `mined_extra` 噪声大，curated 命中应优先。
4. **副产物惩罚**：原子丢失率（第 90 轮的 `atom_keep`）低于 70% 的候选应降权。
