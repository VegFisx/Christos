## 2. 两个真 bug

### 2.1 `.gitignore` 写错，把数据静默排除了

原文件里有一行 `data/`。这个写法会匹配**任意层级**的 `data/` 目录，正好命中 `reports/paper/data/`：
逆向模板库、USPTO-50k 规范化数据、官方 5,001 条切分全被忽略。

- 证据：`git check-ignore -v reports/paper/data/uspto50k_canon.jsonl` → 命中 `.gitignore:3:data/`
- 后果：首次提交 1,195 个文件里没有这些数据；克隆只有 **39.3 MB**
- 修法：改成锚定写法 `/data/`、`/ord-data/`、`/xtb_cache/`、`/repro-20261016/`、`reports/paper/data/uspto_mit/`、`*.parquet`
- 修后：克隆 **101.8 MB**

## 4. 脱敏子集库

TCM 侧三套验证（文献/炮制/方剂）需要 `tcm.db`（63 MB，不可整体分发）。用户同意后做子集：

- **`tools/build_tcm_subset.py`**：只读打开原库，按白名单选行，写出子集；
  **不复制** `crawl_progress` / `ingredient_progress`（内部爬取记录，与任何科学结论无关）。
- 结果：**17 味药 / 2,899 个成分 / 4,555 条药材-成分关联 / 1.96 MB**。
- 收录规则：17 味验证用药材的全部成分 + 已记录用例里出现的种子与目标（按 `ingredient_id` 白名单，避免「有名字但没结构」导致对不上）。

## 5. 让代码认子集库

新增环境变量 `CHEMCREACT_TCM_DB`，在 9 个位置生效（缺省仍是 `D:\TCMAI\tcm.db`）：

`sources/herb.py`、`sources/formula.py`、`sources/tcm_evidence.py`、`core/query_base.py`、
`tools/validate_literature_paths.py`、`tools/validate_literature_conversions.py`、
`tools/validate_paozhi_paths.py`、`tools/validate_paozhi_lit_conditions.py`、
`tools/validate_formula_decoction.py`。

补丁脚本 `_diag/patch_tcm_db_env.py`：每处替换断言「恰好命中一次」，改完逐个 `ast.parse`（避免静默改半截；本轮曾用 PowerShell `Set-Content` 把中文写坏过一次，已改回 write 工具并重写文件）。

## 6. 子集上的复现结果

```
python -I tools/validate_tcm_on_subset.py
```

| 验证 | 子集上结果 | 论文 |
|---|---|---|
| 文献路径（5 例） | **5/5 consistent** | 5/5 |
| 炮制（6 例） | **3 consistent + 3 formula_only**（Rb1/槟榔碱/乌头碱 一致；CATR/JNB/THSG 只到分子式） | 同 |
