## 三、★ 必须知道的三个副作用（这是本轮最重要的部分）★

### 1 【实测】`mined_extra` **完全绕过条件门控和必需试剂判零**

`cond_activation()` 的第一条分支：`cond_table` 里查不到该反应类型就 `return 1.0, "无 ORD 条件数据，放行"`
（`core/smartreact_engine.py:476-478`）。而 `mined_extra` **不在** 37 类 ORD 条件表里，所以：

- 温度超出实测窗口 → **不判零**
- 溶剂完全不符 → **不降权**
- 缺必需试剂 → **不判零**（走的是 `reaction_name` 分支，mined_extra 没有 aux 数据）

**后果**：这 590 条模板吐出的产物，无论条件怎么变都会照常出现。这与 HTE 上「负例产物 +36%」是**同源**现象；
也意味着当前正在推进的**条件感知判据对自抽模板完全无效**——它加进来的正好是门控之外的那部分产物。

### 2 【推断（基于代码路径），有实测旁证】单对产物上限实质翻倍：8 → 最多 16

`max_products_per_pair=8` 的截断发生在 **每个 `ReactionResult` 内部**（`core/smartreact_engine.py:599-602`），
而自抽模板的全部产物被合成**一个独立的 `ReactionResult`**（`reaction_name="mined_extra"`，第 285-291 行）。
所以单对理论上限 = 8（SmartReact）+ 8（自抽）= 16。
**旁证**：小分子 6 对产物由 5 → 10（翻倍），与推断方向一致。

### 3 【实测（按代码路径逐个判定）】哪些工具的输出会跟着变

| 工具 | 是否受影响 | 说明 |
|---|---|---|
| `integration/tcmai_bridge.py:71` | **是（有意）** | 生产路径，默认开正是本轮的意图 |
| `core/smartreact_engine.py` `__main__` 自检 | 是（有意） | 自检应反映默认行为 |
| `tools/test_condition_gate.py` / `test_reagent_gate.py` / `test_required_reagent_gate.py` | 是 | 仍然全绿；输出里新增 `mined_extra` 类型 |
| `tools/fpr_probe_on_negatives.py` | 是 | 它 `eng.step()` 枚举 |
| `tools/measure_cascade_growth.py` | 是 | 它 `cascade(eng, ...)` |
| `tools/hte_negatives.py` | **否** | 只取 `eng.cond_table` + 调 `cond_activation`，**不枚举** |
| `tools/hte_condition_model.py` | **否** | 同上，不枚举 |
| `tools/hte_fpr_after_integration.py` | 否 | 显式传路径与 min_support，自带 mined_K5 / mined_K1 两组 |

**所以**：交接文档里的 `假阳性 94.9% / 强反例 93.1% / 召回 64.0% / AUC 0.530 / 0.592 / 0.646`
**仍可原样复现**（它们是「K1 关闭」口径）；「K1 开启」口径用 `tools/hte_fpr_after_integration.py` 的
`mined_K1` 行（召回 64.0% → 69.2%，负例产物 1.38 → 1.87/对）。
**两个口径别混着引用**——这是本轮最容易出事的地方。
