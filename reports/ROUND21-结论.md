## 2. 量清原因：邻位 vs 对位

```
醌类：两个 C=O 碳之间的最短键数
  邻苯醌 / 1,2-萘醌       1 个键   → 现有 SMARTS 匹配 ✓
  对苯醌 / 1,4-萘醌       3 个键   → 不匹配 ✗
  9,10-蒽醌 / 大黄素      3 个键   → 不匹配 ✗
```

**蒽醌的两个 C=O 在 9、10 位，中间隔着环碳，相距 3 个键；
而现有 SMARTS `[O]=[C][C]=[O]` 要求两个羰基【直接相连】。**

**所以缺的是「对位（1,4-）」这一整类。**

## 3. ★ 中途踩到一个 SMARTS 陷阱：默认键 ★

写对位规则时，第一版对苯醌**一条都匹配不上**。查出来：

```
对苯醌的环：C1-C2=C3-C4（单-双-单 交替）

SMARTS 里不写键符号时，默认是【单键或芳香键】：
    [C:2][#6:5][#6:6][C:3]
          ^^^^^^ 要求这里是单键，但实际是双键 → 匹配失败
```

**这是本项目的第 5 个 SMARTS 陷阱**：

| 陷阱 | 表现 |
|---|---|
| `[C:]` 只认脂肪碳 | 酚苷/酚酯全不匹配 |
| `[CX4H:3]` 氢数写死 | 乙醇/乙醛/丙酮不匹配 |
| **默认键只认单键** | **跨双键的路径匹配失败** |

### 修法：反应物用 `~`（任意键），产物**不能**用

```
反应物 ~ + 产物 ~      → 匹配上了，但产物分子式【多 2 个氢】
                          （~ 让 RDKit 不敢判定芳香性，给碳补了氢）
反应物默认 + 产物默认   → 分子式对，但对苯醌匹配不上
反应物 ~ + 产物默认     → ★ 命中 6/6 ★
```

## 4. 新增两条规则（61 → 63）

| 规则 | SMARTS | 用途 |
|---|---|---|
| **对二酚氧化成醌** | `[OH:1][c:2][c:5][c:6][c:3][OH:4]>>[O:1]=[C:2][c:5][c:6][C:3]=[O:4]` | 对苯二酚→对苯醌、蒽氢醌→9,10-蒽醌 |
| **对醌还原成二酚** | `[O:1]=[C;r6:2]~[#6;R:5]~[#6;R:6]~[C;r6:3]=[O:4]>>[OH:1][c:2][c:5][c:6][c:3][OH:4]` | 对苯醌→对苯二酚、9,10-蒽醌→蒽氢醌 |

```
✓ 对苯醌     → Oc1ccc(O)cc1            [C6H6O2]

✓ 大黄素     → C15H12O6
✓ 辅酶Q0型   → C8H10O2
✓ 排除 邻苯醌、四氢邻苯二甲酸酐、邻苯二甲酸酐、乙酸酐、甾体3,6-二酮
→ 10/10
```

## 5. ★ 我自己的扫描立刻抓到了新规则的问题 ★

新规则加进去之后，八项扫描**马上报了三处**：

| 扫描 | 报告 | 处理 |
|---|---|---|
| 原子守恒 | 对醌还原 UNBALANCED（酸酐/1,4-二酮过度匹配） | 加 `[C;r6:2]` 六元环约束 |
| 化学合理性 | 对二酚氧化的副产物写成 `H2`，与库内其它氧化规则不一致 | 改为 `O2/H2O` |
| 探针矩阵 | 对醌还原 0 命中（矩阵里没有对苯醌） | 补 4 个醌/酚探针 |

**闸门系统起作用了。**

### 六元环约束：从 2 例降到 1 例

```
真醌的两个 C=O 碳都在【六元环】上
四氢邻苯二甲酸酐的在【五元环】上   → [C;r6:2] 精确排除
```
