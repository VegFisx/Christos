## 设计口径（待实施）

1. **域判定**：中文 / 拉丁 / SMILES / 方剂名 → 只在对应域里搜
   （引擎已有这条判定顺序：药典部位词 → 种名 → 属名 → HERB；现在只是没在查找框里显式化）。
2. **粒度递进**：
   * 拉丁：全名 → 属名 → 种加词 → 拼写近似（`uralensis` 走到第三级，**先给"共 N 个物种"**）；
   * 中文：正名 → 别名（多候选）→ 前缀/后缀 → 近似。
3. **来源分档**（关键，按权威度，不按字母）：
   * ① 药典收录（617 味药材 / 1,526 方）→ ② 库内药材（6,450 味，有成分）→
     ③ COCONUT 物种（51,608）→ ④ 别名/异名。
   每档先给**计数**，默认只展开前 5 条 +「还有 N 条」。
4. **排序依据**：药典 marker 数 / 成分数 / 是否出现在方剂中（**不是**字母序，也不打分）。
5. **顺带收益**：把「未收录」变成解释 —— `uralensis` → 「COCONUT 有 3 个物种，其中 1 个对应药材 甘草」。
