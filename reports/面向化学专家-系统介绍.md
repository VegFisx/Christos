# 面向化学专家的系统介绍（2026-10-14 版）

> 一句话：这是一个从公开反应数据（ORD）长出来的**通用有机反应预测 / 逆合成框架**。
> 它不评分、不排序、不隐藏证据：把分子和条件喂进去，它穷举候选产物/路线，
> 给每一步打上**可追溯的标记与出处**，由化学家来判断。
> 本文写清三件事：①最初的设想（要什么、不要什么）；②系统现在是什么、做到哪；③明确承认的不足。
> 所有数字均为仓库内脚本实测、可复现（新会话重跑脚本能得到同样的数）。

---

## 一、原始想法（为什么这样做）

1. **目标**（用户原话）：
   * 「我要做**通用化学 AI**；煎煮条件等在底层框架最后彻底完成了再补充。」
   * 「先建起来一个**通用性更强**的 AI，然后再在此基础上**用现实的条件去约束反应条件**，
     使其能够完成**产物预测**。」
   即：先把"化学本身"的通用框架做扎实（先不掺任何具体场景），再把真实条件
   （溶剂/温度/试剂/催化剂）作为约束叠上去，最终回答两类问题：
   **给底物+条件 → 可能得到什么**；**给目标分子 → 怎么造**。
2. **三条自己定的纪律**（影响一切设计取舍）：
   * **不打分、不排序、不删产物**（"打分排序停工"）——系统的角色是"生成 + 标注 + 留证"，
     不做未经检验的偏好判断；
   * **一切结论用实测数字说话**，推断必须标注来源；每个数字都能用脚本重算；
   * **场景最后做**：任何只为某个具体场景（煎煮/炮制/某味药）服务的东西，都不进当前框架。

## 二、系统是什么（架构）

两个方向 + 一层条件 + 一套质量基础设施。知识全部来自公开数据：
本地 ORD 全库 **1,771,032 条**原子映射反应；COCONUT 天然产物 **269,105**；
tcm.db 中药成分 **31,646**；ORD 反推的可购砌块 **32,146**（另骨架 30,236）。

### 2.1 正向引擎（底物 + 条件 → 候选产物）

* 规则来源：SmartReact 正向模板 9,770 条 + 自抽单组分模板 903 条（从 ORD 反应中心抽出）；
  三组分模板 2,443 条（默认关，见不足③）。
* 级联枚举：逐轮扩展，**轮数由使用者掌握**；每条产物完整记录出处（哪条规则、来自哪个底物、第几轮）。
* **方向层**：每个产物自动标注 方向明确 / 方向可疑 / 方向未定 / 平衡，附判据与理由；
  判据包括规则表、引擎自带的可逆性知识、以及**可计算的形状判据**
  （脱水/水解形状由元素收支与副产物直接算出，不依赖模板出处）。
* **条件层**：ORD 实测条件窗口（温度/溶剂）、必需试剂门控、条件可行性模型
  （在 HTE Buchwald–Hartwig 27,497 条记录上训练；输出 p/档位/分布外标记；只打标记，不删不排）。

### 2.2 逆向引擎（目标分子 → 路线）

* 规则来源：从 ORD 反应**逆向抽取**的 rdchiral 模板 3,025 条（带原子映射）；
  搜索终止集合 = 可购砌块 / 天然产物库 / 受限池（可自定义）。
* 每一步做**正向回验**（把前体喂回正向引擎，确认真能产出目标）。
* **"假路线"判据 R1~R4**（质量核心，全是显式规则、可审计）：
  * R1 残基路线：前体≈目标本身（"把目标换个基团再变回来"）；
  * R2 前体反而更大（逆向放大，不是拆解）；
  * R3 惰性小分子前体（≤2 重原子，如给已有骨架加甲基）；
  * R4 荒谬前体（CO2/无机小分子当骨架来源）。
* 每条路线标注"可用 / 不可用 + 原因"；**不删、不排序**。

### 2.3 质量基础设施（最近 5 轮的重点）

* **模板体检**：3,025 条逆模板 × 56 个目标逐一实测——找出 54 条"从没产出过可用路线"的惯犯，
  它们占全部无效尝试的 **83.8%**；做成**默认关的黑名单**（现行 51 条生效 + 3 条经留出复测豁免
  + 3 条"全等 no-op"）。开关实测：3,025 → 2,971 条模板。
* **留出泛化复测**：COCONUT 随机抽 64 个**新**目标复跑黑名单——命中者 **94% 仍然零可用**
  （泛化成立）；3 条"复活"者（交内复分解、炔→烯加氢型）已按证据移出名单。
* **可得性例外**（化学上关键的一条）：R1 只在前体**不可得**时才判假；前体买得到时
  （如"买炔烃 → 选择性加氢"）就是正当终步。
* **模板出处还原**：3,228/3,228 条逆模板全部对上 ORD 出处（9,177/9,177 个反应串命中，
  并附 reaction_id）——任何一条规则都能追到它来自哪些真实反应。
* 全部查询有台账、有证据回流；自检 30 项、安全审计 0 ERROR。

## 三、现在做到哪（关键实测数字）

| 指标 | 数字（实测） | 口径 |
|---|---|---|
| 逆合成"化学可用率"（56 目标体检） | **2.72% → 16.74%** | 黑名单开关前后；分母 = 模板产出的全部单步切断 |
| 无效尝试削减 | **-83.8%**（24,871 → 4,039） | 同上 |
| 黑名单泛化（COCONUT 64 留出目标） | 命中者 **94% 仍零可用**（50/53） | 新目标、非训练样本 |
| 逆模板溯源覆盖率 | **3,228/3,228（100%）** | 每条模板 → ORD 反应（含 reaction_id） |
| R1 判据标定（以 MCS 为参照） | precision **0.976** / recall **0.900** | 2,090 对 12~30 重原子分子，元素重叠比 ≥0.95 |
| 正向方向层（甘草 demo，552 条路径） | 449 可疑 / 103 未定 | 逐产物标注、附理由 |
| 终止集合规模 | 277,268（COCONUT+tcm 去重）+ 砌块 32,146 | 逆合成"买得到"的近似定义 |
| 回归 | selftest 30/30 · 安全审计 0 ERROR | 每次改动后必跑 |

（正向示例：芳基溴 + 苯胺 → 系统给出候选产物，同时标注
`条件模型 p=0.916（高）[分布外:4]`、`方向：明确（需专用催化剂与配体）`——
即：候选连同"这个判断有多可靠"一起交给你。）

## 四、不足（明确承认）

1. **逆向的"假路线"只解决了一部分**。清完惯犯后，样本上剩余的无效切断仍有 **~82% 是 R1 残基路线**，
   集中来自 8 条"编辑型"模板（加氢/维蒂希/甲基化/烷基化这类"只差两个氢/一个基团"的逆用）。
   现行处理 = 可得性例外 + 黑名单；对"近似相同"的根识别仍不够稳。
2. **判据本身不稳定**。R1 在中等分子上依赖"限时 MCS 比对"：实测 88 次调用里 **68 次超时**
   （更早在天然产物级分子上 **94% 超时**）——**同一分子换台机器可能换结论**；
   另有"环上盲区"：90 条判可用的里有 **58 条**其实元素组分完全覆盖目标（按判据本意应判残基）。
   确定性修补（元素覆盖比）已设计且实测可行，但按与使用者的约定暂缓（当前只做"完全相同"口径的清理）。
3. **正向"生成 ≠ 正确"还没有端到端数字**。近期未在留出反应上测"底物+条件 → 真产物"的整链准确率；
   过预测程度未知。条件可行性模型目前只覆盖 Buchwald–Hartwig 一类，其余走规则层。
4. **条件层薄**。ORD 条件窗口覆盖面有限，"无数据放行"比例不低；催化剂只按名字归一。
5. **模板覆盖面**。三组分模板 94% 只见过一次（support=1，可信度低）；三组分模式慢约 40 倍、默认关；
   立选择性/区域选择性信息基本没有。
6. **"可用集合"是近似**。"在 COCONUT 里存在" ≠ 现实可购；真正接近"买得到"的代理是
   ORD 反推的砌块表（3.2 万条）。终止判断因此系统性偏乐观。
7. **无产率、无热力学定量、无排序**（设计使然，非遗漏）。系统能回答"可能有什么 / 怎么走"，
   不能回答"该选哪条"；这需要等真实条件数据富集后再补一层。
8. 工程债（与化学无关）：部分历史脚本仍以读写方式访问 tcm.db（迁移只读中）；个别流程对环境有特定依赖。

## 五、给化学专家的"使用姿势"（怎么验它）

* 问"**这批底物能不能做出目标 X**"：受限池问答——池 = 你给的分子表；
  输出每一步"在池内/不在池内 + 可用性判定 + 原因"。
* 问"**这个分子在什么条件下会变成什么**"：正向枚举 N 轮，看产物台账
  （方向标注、条件依据、完整出处全在表里）。
* 所有输出**只标注、不删减、不排序**；若认为某条判定不对，直接改判据表或名单——
  改完用同一套脚本立刻复测"前后数字"，全程留痕。

## 六、2026-10-15 新增：药典判据链（"为什么它排前面"有了出处）

**问题**：成分进批的先后此前依赖"名字关键词表 + 分子量序"这类启发式——化学人有权
问一句"凭什么是这几个"。

**做法**：把《中华人民共和国药典》（2020 一部）的**含量测定**（Tier-0，带限量）
与**鉴别对照品**（Tier-1）做成结构化表，再逐行对齐到成分库（只读）：

* 全链路三脚本（可复跑）：`build_chp_markers.py`（docx→行+原文段号）→
  `curate_chp_markers.py`（OCR 定名/药材-饮片分段/去重）→ `chp_link_to_db.py`
  （中文名→库；分子式路线兜底；多异构体按 marker 名单二次判据，仍不确则弃置）。
* **覆盖（实测）**：连接 3,661 行、命中 1,536；**药材覆盖 339/438 = 77%**——
  剩余为矿物类（48）、聚合指标型（17）、扫描件丢字（13）、一次性残片（~21），
  属数据源与判据定义的天花板，非流程缺口。
* **消费方式**：开关 `--chp-priority`（**默认关**）：打开时 Tier-0 > Tier-1 > 其余，
  同层按**药典原文限量值降序**；每条排序都带出处段号，写进运行留证（meta/报告）。
* **边界**：药典文本仅内部研究引用、只提取事实并标出处；开关不影响枚举、不删产物、
  不打分——它是"有出处的排序"，不是"正确性判断"。
