## 二、哪些慢得有理，哪些是水分

### ✅ 慢得有理由的

| 项 | 耗时 | 为什么 |
|---|---|---|
| ① 原子守恒 | 146s | **15.75 万次**规则应用（2500 底物 × 63 规则），每次调一次 rdchiral（≈0.77 ms）。这是"穷举"的代价 |
| ⑧ 热力学集成 | 117s | **真的在跑量子化学计算**（xTB `--ohess` 频率计算）。单个分子几秒到几分钟，这是物理决定的，不是代码慢 |
| ⑩⑪ 跨进程审计 | 95s | 必须把脚本**在独立进程里跑 5~6 遍**——这正是它能抓到 `PYTHONHASHSEED` 问题的原因 |

### ❌ 是我的问题

1. **我每次都用"发布级"参数**（`--limit 2500`）
   但绝大多数时候只需要抽查 300 个底物就能发现问题。
   **我拿发布前的完整验收，当成了日常检查。**

2. **①③⑨⑩⑪ 在重复跑同一批"规则×底物"**，彼此之间没有共享缓存

3. **热力学集成每次都真算 xTB** —— 日常检查用缓存就够

## 三、于是加了「快速模式」

```powershell
python tools\check_quick.py       # 131 秒
python tools\summarize_defenses.py  # 完整版，9 分钟
```

### 设计原则：**不降低判据的严格程度，只缩小样本量**

| | 完整版 | 快速版 |
|---|---|---|
| 原子守恒 | 2500 底物 | 300 底物 |
| 立体化学 | 1200 底物 | 200 底物 |
| 跨进程审计 | 5~6 次 | 3 次 |
| 各审计的输入 | 3 味药 × 15 | 1 味药 × 8 |
| **通过/失败判据** | **完全相同** | **完全相同** |

> 快速版红了 → **一定有问题**。
> 快速版绿了 → 大概率没问题，**但发布前仍要跑完整版**。

## 四、所以「正常吗」的答案

**如果你问的是"这 9 分钟正常吗"：**

- **方向正常**——穷举 15.75 万次反应、真跑量子化学、跨进程跑 10 遍，这些本来就该花时间
- **但也确实有水分**——我把发布级的强度用在了日常检查上

**如果你想问的是"为什么要反复做这么多检查"：**

因为**这些检查真的抓到过东西**，而且是只有它们能抓到的东西：

| 轮次 | 检查 | 抓到什么 |
|---|---|---|
| 24 | 确定性审计 | 前沿采样按插入顺序 → 级联只有 22% 自重叠 |
| 24 | 确定性审计 | 排序并列按列表顺序 → **用户看到的 Top-20 有 3/4 是任意的** |
| 26 | 跨进程审计 | rdchiral 用 set → **同一脚本每次跑结果都不同** |
| 34 | 跨进程审计 | 时间预算 → 结果依赖机器负载 |
| 34 | 热力学测试 | 水解反应 ΔG 符号错 → **系统性压低糖苷/酯水解产物** |

**这些都不是"看一眼就知道对不对"的问题，只能靠跑。**
