# 第二十二轮：最大的通用性缺口 —— 是我们自己 filter 掉的 22%

> 2026-10-12。承接第二十/二十一轮：37 类模板库全是**合成偶联**化学，而煎煮/天然产物最需要
> **水解 / 氧化 / 还原 / 消除**。本轮去查"这些化学为什么没有"——**答案是我们的挖掘脚本把它们整类跳过了。**

---

## 一、证据链（三步，全部【实测】）

### 第 1 步：模板元数普查（`tools/probe_template_arity.py`）
| 来源 | 需要 1 个反应物 | 2 个 | 3 个 | 4 个 |
|---|---|---|---|---|
| **SmartReact 官方库**（9,770 条） | **0** | **9,770（100%）** | 0 | 0 |
| **我们自抽**（5,670 条） | **0** | 5,308（93.6%） | **348** | **14** |

→ 单反应物模板在库里是 **0 条**。但 ORD 里明明有大量单底物反应 —— 所以**不是"库里没有"，是"我们没做"**。

### 第 2 步：定位过滤条件（`tools/forward_template_mining.py:473-476`）
```python
raws, plains = mc.contributing_components(lhs, pmaps)
if len(plains) != 2:
    skip[f"贡献组分={len(plains)}"] += 1
    continue
```
**只挖"恰好 2 个贡献组分"的反应 → 单底物反应被整类跳过。**

### 第 3 步：脚本自己的跳过统计（`reports/forward_template_mining.json`，40,000 抽样）
| 跳过原因 | 条数 |
|---|---|
| **贡献组分=1（单底物）** | **8,745（21.9%）** |
| 贡献组分=3 | 2,927 |
| 贡献组分=4 | 560 |
| 贡献组分=5 | 116 |
| 贡献组分=6/7 | 19 |
| 重复 | 747 |
| 产物重原子过大（>70） | 1,593 |
| 产物 SMILES 非法 | 2 |

**→ 单底物化学占 ORD 的 21.9%，一条都没挖过。**

## 二、这 22% 是什么化学？

对照第二十一轮的元素收支普查（全表）：**还原 7.5% · 异构化 2.4% · 氧化 1.2% · 水解 0.3% · 脱羧 0.3%**
—— 这些**绝大多数是"单底物 + 试剂"**（NaBH₄ 还原、氧化、水解、脱羧、异构化……），
正是被 `贡献组分=1` 这条 filter 排除掉的那一批。

**★ 换句话说：我们缺的那几类化学，不是"数据里没有"，而是"被自己的口径挡在门外"。**
（第二十一轮说"水解只有 0.3%"仍然成立——那是**水解本身**在 ORD 里少；
但**单底物这一类**整体有 21.9%，里面包含还原/氧化/消除/脱羧等。）

## 三、顺带发现的第二笔现成损失

自抽模板里有 **362 条是 3~4 反应物**的（占 6.4%），而 `tools/rdkit_template_lib.py::compile_templates()`：
```python
if rx is None or rx.GetNumReactantTemplates() != 2:   # 只收恰好 2 个反应物
```
→ **这 362 条每次加载都被静默计入"编译失败"**（第十六轮报告里那句"编译失败 10"只是其中很小一部分；
K1 档 600 条里失败 10 条是这个 filter 造成的）。

## 四、因此"通用性"的正确下一步（按性价比）

| 优先级 | 做什么 | 依据 |
|---|---|---|
| **P1** | **挖掘单底物模板**（放开 `len(plains) != 2`，专门产出一条 arity=1 的模板流） | 21.9% 的 ORD 记录卡在这；本轮已建独立挖掘器（见 §五） |
| **P1** | **引擎支持 arity=1 模板的套用**（对每个底物单独套用，而不是只配对） | 没有这一步，挖出来的模板用不上 |
| **P2** | **放开 3~4 反应物模板**（`compile_templates` 收全部元数；枚举时按元数组合） | 362 条现成模板被丢 |
| **P2** | 顺带：给这些单底物模板配**条件**（还原剂/氧化剂/酸碱）—— 这正好接上"条件层" | ORD 条件表 925,943 行已在手 |

### ★★ 挖出来的模板有个关键性质：**它们是"单底物 + 试剂"型的，天生需要条件门控**
support 最高的 5 条：

| support | 模板 | 实质 |
|---|---|---|
| 566 | `[NH2;D1;+0:1]-[c:2]>>O=[N+;H0;D3:1](-[O-])-[c:2]` | 芳胺 → 硝基（**氧化**） |
| 339 | `[O;D1;H0:3]=[C:2]-[OH;D1;+0:1]>>C-[O;H0;D2;+0:1]-[C:2]=[O;D1;H0:3]` | 羧酸 → **甲酯**（需甲醇，模板里那个 `C-` 来自试剂） |
| 306 | 同上但 `C-C-` | 羧酸 → **乙酯**（需乙醇） |
| 173 | `[C:2]-[NH;D2;+0:1]-[C:3]>>…Boc…` | 胺 → **N-Boc**（需 Boc₂O） |
| 162 | `[OH;D1;+0:1]-[c:2]>>C-[O;H0;D2;+0:1]-[c:2]` | 酚 → **甲基醚**（需甲基化试剂） |

→ **模板里凭空出现的原子就是试剂带来的**。所以：
- **直接套用会"假设试剂一定在场"** → 必须由**条件层**决定这个试剂在不在；
- 这正好落在你定的顺序上：**先靠通用模板把覆盖率做上去（Phase 1），再用条件约束筛掉试剂不在的情况（Phase 2）**；
- 引擎里已有现成零件：**必需试剂判零（6/37 类）** + `aux_reagent_coverage.json` 的试剂覆盖率表。
