## 3. 修好 2 条 `verify` 规则，**都是真错误**

### 分子内半缩醛化：**环上的氧写错了**

原产物：`[C:1]1([OH:6])[...][O:2]1`
→ 让**醛基的氧**既在环里、又是羟基。化学上说不通。

正确：`[C:1]1([OH:2])[...][O:6]1`
→ **羟基的氧**进环，醛基的氧变成羟基——**这才是半缩醛的化学**。

### 分子内酰胺化：**少了一个碳**

γ-丁内酰胺是五元环（C=O + 3 个 CH₂ + N），我只写了 2 个 CH₂，
**所以连 4-氨基丁酸都匹配不上**。已补齐。

> 两条都是"看上去像对的"错误。校验器能发现"匹配不到"，但**说不出为什么**——
> 得靠人工看结构。第 6 轮那条 O-O 键的教训在这里又应验了一次。

## 4. ★ 一个字符的笔误，被 JSON 序列化器抓住 ★

写配平系数时手滑：

```python
"co_reagents": {"H2: 1"}     # ← 冒号在引号【里面】
"co_reagents": {"H2": 1}     # ← 正确
```

`{"H2: 1"}` 在 Python 里不是字典，是**含一个字符串元素的集合**。
于是 `json.dumps` 直接抛 `TypeError: Object of type set is not JSON serializable`。

**这是"失败要响亮"的价值。** 如果它悄悄写进了规则库，
`formula_atoms()` 拿到一个 set 会算出莫名其妙的结果，而且极难定位。

排查过程本身也值得记：我先写了复现脚本，结果**复现不出来**——
因为我复现时写的是正确版本。最后是在写文件前插了个遍历检查，
让程序自己报出 `root.rules[59].co_reagents -> set`，才定位到。

> 教训：**别靠"我觉得是哪里的问题"去排查，让程序把位置说出来。**

## 5. 顺带发现工具的缺口

**推导器 `derive_co_reagents.py` 只走 rdchiral**，而 rdchiral 不支持多反应物，
所以 6 条双反应物规则在它眼里全是"(无产物)"。

这不是错误——这些规则的配平由**校验器**负责（校验器有双反应物分支）。
但工具报告里会误导人。已在本轮记录，下轮可以给推导器加双反应物支持。
